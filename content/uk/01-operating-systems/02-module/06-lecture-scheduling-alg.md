## Хто отримає CPU наступним?

Уявіть чергу в кав'ярні. Є 10 клієнтів, але тільки один бариста. Як вирішити, кого обслуговувати першим? Першого в черзі? Того, хто замовляє найшвидше? Постійного клієнта? А якщо з'явиться VIP?

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ПЛАНУВАЛЬНИК ЯК БАРИСТА                            │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │                      ЧЕРГА ПРОЦЕСІВ                             │ │
│   │                                                                 │ │
│   │   [P1]──[P2]──[P3]──[P4]──[P5]──[P6]──[P7]──[P8]               │ │
│   │     ↓                                                           │ │
│   │   ┌───┐                                                         │ │
│   │   │CPU│  ← Тільки ОДИН процес може виконуватись!               │ │
│   │   └───┘                                                         │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   SCHEDULER (Планувальник) вирішує:                                  │
│   • Який процес отримає CPU?                                         │
│   • На скільки часу?                                                 │
│   • Коли його витіснити?                                             │
│                                                                       │
│   Це одне з найважливіших рішень ОС!                                 │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

**Запитання до аудиторії**: Ви граєте в онлайн-гру, а фоновий антивірус починає сканування. Що важливіше - ваша гра чи безпека? Хто вирішує?

## Чому планування - це складно?

### Цілі планування (часто суперечливі!)

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ЦІЛІ ПЛАНУВАННЯ                                    │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ДЛЯ СИСТЕМИ:                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ • Максимізувати CPU utilization (завантаженість CPU)            │ │
│   │ • Максимізувати throughput (пропускну здатність)                │ │
│   │ • Забезпечити fairness (справедливість)                         │ │
│   │ • Уникнути starvation (голодування)                             │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ДЛЯ КОРИСТУВАЧА:                                                   │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ • Мінімізувати turnaround time (час виконання)                  │ │
│   │ • Мінімізувати waiting time (час очікування)                    │ │
│   │ • Мінімізувати response time (час відгуку)                      │ │
│   │ • Передбачуваність поведінки                                    │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   КОНФЛІКТ:                                                          │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ Максимізувати throughput ←─────VERSUS─────→ Мінімізувати latency│ │
│   │                                                                 │ │
│   │ Batch-обробка                              Інтерактивність      │ │
│   │ (рендеринг відео)                         (друкування тексту)   │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Метрики планування

| Метрика | Визначення | Важлива для |
|---------|------------|-------------|
| **CPU utilization** | % часу, коли CPU зайнятий | Сервери, batch-системи |
| **Throughput** | Кількість завершених процесів за час | Сервери |
| **Turnaround time** | Час від submission до completion | Batch jobs |
| **Waiting time** | Час у черзі ready | Всі системи |
| **Response time** | Час від запиту до першої відповіді | Інтерактивні системи |

## Типи планування

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ТИПИ ПЛАНУВАННЯ                                    │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   NON-PREEMPTIVE (Невитісняюче)                                      │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │                                                                 │ │
│   │   Процес виконується, поки САМ не віддасть CPU:                │ │
│   │   • Завершиться                                                 │ │
│   │   • Заблокується (I/O, sleep)                                   │ │
│   │                                                                 │ │
│   │   ┌─────┐   ┌─────┐   ┌─────┐                                  │ │
│   │   │ P1  │───│ P2  │───│ P3  │───►                              │ │
│   │   │     │   │     │   │     │                                  │ │
│   │   └─────┘   └─────┘   └─────┘                                  │ │
│   │   0    10   10   25   25   30                                  │ │
│   │                                                                 │ │
│   │   + Простота, менше context switch                             │ │
│   │   - Один "жадібний" процес може заблокувати всю систему        │ │
│   │                                                                 │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   PREEMPTIVE (Витісняюче)                                            │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │                                                                 │ │
│   │   ОС ПРИМУСОВО забирає CPU у процесу:                          │ │
│   │   • По закінченню time slice (кванту)                          │ │
│   │   • При появі процесу з вищим пріоритетом                      │ │
│   │                                                                 │ │
│   │   ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐                               │ │
│   │   │P1│─│P2│─│P3│─│P1│─│P2│─│P3│───►                            │ │
│   │   └──┘ └──┘ └──┘ └──┘ └──┘ └──┘                                │ │
│   │   0  4  4  8  8 12 12 16 16 20                                 │ │
│   │        ↑                                                        │ │
│   │   Timer interrupt кожні 4ms                                    │ │
│   │                                                                 │ │
│   │   + Чесність, responsiveness                                   │ │
│   │   - Більше context switch, складніше                           │ │
│   │                                                                 │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   Сучасні ОС (Linux, Windows, macOS) - PREEMPTIVE                    │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

## Класичні алгоритми планування

### 1. FCFS (First-Come, First-Served)

Найпростіший алгоритм - хто перший прийшов, того першого обслуговують.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    FCFS: First-Come, First-Served                     │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Вхідні дані:                                                       │
│   ┌────────────────────────────────────────┐                         │
│   │ Process │ Arrival Time │ Burst Time   │                         │
│   │─────────│──────────────│──────────────│                         │
│   │   P1    │      0       │     24       │                         │
│   │   P2    │      0       │      3       │                         │
│   │   P3    │      0       │      3       │                         │
│   └────────────────────────────────────────┘                         │
│                                                                       │
│   Gantt Chart (порядок: P1, P2, P3):                                 │
│   ┌──────────────────────────┬───┬───┐                               │
│   │           P1             │P2 │P3 │                               │
│   └──────────────────────────┴───┴───┘                               │
│   0                         24  27  30                               │
│                                                                       │
│   Розрахунок:                                                        │
│   ┌────────────────────────────────────────────────────────┐         │
│   │ Process │ Completion │ Turnaround │ Waiting            │         │
│   │─────────│────────────│────────────│────────────────────│         │
│   │   P1    │    24      │   24-0=24  │   0                │         │
│   │   P2    │    27      │   27-0=27  │   24               │         │
│   │   P3    │    30      │   30-0=30  │   27               │         │
│   │─────────│────────────│────────────│────────────────────│         │
│   │ Average │     -      │   27       │   17               │         │
│   └────────────────────────────────────────────────────────┘         │
│                                                                       │
│   CONVOY EFFECT: P2 і P3 (короткі) чекають P1 (довгий)               │
│                                                                       │
│   А якби порядок був P2, P3, P1?                                     │
│   ┌───┬───┬──────────────────────────┐                               │
│   │P2 │P3 │           P1             │                               │
│   └───┴───┴──────────────────────────┘                               │
│   0   3   6                         30                               │
│                                                                       │
│   Average Turnaround: (3 + 6 + 30)/3 = 13 (замість 27!)              │
│   Average Waiting: (0 + 3 + 6)/3 = 3 (замість 17!)                   │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

**Висновок**: FCFS простий, але неефективний. Порядок прибуття критично впливає на продуктивність.

### 2. SJF (Shortest Job First)

Виконуємо спочатку найкоротші задачі.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    SJF: Shortest Job First                            │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Вхідні дані:                                                       │
│   ┌────────────────────────────────────────┐                         │
│   │ Process │ Arrival Time │ Burst Time   │                         │
│   │─────────│──────────────│──────────────│                         │
│   │   P1    │      0       │      6       │                         │
│   │   P2    │      0       │      8       │                         │
│   │   P3    │      0       │      7       │                         │
│   │   P4    │      0       │      3       │                         │
│   └────────────────────────────────────────┘                         │
│                                                                       │
│   SJF вибирає: P4 (3) → P1 (6) → P3 (7) → P2 (8)                     │
│                                                                       │
│   Gantt Chart:                                                       │
│   ┌───┬──────┬───────┬────────┐                                      │
│   │P4 │  P1  │  P3   │   P2   │                                      │
│   └───┴──────┴───────┴────────┘                                      │
│   0   3      9      16       24                                      │
│                                                                       │
│   Розрахунок:                                                        │
│   ┌────────────────────────────────────────────────────────┐         │
│   │ Process │ Completion │ Turnaround │ Waiting            │         │
│   │─────────│────────────│────────────│────────────────────│         │
│   │   P4    │     3      │     3      │   0                │         │
│   │   P1    │     9      │     9      │   3                │         │
│   │   P3    │    16      │    16      │   9                │         │
│   │   P2    │    24      │    24      │   16               │         │
│   │─────────│────────────│────────────│────────────────────│         │
│   │ Average │     -      │   13       │   7                │         │
│   └────────────────────────────────────────────────────────┘         │
│                                                                       │
│   ✓ SJF дає ОПТИМАЛЬНИЙ середній waiting time                        │
│   ✗ Проблема: Як знати burst time заздалегідь?                       │
│   ✗ STARVATION: довгі процеси можуть ніколи не виконатись            │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### 3. SRTF (Shortest Remaining Time First)

Preemptive версія SJF - витісняємо, якщо з'явився коротший процес.

```
┌───────────────────────────────────────────────────────────────────────┐
│              SRTF: Shortest Remaining Time First                      │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Вхідні дані:                                                       │
│   ┌────────────────────────────────────────┐                         │
│   │ Process │ Arrival Time │ Burst Time   │                         │
│   │─────────│──────────────│──────────────│                         │
│   │   P1    │      0       │      8       │                         │
│   │   P2    │      1       │      4       │                         │
│   │   P3    │      2       │      9       │                         │
│   │   P4    │      3       │      5       │                         │
│   └────────────────────────────────────────┘                         │
│                                                                       │
│   Хронологія:                                                        │
│   t=0: P1 приходить, виконується (remaining=8)                       │
│   t=1: P2 приходить (burst=4), P1 remaining=7 → P2 коротший!        │
│        Preempt P1, виконуємо P2                                      │
│   t=2: P3 приходить (burst=9), P2 remaining=3 → P2 коротший         │
│   t=3: P4 приходить (burst=5), P2 remaining=2 → P2 коротший         │
│   t=5: P2 завершується. Хто далі?                                    │
│        P1=7, P3=9, P4=5 → P4 найкоротший                            │
│   ...                                                                │
│                                                                       │
│   Gantt Chart:                                                       │
│   ┌──┬────┬─────┬───────┬─────────┐                                  │
│   │P1│ P2 │ P4  │  P1   │   P3    │                                  │
│   └──┴────┴─────┴───────┴─────────┘                                  │
│   0  1    5    10      17        26                                  │
│                                                                       │
│   Average Waiting Time = 6.5 (краще за SJF, якщо arrival time ≠ 0)   │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### 4. Round Robin (RR)

Найпопулярніший алгоритм для time-sharing систем. Кожен процес отримує фіксований квант часу (time slice).

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ROUND ROBIN                                        │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Вхідні дані (time quantum = 4):                                    │
│   ┌────────────────────────────────────────┐                         │
│   │ Process │ Arrival Time │ Burst Time   │                         │
│   │─────────│──────────────│──────────────│                         │
│   │   P1    │      0       │     24       │                         │
│   │   P2    │      0       │      3       │                         │
│   │   P3    │      0       │      3       │                         │
│   └────────────────────────────────────────┘                         │
│                                                                       │
│   Виконання з quantum = 4:                                           │
│   ┌────┬───┬───┬────┬────┬────┬────┬────┬────┐                       │
│   │ P1 │P2 │P3 │ P1 │ P1 │ P1 │ P1 │ P1 │ P1 │                       │
│   └────┴───┴───┴────┴────┴────┴────┴────┴────┘                       │
│   0    4   7  10   14   18   22   26   30   30                       │
│        ↑   ↑   ↑                                                     │
│        │   │   P2, P3 завершились за свій квант                      │
│        │   P3 burst=3 < quantum=4                                    │
│        P2 burst=3 < quantum=4                                        │
│                                                                       │
│   Зверніть увагу:                                                    │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ Черга Ready:                                                    │ │
│   │ t=0:  [P1, P2, P3]                                              │ │
│   │ t=4:  [P2, P3, P1] ← P1 повернувся в кінець черги              │ │
│   │ t=7:  [P3, P1]     ← P2 завершився                              │ │
│   │ t=10: [P1]         ← P3 завершився                              │ │
│   │ t=14: [P1]         ← P1 продовжує (remaining=16)                │ │
│   │ ...                                                             │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   Average Waiting = (10-4 + 4 + 7)/3 = 5.66                          │
│   (Гірше за SJF, але СПРАВЕДЛИВО!)                                   │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Вибір time quantum

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ВПЛИВ TIME QUANTUM                                 │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Quantum ЗАНАДТО МАЛИЙ (наприклад, 1ms):                            │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ [P1][P2][P3][P1][P2][P3][P1][P2][P3]...                         │ │
│   │    ↓    ↓    ↓    ↓    ↓    ↓                                   │ │
│   │    CS   CS   CS   CS   CS   CS   (CS = context switch)          │ │
│   │                                                                 │ │
│   │ ⚠ Забагато context switch! Overhead може з'їсти 50%+ CPU       │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   Quantum ЗАНАДТО ВЕЛИКИЙ (наприклад, 100ms):                        │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ [P1────────────────][P2────────────────][P3────────────────]    │ │
│   │                                                                 │ │
│   │ ⚠ Поведінка наближається до FCFS                               │ │
│   │ ⚠ Погана responsiveness для інтерактивних процесів             │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ОПТИМАЛЬНИЙ quantum (зазвичай 10-100ms):                           │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ Правило: 80% CPU bursts мають бути < quantum                    │ │
│   │                                                                 │ │
│   │ Типові значення:                                                │ │
│   │ • Linux default: ~4-6ms (можна налаштувати)                     │ │
│   │ • Windows: ~20ms (залежить від priority class)                  │ │
│   │ • macOS: ~10ms                                                  │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   Context switch overhead: ~1-10 μs на сучасних CPU                  │
│   Якщо quantum=10ms, overhead = 0.01-0.1% (прийнятно)               │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### 5. Priority Scheduling

Кожен процес має пріоритет. Вищий пріоритет = швидше виконання.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    PRIORITY SCHEDULING                                │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Вхідні дані (менше число = вищий пріоритет):                       │
│   ┌────────────────────────────────────────────────────┐             │
│   │ Process │ Arrival │ Burst │ Priority              │             │
│   │─────────│─────────│───────│───────────────────────│             │
│   │   P1    │    0    │  10   │    3                  │             │
│   │   P2    │    0    │   1   │    1 (найвищий)       │             │
│   │   P3    │    0    │   2   │    4                  │             │
│   │   P4    │    0    │   1   │    5 (найнижчий)      │             │
│   │   P5    │    0    │   5   │    2                  │             │
│   └────────────────────────────────────────────────────┘             │
│                                                                       │
│   Порядок виконання: P2 → P5 → P1 → P3 → P4                          │
│                                                                       │
│   Gantt Chart:                                                       │
│   ┌─┬─────┬──────────┬──┬─┐                                          │
│   │P2│ P5  │    P1    │P3│P4                                         │
│   └─┴─────┴──────────┴──┴─┘                                          │
│   0 1     6         16 18 19                                         │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │                    ПРОБЛЕМА: STARVATION                          │ │
│   │                                                                 │ │
│   │   Low-priority процес P4:                                       │ │
│   │   ┌───────────────────────────────────────────────────────┐     │ │
│   │   │ [Waiting...][Waiting...][Waiting...][FINALLY!]        │     │ │
│   │   │                                      ↑                │     │ │
│   │   │                          Може чекати ВІЧНО!           │     │ │
│   │   └───────────────────────────────────────────────────────┘     │ │
│   │                                                                 │ │
│   │   РІШЕННЯ: AGING (старіння)                                     │ │
│   │   Поступово підвищуємо пріоритет процесів, що довго чекають    │ │
│   │                                                                 │ │
```

### 7. Multilevel Feedback Queue (MLFQ)

Найгнучкіший алгоритм - процеси можуть переміщатися між чергами.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    MULTILEVEL FEEDBACK QUEUE                          │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ПРАВИЛА MLFQ:                                                      │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ 1. Новий процес → найвища черга (Q0)                           │ │
│   │ 2. Використав весь квант → переміщення ВНИЗ                    │ │
│   │ 3. Заблокувався до кінця кванту → залишається                  │ │
│   │ 4. Періодичний BOOST: всі процеси → Q0 (запобігає starvation)  │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ Q0: quantum = 8ms (найвищий пріоритет)                         │ │
│   │ ┌────┐                                                         │ │
│   │ │NEW │ → виконується першим                                    │ │
│   │ └────┘                                                         │ │
│   │     │ (використав 8ms? → переміщення вниз)                     │ │
│   │     ▼                                                          │ │
│   │ Q1: quantum = 16ms                                             │ │
│   │ ┌────┬────┐                                                    │ │
│   │ │ P1 │ P2 │                                                    │ │
│   │ └────┴────┘                                                    │ │
│   │     │ (використав 16ms? → переміщення вниз)                    │ │
│   │     ▼                                                          │ │
│   │ Q2: quantum = 32ms (найнижчий пріоритет)                       │ │
│   │ ┌────┬────┬────┬────┐                                          │ │
│   │ │ P3 │ P4 │ P5 │ P6 │ → CPU-intensive процеси                  │ │
│   │ └────┴────┴────┴────┘                                          │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ПРИКЛАД:                                                           │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ Інтерактивний процес (vim):                                    │ │
│   │ • Швидко блокується на I/O (keyboard input)                    │ │
│   │ • Залишається в Q0 → швидка відповідь                          │ │
│   │                                                                 │ │
│   │ CPU-bound процес (render):                                     │ │
│   │ • Завжди використовує весь квант                               │ │
│   │ • Q0 → Q1 → Q2 → більший квант, нижчий пріоритет              │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   MLFQ автоматично класифікує процеси за поведінкою!                 │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

## Планувальник Linux: CFS (Completely Fair Scheduler)

CFS - це сучасний планувальник Linux з версії 2.6.23 (2007 рік).

```
┌───────────────────────────────────────────────────────────────────────┐
│                    CFS: COMPLETELY FAIR SCHEDULER                     │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ІДЕЯ: Ідеальний процесор ділить час РІВНО між усіма               │
│                                                                       │
│   Ідеальна багатозадачність (1 CPU, 4 процеси):                      │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ P1: ▓░░░▓░░░▓░░░▓░░░▓░░░▓░░░                                   │ │
│   │ P2: ░▓░░░▓░░░▓░░░▓░░░▓░░░▓░░                                   │ │
│   │ P3: ░░▓░░░▓░░░▓░░░▓░░░▓░░░▓░                                   │ │
│   │ P4: ░░░▓░░░▓░░░▓░░░▓░░░▓░░░▓                                   │ │
│   │     ─────────────────────────►                                  │ │
│   │     Кожен отримує 25% CPU в кожен момент часу                  │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   Реальність: CPU не можна ділити нескінченно                        │
│   CFS емулює це через "virtual runtime" (vruntime)                   │
│                                                                       │
│   VRUNTIME = реальний час * (nice_weight / process_weight)           │
│                                                                       │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ Red-Black Tree (відсортовано за vruntime):                      │ │
│   │                                                                 │ │
│   │                     ┌───────┐                                   │ │
│   │                     │vr=100 │                                   │ │
│   │                     └───┬───┘                                   │ │
│   │                   ┌─────┴─────┐                                 │ │
│   │              ┌────▼───┐  ┌────▼───┐                             │ │
│   │              │ vr=50  │  │ vr=150 │                             │ │
│   │              └───┬────┘  └────┬───┘                             │ │
│   │             ┌────┴────┐  ┌────┴────┐                            │ │
│   │        ┌────▼──┐ ┌────▼──┐ ┌──────▼┐                            │ │
│   │        │ vr=25 │ │ vr=75 │ │vr=200 │                            │ │
│   │        └───────┘ └───────┘ └───────┘                            │ │
│   │            ↑                                                    │ │
│   │     Найлівіший = МІНІМАЛЬНИЙ vruntime                          │ │
│   │     ЦЕЙ ПРОЦЕС ОТРИМАЄ CPU НАСТУПНИМ!                          │ │
│   │                                                                 │ │
│   │     O(log N) - час вибору наступного процесу                   │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   WEIGHT (вага): визначається nice value                             │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ nice =  0 → weight = 1024 (default)                             │ │
│   │ nice = -5 → weight = 3121 (≈3x більше CPU)                      │ │
│   │ nice = +5 → weight =  335 (≈3x менше CPU)                       │ │
│   │                                                                 │ │
│   │ Кожен рівень nice ≈ 10% різниці в CPU time                     │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

## Real-Time планування

```
┌───────────────────────────────────────────────────────────────────────┐
│                    REAL-TIME SCHEDULING                               │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Для систем, де DEADLINE критичний:                                 │
│   • Автопілот                                                        │
│   • Медичне обладнання                                               │
│   • Промислові роботи                                                │
│   • Аудіо/відео обробка                                              │
│                                                                       │
│   LINUX REALTIME SCHEDULING POLICIES:                                │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ SCHED_FIFO:                                                     │ │
│   │ • Виконується, поки не завершиться або заблокується            │ │
│   │ • Вищий RT-priority завжди preempt нижчий                       │ │
│   │ • Priorities: 1-99 (99 = найвищий)                              │ │
│   │                                                                 │ │
│   │ SCHED_RR (Round Robin RT):                                      │ │
│   │ • Як SCHED_FIFO, але з time quantum                             │ │
│   │ • Процеси з однаковим priority чергуються                       │ │
│   │                                                                 │ │
│   │ SCHED_DEADLINE:                                                 │ │
│   │ • Earliest Deadline First (EDF)                                 │ │
│   │ • Процес із найближчим deadline виконується першим              │ │
│   │ • Найпріоритетніший клас в Linux                                │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   RT PRIORITY VISUALIZED:                                            │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ SCHED_DEADLINE  │  Deadline tasks (найвищий)                    │ │
│   │ SCHED_FIFO/RR   │  RT priorities 1-99                           │ │
│   │ SCHED_OTHER     │  Nice -20..+19 (CFS)                          │ │
│   │ SCHED_BATCH     │  Batch processing                             │ │
│   │ SCHED_IDLE      │  Idle tasks (найнижчий)                       │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

```bash
# Запустити процес з SCHED_FIFO
sudo chrt -f 50 ./my_realtime_app

# Подивитися scheduling policy
chrt -p 1234
# pid 1234's current scheduling policy: SCHED_OTHER
# pid 1234's current scheduling priority: 0

# Запустити з SCHED_RR
sudo chrt -r 30 ./my_app

# Змінити policy для існуючого процесу
sudo chrt -f -p 50 1234
```

**Крок 1**: Базова структура

```python
#!/usr/bin/env python3
"""scheduler_sim.py - Симулятор алгоритмів планування CPU"""

from dataclasses import dataclass
from typing import List

@dataclass
class Process:
    """Процес для планування"""
    pid: str
    arrival_time: int
    burst_time: int
    remaining_time: int = 0
    completion_time: int = 0
    waiting_time: int = 0
    turnaround_time: int = 0

    def __post_init__(self):
        self.remaining_time = self.burst_time

def print_gantt_chart(schedule: List[tuple], total_time: int):
    """Візуалізація Gantt Chart"""
    print("\n=== Gantt Chart ===")
    print("┌" + "─" * (total_time * 3 + 1) + "┐")

    line = "│"
    for pid, duration in schedule:
        line += f" {pid} " + "──" * (duration - 1)
    line += " │"
    print(line)

    print("└" + "─" * (total_time * 3 + 1) + "┘")

    # Timeline
    timeline = " 0"
    current = 0
    for pid, duration in schedule:
        current += duration
        timeline += " " * (duration * 3 - len(str(current))) + str(current)
    print(timeline)
```

**Крок 2**: Реалізація FCFS

```python
def fcfs(processes: List[Process]) -> List[tuple]:
    """First-Come, First-Served scheduling"""
    schedule = []
    current_time = 0

    # Сортуємо за часом прибуття
    sorted_procs = sorted(processes, key=lambda p: p.arrival_time)

    for proc in sorted_procs:
        # Чекаємо, якщо процес ще не прибув
        if current_time < proc.arrival_time:
            current_time = proc.arrival_time

        # Виконуємо процес
        proc.waiting_time = current_time - proc.arrival_time
        current_time += proc.burst_time
        proc.completion_time = current_time
        proc.turnaround_time = proc.completion_time - proc.arrival_time

        schedule.append((proc.pid, proc.burst_time))

    return schedule
```

**Крок 3**: Реалізація SJF

```python
def sjf(processes: List[Process]) -> List[tuple]:
    """Shortest Job First (non-preemptive)"""
    schedule = []
    current_time = 0
    remaining = list(processes)

    while remaining:
        # Знаходимо процеси, що вже прибули
        available = [p for p in remaining if p.arrival_time <= current_time]

        if not available:
            # Перемотуємо час до наступного прибуття
            current_time = min(p.arrival_time for p in remaining)
            continue

        # Вибираємо найкоротший
        shortest = min(available, key=lambda p: p.burst_time)

        shortest.waiting_time = current_time - shortest.arrival_time
        current_time += shortest.burst_time
        shortest.completion_time = current_time
        shortest.turnaround_time = shortest.completion_time - shortest.arrival_time

        schedule.append((shortest.pid, shortest.burst_time))
        remaining.remove(shortest)

    return schedule
```

**Крок 4**: Реалізація Round Robin

```python
def round_robin(processes: List[Process], quantum: int) -> List[tuple]:
    """Round Robin scheduling"""
    schedule = []
    current_time = 0
    queue = []
    remaining = [Process(p.pid, p.arrival_time, p.burst_time) for p in processes]

    # Сортуємо за arrival time
    remaining.sort(key=lambda p: p.arrival_time)

    while remaining or queue:
        # Додаємо процеси, що прибули
        while remaining and remaining[0].arrival_time <= current_time:
            queue.append(remaining.pop(0))

        if not queue:
            if remaining:
                current_time = remaining[0].arrival_time
            continue

        # Виконуємо перший в черзі
        current = queue.pop(0)
        exec_time = min(quantum, current.remaining_time)
        current.remaining_time -= exec_time
        current_time += exec_time

        schedule.append((current.pid, exec_time))

        # Додаємо нових процесів, що прибули під час виконання
        while remaining and remaining[0].arrival_time <= current_time:
            queue.append(remaining.pop(0))

        # Якщо не завершився - в кінець черги
        if current.remaining_time > 0:
            queue.append(current)
        else:
            # Знаходимо оригінальний процес для статистики
            for p in processes:
                if p.pid == current.pid:
                    p.completion_time = current_time
                    p.turnaround_time = p.completion_time - p.arrival_time
                    p.waiting_time = p.turnaround_time - p.burst_time

    return schedule
```

```python
def print_stats(processes: List[Process]):
    """Друк статистики"""
    print("\n=== Statistics ===")
    print(f"{'PID':<5} {'Arrival':<8} {'Burst':<6} {'Complete':<9} {'Turn':<6} {'Wait':<6}")

    for p in processes:
        print(f"{p.pid:<5} {p.arrival_time:<8} {p.burst_time:<6} "
              f"{p.completion_time:<9} {p.turnaround_time:<6} {p.waiting_time:<6}")

    avg_turnaround = sum(p.turnaround_time for p in processes) / len(processes)
    avg_waiting = sum(p.waiting_time for p in processes) / len(processes)

    print("-" * 45)
    print(f"Average Turnaround Time: {avg_turnaround:.2f}")
    print(f"Average Waiting Time: {avg_waiting:.2f}")
```

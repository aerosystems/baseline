## Чому ваш комп'ютер робить 100 справ одночасно

Відкрийте прямо зараз диспетчер задач (Windows) або htop (Linux). Скільки процесів ви бачите? 200? 300? 500?

А тепер подивіться на характеристики свого процесора. Скільки ядер? 4? 8? Навіть якщо 16 — це все одно набагато менше, ніж кількість процесів.

**Як комп'ютер з 4 ядрами "одночасно" виконує 400 процесів?**

Відповідь на це питання — фундаментальна концепція операційних систем, яка визначає, як працює кожен сучасний пристрій: від смартфона до суперкомп'ютера.

## Паралелізм vs Конкурентність

Це два терміни, які часто плутають, але вони означають різні речі. Розуміння різниці — ключ до глибокого знання операційних систем.

### Аналогія: Кухня ресторану

```
┌───────────────────────────────────────────────────────────────────────┐
│                    КОНКУРЕНТНІСТЬ vs ПАРАЛЕЛІЗМ                       │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   КОНКУРЕНТНІСТЬ (Concurrency)              ПАРАЛЕЛІЗМ (Parallelism)  │
│   ─────────────────────────────             ──────────────────────── │
│                                                                       │
│   Один кухар готує 5 страв:                 5 кухарів готують 5 страв:│
│                                                                       │
│   ┌─────────────────────────┐               ┌─────┬─────┬─────┬─────┐ │
│   │  Кухар                  │               │Кух 1│Кух 2│Кух 3│Кух 4│ │
│   │  ┌───┐                  │               ├─────┼─────┼─────┼─────┤ │
│   │  │ 1 │ ← готує борщ     │               │Борщ │Салат│ М'со│Десерт│ │
│   │  └───┘                  │               └─────┴─────┴─────┴─────┘ │
│   │    │ перемикається      │                                         │
│   │  ┌─▼─┐                  │               Справжнє одночасне        │
│   │  │ 2 │ ← ріже салат     │               виконання!                │
│   │  └───┘                  │                                         │
│   │    │ перемикається      │               Кожна страва готується    │
│   │  ┌─▼─┐                  │               на своїй "станції"        │
│   │  │ 3 │ ← смажить м'ясо  │               незалежно від інших.      │
│   │  └───┘                  │                                         │
│   │    │ ... і так далі    │                                         │
│   └─────────────────────────┘                                         │
│                                                                       │
│   Прогрес у кількох задачах,               Виконання кількох задач    │
│   але в один момент часу —                 буквально в один момент    │
│   лише одна активна.                       часу.                      │
│                                                                       │
│   Потрібен: 1 виконавець                   Потрібно: N виконавців     │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Формальні визначення

| Концепція | Визначення | Приклад |
|-----------|------------|---------|
| **Конкурентність** | Структура програми, що дозволяє працювати з кількома задачами, які можуть прогресувати одночасно | Один процесор перемикається між браузером і музичним плеєром |
| **Паралелізм** | Фактичне одночасне виконання кількох задач | 4-ядерний процесор виконує 4 різних обчислення одночасно |

**Rob Pike (творець Go):**
> "Concurrency is about dealing with lots of things at once. Parallelism is about doing lots of things at once."
>
> "Конкурентність — це про керування багатьма речами одночасно. Паралелізм — це про виконання багатьох речей одночасно."

На одноядерному процесорі:

```
│                                                                       │
│   Процес A:  ████░░░░████░░░░████░░░░████                             │
│   Процес B:  ░░░░████░░░░████░░░░████░░░░                             │
│   Процес C:  ░░░░░░░░░░░░░░░░████████████  (чекає на I/O, потім run) │
```

## Потоки виконання (Threads)

### Процес vs Потік

Ми вже знаємо, що **процес** — це програма, що виконується. Але всередині процесу може бути кілька **потоків** (threads).

```
┌───────────────────────────────────────────────────────────────────────┐
│                       ПРОЦЕС vs ПОТІК                                 │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ПРОЦЕС (Process)                    ПОТІК (Thread)                  │
│   ─────────────────                   ──────────────                  │
│                                                                       │
│   ┌─────────────────────┐             ┌─────────────────────┐         │
│   │ Процес A (PID 1234) │             │ Процес A (PID 1234) │         │
│   │                     │             │                     │         │
│   │  ┌───────────────┐  │             │  ┌───┐ ┌───┐ ┌───┐  │         │
│   │  │   Код         │  │             │  │T1 │ │T2 │ │T3 │  │ ← Потоки│
│   │  │   Дані        │  │             │  └─┬─┘ └─┬─┘ └─┬─┘  │         │
│   │  │   Heap        │  │             │    │     │     │    │         │
│   │  │   Stack       │  │             │    ▼     ▼     ▼    │         │
│   │  └───────────────┘  │             │  ┌───────────────┐  │         │
│   │                     │             │  │ Спільні:      │  │         │
│   └─────────────────────┘             │  │ • Код         │  │         │
│                                       │  │ • Дані        │  │         │
│   Один потік виконання                │  │ • Heap        │  │         │
│                                       │  │ • Файли       │  │         │
│                                       │  └───────────────┘  │         │
│                                       │                     │         │
│                                       │  Окремі для кожного:│         │
│                                       │  • Stack            │         │
│                                       │  • Регістри CPU     │         │
│                                       │  • Program Counter  │         │
│                                       └─────────────────────┘         │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Аналогія: Офіс компанії

**Процес** — це окремий офіс компанії з власною адресою, меблями, документами.

**Потоки** — це працівники в цьому офісі:
- Вони **ділять** офісне приміщення, принтер, кухню (спільна пам'ять)
- Кожен має **свій** робочий стіл, блокнот, задачі (окремий стек, регістри)
- Вони можуть **комунікувати** напряму (швидко!)
- Але якщо один працівник "зламається" — може вплинути на інших

### Чому потоки?

| Перевага | Пояснення |
|----------|-----------|
| **Швидше створення** | Створення потоку ~10-100x швидше, ніж процесу |
| **Менше пам'яті** | Потоки ділять код, дані, heap — економія RAM |
| **Швидша комунікація** | Спільна пам'ять замість IPC (міжпроцесна комунікація) |
| **Простіша синхронізація** | Доступ до спільних даних без копіювання |

**Недоліки**:
- Складніше програмувати (race conditions, deadlocks)
- Помилка в одному потоці може "впустити" весь процес
- Потребує синхронізації доступу до спільних даних

## Основи багатопоточності

### Створення потоків у C (POSIX Threads)

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

// Функція, яку виконуватиме потік
void* worker(void* arg) {
    int id = *(int*)arg;
    for (int i = 0; i < 5; i++) {
        printf("Потік %d: ітерація %d\n", id, i);
        sleep(1);  // Пауза 1 секунда
    }
    return NULL;
}

int main() {
    pthread_t thread1, thread2;
    int id1 = 1, id2 = 2;

    // Створюємо два потоки
    pthread_create(&thread1, NULL, worker, &id1);
    pthread_create(&thread2, NULL, worker, &id2);

    // Головний потік чекає завершення
    pthread_join(thread1, NULL);
    pthread_join(thread2, NULL);

    printf("Всі потоки завершили роботу\n");
    return 0;
}
```

Компіляція та запуск:

```bash
# Компіляція з бібліотекою pthread
gcc -o threads threads.c -pthread

# Запуск
./threads

# Очікуваний вивід (порядок може відрізнятися!):
# Потік 1: ітерація 0
# Потік 2: ітерація 0
# Потік 1: ітерація 1
# Потік 2: ітерація 1
# ...
```

### Головна проблема: Race Condition

```c
#include <stdio.h>
#include <pthread.h>

int counter = 0;  // Спільна змінна

void* increment(void* arg) {
    for (int i = 0; i < 1000000; i++) {
        counter++;  // НЕ атомарна операція!
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;

    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    // Очікуємо 2,000,000, але отримаємо менше!
    printf("Counter: %d (очікувалось: 2000000)\n", counter);
    return 0;
}
```

```
┌───────────────────────────────────────────────────────────────────────┐
│                         RACE CONDITION                                │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   counter++ — це НЕ одна операція, а три:                            │
│                                                                       │
│   1. READ:  Прочитати значення з пам'яті → регістр                   │
│   2. INCREMENT: Збільшити значення в регістрі                        │
│   3. WRITE: Записати значення з регістра → пам'ять                   │
│                                                                       │
│   Проблема виникає при перемиканні між потоками:                      │
│                                                                       │
│   Потік 1                      Потік 2                     counter   │
│   ──────────────────────       ──────────────────────      ────────  │
│   READ counter (=5)                                             5    │
│                                READ counter (=5)                5    │
│   INCREMENT (reg=6)                                             5    │
│                                INCREMENT (reg=6)                5    │
│   WRITE counter (=6)                                            6    │
│                                WRITE counter (=6)               6    │
│                                                                       │
│   Результат: counter = 6 замість очікуваних 7!                       │
│   Ми "втратили" один інкремент!                                      │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Рішення: Mutex (Mutual Exclusion)

```c
#include <stdio.h>
#include <pthread.h>

int counter = 0;
pthread_mutex_t lock;  // М'ютекс для захисту

void* increment(void* arg) {
    for (int i = 0; i < 1000000; i++) {
        pthread_mutex_lock(&lock);    // Захопити замок
        counter++;                     // Критична секція
        pthread_mutex_unlock(&lock);  // Звільнити замок
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_mutex_init(&lock, NULL);

    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    pthread_mutex_destroy(&lock);

    // Тепер завжди 2,000,000!
    printf("Counter: %d\n", counter);
    return 0;
}
```

## Чому паралельне виконання важливе

### 1. Використання багатоядерних процесорів

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ЕВОЛЮЦІЯ ПРОЦЕСОРІВ                                │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   2000-2005: Гонка за частотою                                       │
│   ─────────────────────────────                                       │
│   1 GHz → 2 GHz → 3 GHz → ... → 3.8 GHz (межа!)                      │
│                                                                       │
│   Проблема: тепловиділення росте експоненційно з частотою            │
│   P ≈ f³ (потужність пропорційна кубу частоти)                       │
│                                                                       │
│   2005+: Гонка за ядрами                                             │
│   ──────────────────────                                             │
│   1 ядро → 2 ядра → 4 ядра → 8 ядер → 16 ядер → 64+ ядер             │
```

### Практичний приклад: Порівняння швидкості

```bash
#!/bin/bash
# Порівняння послідовного vs паралельного виконання

echo "=== Послідовне виконання ==="
time (
    sleep 1
    sleep 1
    sleep 1
)
# Результат: ~3 секунди

echo "=== Паралельне виконання ==="
time (
    sleep 1 &
    sleep 1 &
    sleep 1 &
    wait  # Чекаємо завершення всіх фонових процесів
)
# Результат: ~1 секунда
```

## 🎯 Міні-проект (30 хв)

### Завдання: Дослідження паралелізму у вашій системі

Проведіть дослідження того, як ваша операційна система використовує паралельне виконання, та створіть звіт.

**Кроки:**

1. Визначте характеристики вашого CPU:
```bash
echo "=== CPU ХАРАКТЕРИСТИКИ ===" > ~/parallel-report.txt
echo "Кількість ядер: $(nproc)" >> ~/parallel-report.txt
lscpu | grep "Model name" >> ~/parallel-report.txt
lscpu | grep "Thread(s) per core" >> ~/parallel-report.txt
lscpu | grep "Core(s) per socket" >> ~/parallel-report.txt
```

2. Порахуйте процеси та потоки:
```bash
echo "" >> ~/parallel-report.txt
echo "=== ПРОЦЕСИ ТА ПОТОКИ ===" >> ~/parallel-report.txt
echo "Всього процесів: $(ps aux | wc -l)" >> ~/parallel-report.txt
echo "Всього потоків: $(ps -eLf | wc -l)" >> ~/parallel-report.txt
```

3. Знайдіть топ-5 процесів за кількістю потоків:
```bash
echo "" >> ~/parallel-report.txt
echo "=== ТОП-5 ЗА КІЛЬКІСТЮ ПОТОКІВ ===" >> ~/parallel-report.txt
ps -eo pid,nlwp,comm --sort=-nlwp | head -6 >> ~/parallel-report.txt
```

4. Проведіть тест паралельного виконання:
```bash
echo "" >> ~/parallel-report.txt
echo "=== ТЕСТ ПАРАЛЕЛІЗМУ ===" >> ~/parallel-report.txt

echo "Послідовне виконання:" >> ~/parallel-report.txt
{ time (sleep 0.5; sleep 0.5; sleep 0.5; sleep 0.5); } 2>> ~/parallel-report.txt

echo "Паралельне виконання:" >> ~/parallel-report.txt
{ time (sleep 0.5 & sleep 0.5 & sleep 0.5 & sleep 0.5 & wait); } 2>> ~/parallel-report.txt
```

5. Перегляньте результат:
```bash
cat ~/parallel-report.txt
```

**Очікуваний результат:**
Файл `parallel-report.txt` з інформацією про ваш CPU, кількість процесів і потоків, топ багатопоточних програм та результати тесту, що демонструє різницю між послідовним і паралельним виконанням.

**Бонус (для допитливих):**
- Напишіть простий bash-скрипт, який симулює навантаження на CPU (`while true; do :; done &`) і спостерігайте за htop
- Знайдіть, скільки потоків використовує ваш браузер
- Спробуйте скомпілювати програму з прикладу race condition і переконайтеся, що результат непередбачуваний

## Підсумок

| Термін | Визначення |
|--------|------------|
| **Конкурентність (Concurrency)** | Структура програми для роботи з кількома задачами |
| **Паралелізм (Parallelism)** | Фактичне одночасне виконання на кількох ядрах |
| **Процес (Process)** | Ізольований екземпляр програми з власною пам'яттю |
| **Потік (Thread)** | Легкий потік виконання всередині процесу |
| **Race Condition** | Помилка через неконтрольований доступ до спільних даних |
| **Mutex** | Механізм взаємного виключення для синхронізації |
| **Time-slicing** | Розділення часу CPU між задачами |
| **Preemptive Multitasking** | ОС примусово перемикає задачі |

| Концепція | Ключова ідея |
|-----------|--------------|
| Процес vs Потік | Потоки легші, діляться пам'яттю, швидша комунікація |
| Навіщо паралелізм | Використання багатоядерних CPU, швидший I/O, responsive UI |
| Головна проблема | Race conditions — потребують синхронізації |

На наступній лекції — стани процесів та діаграми станів: як ОС керує життєвим циклом кожного процесу.

## Кожен процес має свою історію

Уявіть, що ви працюєте в ресторані швидкого харчування. Кожне замовлення проходить певні етапи:

1. **Прийняте** — офіціант записав замовлення
2. **В черзі** — чекає на кухаря
3. **Готується** — кухар активно працює
4. **Очікує інгредієнти** — пауза, поки принесуть продукти
5. **Видане** — страва готова, замовлення закрите

Процеси в операційній системі працюють так само! Вони народжуються, чекають своєї черги, виконуються, іноді зупиняються і, врешті-решт, завершуються.

**Запитання до аудиторії**: Що відбувається, коли ви натискаєте Play у Spotify, а потім вмикаєте гру? Чому музика продовжує грати, хоча ви "перемкнулися" на гру?

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ЖИТТЄВИЙ ЦИКЛ ЗАМОВЛЕННЯ                           │
│                                                                       │
│   [Прийняте] ──► [В черзі] ──► [Готується] ──► [Видане]              │
│                                     │                                 │
│                                     ▼                                 │
│                          [Очікує інгредієнти]                         │
│                                     │                                 │
│                                     └─────────────► [Готується]       │
│                                                                       │
│   Процес у комп'ютері проходить схожі стани!                         │
└───────────────────────────────────────────────────────────────────────┘
```

## Стани процесу: п'ять ключових станів

Операційна система відстежує кожен процес через його **стан**. Класична модель включає п'ять станів:

### 1. New (Новий)

Процес щойно створено. ОС виділяє ресурси, створює структури даних, але процес ще не готовий до виконання.

```bash
# Коли ви запускаєте програму, перші мілісекунди вона у стані New
./my_program &
# ОС: виділяє PID, створює PCB, завантажує код у пам'ять
```

**Аналогія**: Ви щойно влаштувалися на роботу. HR оформляє документи, видає пропуск, але до робочого місця ви ще не дійшли.

### 2. Ready (Готовий)

Процес готовий до виконання і чекає, коли планувальник призначить йому процесорний час.

```bash
# Подивитися процеси у стані Ready (стовпець STAT: R)
ps aux | awk '$8 ~ /R/ {print $2, $11}'
```

**Аналогія**: Ви сидите в черзі до лікаря. Ви готові увійти, але треба дочекатися виклику.

### 3. Running (Виконується)

Процес активно використовує CPU. В один момент часу на одному ядрі може бути тільки **один** процес у стані Running.

```bash
# На 4-ядерному процесорі максимум 4 процеси одночасно у Running
# Решта чекають у Ready
nproc  # кількість ядер
```

**Аналогія**: Ви в кабінеті лікаря, він вас оглядає.

### 4. Waiting / Blocked (Очікування)

Процес зупинено, бо він чекає на зовнішню подію: введення з клавіатури, читання з диска, відповідь мережі.

```bash
# Процеси у стані Waiting (STAT: S, D)
ps aux | awk '$8 ~ /S|D/ {print $2, $8, $11}' | head -10
# S = Sleeping (interruptible)
# D = Disk sleep (uninterruptible)
```

**Аналогія**: Лікар відправив вас на аналізи. Ви чекаєте результатів і не можете продовжити огляд.

### 5. Terminated (Завершений)

Процес закінчив виконання. ОС звільняє ресурси, але зберігає інформацію про завершення (exit code) для батьківського процесу.

```bash
# Zombie-процеси: завершилися, але батько не забрав статус
ps aux | awk '$8 ~ /Z/ {print $2, $11}'

# Exit code останньої команди
echo $?
# 0 = успіх, інше = помилка
```

**Аналогія**: Ви вийшли з кабінету, огляд завершено. Залишається тільки запис у картці.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    П'ЯТЬ СТАНІВ ПРОЦЕСУ                               │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ┌─────────┐    ┌─────────┐    ┌─────────────┐    ┌─────────────┐   │
│   │   NEW   │───►│  READY  │◄──►│   RUNNING   │───►│ TERMINATED  │   │
│   │ (новий) │    │(готовий)│    │(виконується)│    │ (завершений)│   │
│   └─────────┘    └────┬────┘    └──────┬──────┘    └─────────────┘   │
│                       │                │                              │
│                       │                ▼                              │
│                       │         ┌────────────┐                        │
│                       └─────────│  WAITING   │                        │
│                                 │(очікування)│                        │
│                                 └────────────┘                        │
│                                                                       │
│   NEW        → Створення процесу, виділення ресурсів                 │
│   READY      → Готовий виконуватись, чекає CPU                       │
│   RUNNING    → Активно використовує процесор                         │
│   WAITING    → Чекає на I/O або подію                                │
│   TERMINATED → Завершив роботу, звільняє ресурси                     │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

## Діаграма переходів станів

Процес не може переходити між станами довільно. Існують чіткі правила переходів:

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ДІАГРАМА ПЕРЕХОДІВ СТАНІВ                          │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│                          ┌─────────────┐                              │
│                          │     NEW     │                              │
│                          │  (створення)│                              │
│                          └──────┬──────┘                              │
│                                 │ admitted                            │
│                                 ▼                                     │
│           ┌────────────────────────────────────────┐                  │
│           │                                        │                  │
│           ▼              scheduler dispatch        │                  │
│    ┌────────────┐ ──────────────────────────► ┌────────────┐         │
│    │   READY    │                             │  RUNNING   │         │
│    │  (готовий) │ ◄────────────────────────── │(виконання) │         │
│    └─────┬──────┘      interrupt/preempt      └─────┬──────┘         │
│          │                                          │                 │
│          │                                          │                 │
│          │    I/O or event completion               │ I/O or          │
│          │ ◄────────────────────────────────────────┤ event wait      │
│          │                                          │                 │
│          │              ┌────────────┐              │                 │
│          │              │  WAITING   │◄─────────────┘                 │
│          └──────────────│(очікування)│                                │
│                         └────────────┘                                │
│                                                                       │
│                          exit                                         │
│    ┌────────────┐ ◄────────────────────────── ┌────────────┐         │
│    │ TERMINATED │                             │  RUNNING   │         │
│    │(завершення)│                             │            │         │
│    └────────────┘                             └────────────┘         │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Переходи та їх причини

| Перехід | Причина | Приклад |
|---------|---------|---------|
| **New → Ready** | Admitted: ОС прийняла процес | `fork()` завершився успішно |
| **Ready → Running** | Dispatch: планувальник обрав процес | Процес отримав CPU |
| **Running → Ready** | Preempt: час вичерпано або пріоритетніший процес | Таймер переривання |
| **Running → Waiting** | I/O wait: процес чекає на ресурс | `read()` з диска |
| **Waiting → Ready** | I/O complete: ресурс став доступний | Дані прочитані |
| **Running → Terminated** | Exit: процес завершився | `exit(0)` |

### Заборонені переходи

Деякі переходи **неможливі** за логікою роботи ОС:

- **Waiting → Running**: Процес не може одразу почати виконуватись після I/O. Спочатку він має стати Ready і дочекатися планувальника.
- **Ready → Waiting**: Процес не може чекати на I/O, якщо він не виконується. Тільки Running-процес може ініціювати операцію I/O.
- **Terminated → будь-що**: Мертвий процес не воскресає.

```bash
# Спостерігаємо за станами процесів у реальному часі
watch -n 1 'ps aux | head -15'

# Або через top (натисніть q для виходу)
top
# Колонка S (Status): R=Running, S=Sleeping, D=Disk, Z=Zombie
```

## Process Control Block (PCB)

**Process Control Block (PCB)** — структура даних, яка містить всю інформацію про процес. Це "паспорт" процесу, який ОС використовує для керування.

```
┌───────────────────────────────────────────────────────────────────────┐
│                    PROCESS CONTROL BLOCK (PCB)                        │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ┌───────────────────────────────────────────────────────────────┐   │
│   │                         PCB                                   │   │
│   ├───────────────────────────────────────────────────────────────┤   │
│   │  PID: 1234                    │ Process Identifier            │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  State: RUNNING               │ Поточний стан процесу         │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  PC: 0x7fff5fbff8c0           │ Program Counter (наступна     │   │
│   │                               │ інструкція)                   │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  Registers: RAX, RBX, RCX...  │ Значення регістрів CPU        │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  Memory: base=0x400000        │ Межі пам'яті, page table      │   │
│   │          limit=0x4FFFFF       │                               │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  Priority: 20                 │ Пріоритет планування          │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  CPU Time: 00:05:32           │ Використаний час CPU          │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  PPID: 1                      │ PID батьківського процесу     │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  Open Files: [fd0, fd1, fd2]  │ Відкриті файлові дескриптори  │   │
│   ├───────────────────────────────┼───────────────────────────────┤   │
│   │  UID/GID: 1000/1000           │ Власник процесу               │   │
│   └───────────────────────────────┴───────────────────────────────┘   │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Компоненти PCB

| Компонент | Призначення | Команда для перегляду |
|-----------|-------------|----------------------|
| **PID** | Унікальний ідентифікатор | `echo $$` |
| **State** | Поточний стан (R, S, D, Z, T) | `ps -o stat -p PID` |
| **Program Counter** | Адреса наступної інструкції | `/proc/PID/maps` |
| **Registers** | Збережені значення регістрів | (при context switch) |
| **Memory Info** | Карта пам'яті процесу | `cat /proc/PID/maps` |
| **Priority** | Пріоритет (nice value) | `ps -o ni -p PID` |
| **CPU Time** | Використаний час CPU | `ps -o time -p PID` |
| **PPID** | Батьківський процес | `ps -o ppid -p PID` |
| **Open Files** | Файлові дескриптори | `ls -la /proc/PID/fd` |
| **UID/GID** | Власник | `ps -o uid,gid -p PID` |

### Перегляд PCB через /proc

Linux надає доступ до інформації про процеси через віртуальну файлову систему `/proc`:

```bash
# Інформація про поточний процес
echo "PID поточного shell: $$"

# Статус процесу (детальний PCB)
cat /proc/$$/status

# Карта пам'яті
cat /proc/$$/maps | head -10

# Відкриті файли
ls -la /proc/$$/fd

# Командний рядок
cat /proc/$$/cmdline

# Поточна робоча директорія
readlink /proc/$$/cwd

# Батьківський процес
cat /proc/$$/status | grep PPid
```

### Навіщо потрібен PCB?

PCB критично важливий для:

1. **Context Switch** — при перемиканні між процесами ОС зберігає стан одного процесу (в його PCB) і відновлює стан іншого
2. **Планування** — планувальник використовує пріоритет і CPU time для вибору наступного процесу
3. **Захист** — UID/GID визначають права доступу
4. **Відновлення** — після I/O операції ОС знає, куди повернути процес

## Життєвий цикл процесу

Від народження до смерті процес проходить повний життєвий цикл:

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ЖИТТЄВИЙ ЦИКЛ ПРОЦЕСУ                              │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   1. НАРОДЖЕННЯ (fork/exec)                                          │
│   ┌─────────────────────────────────────────────────────────────┐    │
│   │  Батьківський процес викликає fork()                        │    │
│   │  ОС: створює PCB, виділяє PID, копіює адресний простір      │    │
│   │  Новий процес викликає exec() для завантаження програми     │    │
│   └─────────────────────────────────────────────────────────────┘    │
│                              │                                        │
│                              ▼                                        │
│   2. ЖИТТЯ (ready ↔ running ↔ waiting)                               │
│   ┌─────────────────────────────────────────────────────────────┐    │
│   │  Процес циклічно переходить між станами:                    │    │
│   │  • Отримує CPU час (running)                                │    │
│   │  • Перервано таймером (ready)                               │    │
│   │  • Чекає на I/O (waiting)                                   │    │
│   │  • I/O завершено (ready)                                    │    │
│   └─────────────────────────────────────────────────────────────┘    │
│                              │                                        │
│                              ▼                                        │
│   3. СМЕРТЬ (exit/kill)                                              │
│   ┌─────────────────────────────────────────────────────────────┐    │
│   │  Процес завершується: exit() або отримує сигнал             │    │
│   │  ОС: звільняє пам'ять, закриває файли                       │    │
│   │  PCB зберігається (zombie) поки батько не викличе wait()    │    │
│   │  Після wait() PCB видаляється повністю                      │    │
│   └─────────────────────────────────────────────────────────────┘    │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Створення процесу: fork() та exec()

```bash
# fork() створює копію поточного процесу
# exec() замінює код процесу новою програмою

# Приклад: bash створює новий процес для команди
bash -c 'echo "PID: $$"; sleep 5'

# Подивитися дерево процесів
pstree -p $$
```

```
┌───────────────────────────────────────────────────────────────────────┐
│                    FORK + EXEC                                        │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   Батьківський процес (PID: 1000)                                    │
│   │                                                                   │
│   │ fork()                                                            │
│   │                                                                   │
│   ├──────────────────────────────────────────┐                       │
│   │                                          │                        │
│   ▼                                          ▼                        │
│   Батько (PID: 1000)              Дитина (PID: 1001)                 │
│   продовжує роботу                fork() повертає 0                  │
│   fork() повертає 1001            │                                  │
│                                   │ exec("/bin/ls")                  │
│                                   │                                  │
│                                   ▼                                  │
│                                   Дитина тепер виконує ls            │
│                                   (код bash замінено на ls)          │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Завершення процесу та Zombie

```bash
# Створимо zombie-процес (для демонстрації)
# Батько створює дитину, дитина завершується, батько не викликає wait()

# Подивитися zombie-процеси
ps aux | awk '$8=="Z" {print}'

# Zombie займає тільки PCB (мінімум пам'яті)
# Звільняється коли батько викликає wait() або батько помирає
```

**Запитання**: Чому zombie-процес не можна "вбити" командою `kill`? Тому що він вже мертвий! Це як намагатися вбити труп.

## Практичні команди для роботи зі станами

### ps - Process Status

```bash
# Базова інформація про процеси
ps aux

# Формат виводу:
# USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
# root         1  0.0  0.1 169256 13120 ?        Ss   Sep01   0:14 /sbin/init

# STAT - стан процесу:
# R = Running (виконується)
# S = Sleeping (очікує, можна перервати)
# D = Disk sleep (очікує I/O, не можна перервати)
# Z = Zombie (завершений, чекає на батька)
# T = Stopped (зупинений, наприклад Ctrl+Z)
# + = Foreground process group

# Фільтрація за станом
ps aux | awk '$8 ~ /R/ {print "Running:", $11}'
ps aux | awk '$8 ~ /S/ {print "Sleeping:", $11}' | head -5
ps aux | awk '$8 ~ /Z/ {print "Zombie:", $11}'
```

### top - Real-time Monitor

```bash
# Інтерактивний монітор процесів
top

# Корисні клавіші в top:
# M - сортувати за пам'яттю
# P - сортувати за CPU
# T - сортувати за часом
# k - вбити процес (ввести PID)
# r - змінити пріоритет (renice)
# 1 - показати всі ядра CPU
# q - вийти

# Або htop для кращого інтерфейсу
htop
```

### Моніторинг конкретного процесу

```bash
# Відстежувати стан конкретного процесу
PID=$$  # PID поточного shell

# Стан
cat /proc/$PID/status | grep State

# Або через ps
ps -o pid,stat,cmd -p $PID

# Безперервний моніторинг
watch -n 0.5 "ps -o pid,stat,%cpu,%mem,cmd -p $PID"
```

## Черги процесів

ОС організовує процеси в **черги** для ефективного керування:

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ЧЕРГИ ПРОЦЕСІВ В ОС                                │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   JOB QUEUE (всі процеси в системі)                                  │
│   ┌─────────────────────────────────────────────────────────────┐    │
│   │ [P1] [P2] [P3] [P4] [P5] [P6] [P7] [P8] [P9] [P10] ...     │    │
│   └─────────────────────────────────────────────────────────────┘    │
│                                                                       │
│   READY QUEUE (готові до виконання)                                  │
│   ┌─────────────────────────────────────────────────────────────┐    │
│   │ ► [P3] → [P7] → [P1] → [P9] →                              │    │
│   └───────────────────────────────────────────────┬─────────────┘    │
│                                                   │                   │
│                                      Scheduler    │                   │
│                                                   ▼                   │
│                                              ┌────────┐               │
│                                              │  CPU   │               │
│                                              │ [P5]   │               │
│                                              └────────┘               │
│                                                                       │
│   DEVICE QUEUES (очікують на пристрої)                               │
│   ┌─────────────────────────────────────────────────────────────┐    │
│   │ Disk:      [P2] → [P6] →                                    │    │
│   │ Network:   [P4] → [P8] →                                    │    │
│   │ Keyboard:  [P10] →                                          │    │
│   └─────────────────────────────────────────────────────────────┘    │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Типи черг

| Черга | Призначення | Коли процес потрапляє |
|-------|-------------|----------------------|
| **Job Queue** | Всі процеси в системі | При створенні |
| **Ready Queue** | Готові до виконання | Після створення або завершення I/O |
| **Device Queues** | Чекають на конкретний пристрій | При запиті I/O |

## Приклад: відстеження життєвого циклу

Створимо простий скрипт для демонстрації станів:

```bash
#!/bin/bash
# lifecycle_demo.sh - демонстрація станів процесу

echo "1. Процес створено (NEW -> READY)"
echo "   PID: $$"
echo "   Стан: $(cat /proc/$$/status | grep State)"

echo ""
echo "2. Процес виконується (RUNNING)"
echo "   Виконуємо обчислення..."
for i in {1..1000000}; do
    : # порожня команда, споживає CPU
done
echo "   Обчислення завершено"

echo ""
echo "3. Процес чекає на I/O (WAITING)"
echo "   Читаємо з диска..."
cat /etc/passwd > /dev/null
echo "   Читання завершено"

echo ""
echo "4. Процес завершується (TERMINATED)"
echo "   Exit code: 0"
exit 0
```

```bash
# Запустити демонстрацію
chmod +x lifecycle_demo.sh
./lifecycle_demo.sh

# Моніторити стан у реальному часі (в іншому терміналі)
watch -n 0.1 "ps -o pid,stat,cmd -p $(pgrep lifecycle_demo)"
```

## 🎯 Міні-проект (30 хв)

### Завдання: Детектив станів процесів

Створіть скрипт, який аналізує стани процесів у системі та генерує звіт. Це типова задача для SRE/DevOps інженера.

**Кроки:**

1. Створіть файл скрипта:
```bash
#!/bin/bash
# process_detective.sh - аналіз станів процесів

REPORT_FILE=~/process_report_$(date +%Y%m%d_%H%M%S).txt

echo "=== ЗВІТ ПРО СТАНИ ПРОЦЕСІВ ===" > $REPORT_FILE
echo "Дата: $(date)" >> $REPORT_FILE
echo "Hostname: $(hostname)" >> $REPORT_FILE
echo "" >> $REPORT_FILE
```

2. Додайте підрахунок процесів за станами:
```bash
echo "--- СТАТИСТИКА СТАНІВ ---" >> $REPORT_FILE
echo "Running (R):  $(ps aux | awk '$8 ~ /R/ {count++} END {print count+0}')" >> $REPORT_FILE
echo "Sleeping (S): $(ps aux | awk '$8 ~ /S/ {count++} END {print count+0}')" >> $REPORT_FILE
echo "Disk I/O (D): $(ps aux | awk '$8 ~ /D/ {count++} END {print count+0}')" >> $REPORT_FILE
echo "Zombie (Z):   $(ps aux | awk '$8 ~ /Z/ {count++} END {print count+0}')" >> $REPORT_FILE
echo "Stopped (T):  $(ps aux | awk '$8 ~ /T/ {count++} END {print count+0}')" >> $REPORT_FILE
echo "" >> $REPORT_FILE
```

3. Додайте виявлення проблемних процесів:
```bash
echo "--- ПОТЕНЦІЙНІ ПРОБЛЕМИ ---" >> $REPORT_FILE

# Zombie-процеси
echo "Zombie-процеси:" >> $REPORT_FILE
ps aux | awk '$8 ~ /Z/ {print "  PID:", $2, "CMD:", $11}' >> $REPORT_FILE

# Процеси у D-state (можуть вказувати на проблеми з диском)
echo "Процеси в uninterruptible sleep (D):" >> $REPORT_FILE
ps aux | awk '$8 ~ /D/ {print "  PID:", $2, "CMD:", $11}' >> $REPORT_FILE
echo "" >> $REPORT_FILE
```

4. Додайте топ споживачів CPU:
```bash
echo "--- ТОП-5 ПО CPU ---" >> $REPORT_FILE
ps aux --sort=-%cpu | head -6 | tail -5 | \
  awk '{printf "  PID: %s, CPU: %s%%, CMD: %s\n", $2, $3, $11}' >> $REPORT_FILE
echo "" >> $REPORT_FILE
```

5. Виведіть результат:
```bash
echo "--- READY QUEUE (процеси, що чекають CPU) ---" >> $REPORT_FILE
ps aux | awk '$8 ~ /R/ && $3 < 1 {print "  PID:", $2, "STAT:", $8, "CMD:", $11}' >> $REPORT_FILE

echo "" >> $REPORT_FILE
echo "Звіт збережено: $REPORT_FILE"
cat $REPORT_FILE
```

**Очікуваний результат:**

Файл `process_report_YYYYMMDD_HHMMSS.txt` з:
- Статистикою процесів за станами
- Списком zombie-процесів (якщо є)
- Процесами у D-state
- Топ-5 споживачів CPU

**Бонус (для допитливих):**
- Додайте перевірку кожні 5 секунд протягом хвилини та порівняйте зміни
- Додайте alert якщо zombie-процесів більше 0
- Використайте `/proc/PID/status` для детальнішої інформації про конкретний процес

## Підсумок

| Термін | Визначення |
|--------|------------|
| **Стан процесу** | Поточний етап життєвого циклу (new, ready, running, waiting, terminated) |
| **New** | Процес створюється, виділяються ресурси |
| **Ready** | Готовий до виконання, чекає на CPU |
| **Running** | Активно виконується на процесорі |
| **Waiting** | Заблокований, чекає на I/O або подію |
| **Terminated** | Завершив виконання |
| **PCB** | Process Control Block - структура даних з інформацією про процес |
| **Context Switch** | Перемикання CPU між процесами зі збереженням/відновленням стану |
| **Zombie** | Завершений процес, чий статус не забрано батьком |
| **Ready Queue** | Черга процесів, готових до виконання |

| Команда | Призначення |
|---------|-------------|
| `ps aux` | Список всіх процесів зі станами |
| `top` / `htop` | Інтерактивний монітор процесів |
| `cat /proc/PID/status` | Детальна інформація про процес (PCB) |
| `pstree` | Дерево процесів |

На наступній лекції — диспетчеризація та перемикання контексту: як ОС швидко перемикається між процесами.

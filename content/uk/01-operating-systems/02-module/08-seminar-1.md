**Ситуація**: У системі з Priority Scheduling є процес з низьким пріоритетом, який не виконувався вже 24 години, бо постійно з'являються процеси з вищим пріоритетом.

## Частина 3: Задачі на планування (20 хв)

### Задача 3.1: FCFS

```
┌────────────────────────────────────────┐
│ Process │ Arrival Time │ Burst Time   │
│─────────│──────────────│──────────────│
│   P1    │      0       │      7       │
│   P2    │      2       │      4       │
│   P3    │      4       │      1       │
│   P4    │      5       │      4       │
└────────────────────────────────────────┘
```

**Завдання:**
1. Намалюйте Gantt Chart для FCFS
2. Обчисліть Turnaround Time для кожного процесу
3. Обчисліть Waiting Time для кожного процесу
4. Обчисліть середній Turnaround та Waiting Time

**Розв'язок:**

```
Gantt Chart:
┌───────────────┬────────┬───┬────────┐
│      P1       │   P2   │P3 │   P4   │
└───────────────┴────────┴───┴────────┘
0               7        11 12        16

Turnaround Time = Completion - Arrival
P1: 7 - 0 = 7
P2: 11 - 2 = 9
P3: 12 - 4 = 8
P4: 16 - 5 = 11

Waiting Time = Turnaround - Burst
P1: 7 - 7 = 0
P2: 9 - 4 = 5
P3: 8 - 1 = 7
P4: 11 - 4 = 7

Average Turnaround = (7 + 9 + 8 + 11) / 4 = 8.75
Average Waiting = (0 + 5 + 7 + 7) / 4 = 4.75
```

### Задача 3.2: SJF (Non-Preemptive)

Використовуючи ті ж дані, розв'яжіть для SJF:

**Розв'язок:**

```
Момент 0: Доступний тільки P1 → виконуємо P1
Момент 7: Доступні P2(4), P3(1), P4(4) → P3 найкоротший
Момент 8: Доступні P2(4), P4(4) → P2 (прибув раніше)
Момент 12: Доступний P4(4) → P4

Gantt Chart:
┌───────────────┬───┬────────┬────────┐
│      P1       │P3 │   P2   │   P4   │
└───────────────┴───┴────────┴────────┘
0               7   8        12       16

Turnaround Time:
P1: 7 - 0 = 7
P2: 12 - 2 = 10
P3: 8 - 4 = 4
P4: 16 - 5 = 11

Waiting Time:
P1: 7 - 7 = 0
P2: 10 - 4 = 6
P3: 4 - 1 = 3
P4: 11 - 4 = 7

Average Turnaround = (7 + 10 + 4 + 11) / 4 = 8.0
Average Waiting = (0 + 6 + 3 + 7) / 4 = 4.0
```

### Задача 3.3: Round Robin

Використовуючи ті ж дані з quantum = 2:

**Завдання:**
1. Намалюйте Gantt Chart
2. Скільки context switches відбулося?
3. Порівняйте з FCFS та SJF

**Розв'язок:**

```
Черга на початку: [P1]
t=0: P1 виконується 2, remaining=5, черга: [P1]
t=2: P2 прибув, черга: [P1, P2], виконуємо P2, remaining=2
t=4: P3 прибув, черга: [P1, P2, P3], виконуємо P1, remaining=3
t=5: P4 прибув, черга: [P2, P3, P4, P1]
t=6: P1 remaining=3→1, черга: [P2, P3, P4, P1]
     виконуємо P2, remaining=0, P2 завершено
t=8: черга: [P3, P4, P1], виконуємо P3, remaining=0, P3 завершено
     (P3 burst=1, тому виконується 1, а не 2)
t=9: черга: [P4, P1], виконуємо P4, remaining=2
t=11: черга: [P1, P4], виконуємо P1, remaining=1
t=13: черга: [P4, P1], виконуємо P4, remaining=0, P4 завершено
t=14: черга: [P1], виконуємо P1, remaining=0, P1 завершено

Gantt Chart:
┌──┬──┬──┬──┬─┬──┬──┬─┐
│P1│P2│P1│P2│P3│P4│P1│P4│P1│
└──┴──┴──┴──┴─┴──┴──┴─┘
0  2  4  6  8 9 11 13 14 15

Context switches: 8
```

### Задача 3.4: Priority Scheduling

```
┌──────────────────────────────────────────────────┐
│ Process │ Arrival │ Burst │ Priority (1=highest)│
│─────────│─────────│───────│─────────────────────│
│   P1    │    0    │   5   │        3            │
│   P2    │    1    │   3   │        1            │
│   P3    │    2    │   4   │        4            │
│   P4    │    3    │   2   │        2            │
└──────────────────────────────────────────────────┘
```

**Завдання** (preemptive priority):
1. Намалюйте Gantt Chart
2. Який процес страждає від starvation?

**Розв'язок:**

```
t=0: P1 починає (priority 3)
t=1: P2 прибуває (priority 1) → preempt P1
t=4: P2 завершено, P4 (priority 2) чекає, P1 (priority 3) remaining=4
     Виконуємо P4
t=6: P4 завершено, виконуємо P1
t=10: P1 завершено, виконуємо P3
t=14: P3 завершено

Gantt Chart:
┌─┬───┬──┬────┬────┐
│P1│ P2 │P4│ P1 │ P3 │
└─┴───┴──┴────┴────┘
0 1    4  6   10   14

P3 чекав найдовше (12 одиниць часу)
Якби постійно приходили high-priority процеси, P3 ніколи б не виконався
```

## Частина 4: Аналіз реальних кейсів (20 хв)

### Кейс 4.1: Chrome "з'їдає" RAM

**Ситуація**: Користувач скаржиться, що Google Chrome використовує 8 ГБ RAM при 20 відкритих вкладках.

**Питання для обговорення:**
1. Чому Chrome використовує окремий процес для кожної вкладки?
2. Які переваги та недоліки такого підходу?
3. Як би ви оптимізували використання пам'яті?

**Підказки для обговорення:**
- Ізоляція безпеки
- Стабільність (одна вкладка падає ≠ весь браузер)
- Паралелізм
- Memory overhead

### Кейс 4.2: Сервер "підвисає"

**Ситуація**: Web-сервер обробляє запити, але періодично "підвисає" на кілька секунд. Адміністратор помітив, що це збігається з backup-скриптом, який запускається щохвилини.

**Питання для обговорення:**
1. Що може бути причиною?
2. Як діагностувати проблему? (які команди?)
3. Як виправити, не відключаючи backup?

**Підказки:**
- nice/renice для backup
- ionice для I/O пріоритету
- Розклад backup на нічний час
- Аналіз з top/iotop

### Кейс 4.3: Zombie apocalypse

**Ситуація**: Адміністратор помітив 500+ zombie-процесів у системі.

```bash
ps aux | grep -c Z
# 532
```

**Питання для обговорення:**
1. Чим це загрожує системі?
2. Як знайти "винуватця" (батьківський процес)?
3. Як виправити проблему?

**Команди для аналізу:**
```bash
# Знайти zombie та їх батьків
ps -eo pid,ppid,stat,cmd | grep Z

# Знайти процес, що створює zombie
ps -eo pid,ppid | grep <zombie_ppid> | head -1
```

### Кейс 4.4: Real-time audio

**Ситуація**: Музикант використовує Linux для запису музики. При великій кількості треків з'являються "заїкання" (audio glitches).

**Питання для обговорення:**
1. Чому звичайний планувальник не підходить для audio?
2. Які рішення існують? (RT kernel, JACK, pipewire)
3. Як налаштувати пріоритети для audio-процесів?

**Команди:**
```bash
# Перевірити, чи є realtime scheduling
chrt -m

# Запустити процес з RT priority
sudo chrt -f 80 ./audio_app
```

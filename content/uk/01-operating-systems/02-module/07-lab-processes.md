**Мета:** після виконання лабораторної роботи студенти зможуть:

- Переглядати інформацію про процеси в Linux та Windows

- Змінювати пріоритети процесів
- Розуміти ієрархію процесів та стани процесів
- Використовувати інструменти моніторингу в реальному часі

## Передумови

- Базові навички роботи з терміналом Linux
- Розуміння концепцій процесів та станів (матеріал лекцій 01-06 модуля 2)

### Стани процесів

```
┌───────────────────────────────────────────────────────────────────────┐
│                    СТАНИ ПРОЦЕСІВ (STAT у ps)                         │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│   ОСНОВНІ СТАНИ:                                                      │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ R → Running    → виконується або готовий                        │ │
│   │ S → Sleeping   → очікує події (interruptible)                   │ │
│   │ D → Disk sleep → очікує I/O (uninterruptible)                   │ │
│   │ T → Stopped    → зупинений (Ctrl+Z або SIGSTOP)                 │ │
│   │ Z → Zombie     → завершений, чекає wait() від батька            │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ДОДАТКОВІ СИМВОЛИ:                                                  │
│   ┌─────────────────────────────────────────────────────────────────┐ │
│   │ < → high priority (low nice)                                    │ │
│   │ N → low priority (high nice)                                    │ │
│   │ s → session leader                                              │ │
│   │ l → multi-threaded (uses CLONE_THREAD)                          │ │
│   │ + → foreground process group                                    │ │
│   └─────────────────────────────────────────────────────────────────┘ │
│                                                                       │
│   ПРИКЛАДИ:                                                           │
│   Ss  → sleeping, session leader                                      │
│   R+  → running, foreground                                           │
│   SN  → sleeping, nice (low priority)                                 │
│   Sl  → sleeping, multi-threaded                                      │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Крок 2. Підготовка тестових скриптів

Створіть каталог для лабораторної роботи:

```bash
mkdir -p ~/lab07_processes
cd ~/lab07_processes
```

Створіть тестовий скрипт для CPU-навантаження:

```bash
cat > cpu_load.sh << 'EOF'
#!/bin/bash
# cpu_load.sh - Скрипт для генерації CPU-навантаження
echo "PID: $$ - CPU load started"
while true; do
    # Обчислення для навантаження CPU
    echo "scale=5000; 4*a(1)" | bc -l > /dev/null 2>&1
done
EOF
chmod +x cpu_load.sh
```

Створіть скрипт з I/O-навантаженням:

```bash
cat > io_load.sh << 'EOF'
#!/bin/bash
# io_load.sh - Скрипт для I/O-навантаження
echo "PID: $$ - I/O load started"
while true; do
    dd if=/dev/zero of=/tmp/testfile_$$ bs=1M count=10 2>/dev/null
    rm -f /tmp/testfile_$$
    sleep 1
done
EOF
chmod +x io_load.sh
```

Створіть батьківський процес з дочірніми:

```bash
cat > parent_child.sh << 'EOF'
#!/bin/bash
# parent_child.sh - Демонстрація батьківсько-дочірніх зв'язків
echo "Parent PID: $$"

# Створюємо дочірні процеси
for i in 1 2 3; do
    (
        echo "Child $i PID: $$ (Parent: $PPID)"
        sleep 300
    ) &
done

echo "Parent waiting for children..."
wait
echo "All children finished"
EOF
chmod +x parent_child.sh
```

#### 3.2 Завершення процесів

```bash
# 1. Запустіть тестовий процес
./cpu_load.sh &
CPU_PID=$!
echo "CPU load PID: $CPU_PID"

# 2. Перевірте, що він працює
ps -p $CPU_PID

# 3. Надішліть SIGTERM (коректне завершення)
kill $CPU_PID
sleep 1
ps -p $CPU_PID  # Має показати, що процес відсутній
```

```bash
# 4. Запустіть процес, що ігнорує SIGTERM
cat > stubborn.sh << 'EOF'
#!/bin/bash
trap '' SIGTERM  # Ігноруємо SIGTERM
echo "PID: $$ - I ignore SIGTERM! Use SIGKILL to stop me."
while true; do sleep 1; done
EOF
chmod +x stubborn.sh

./stubborn.sh &
STUBBORN_PID=$!

# 5. Спробуйте SIGTERM
kill $STUBBORN_PID
ps -p $STUBBORN_PID  # Ще працює!

# 6. Використайте SIGKILL
kill -9 $STUBBORN_PID
ps -p $STUBBORN_PID  # Тепер завершено

# Запишіть у звіт: чому SIGKILL завжди працює?
```

#### 3.3 Сигнали STOP та CONT

```bash
# 1. Запустіть процес

# 2. Подивіться його стан в top (R - running)

# 3. Призупиніть процес

# 4. Перевірте стан (T - stopped)

# 6. Перевірте стан знову (R - running)
```

#### 4.2 Запуск з різними пріоритетами

```bash
# 1. Запустіть процес зі звичайним пріоритетом
./cpu_load.sh &
PID_NORMAL=$!
echo "Normal priority PID: $PID_NORMAL"

# 2. Запустіть процес з низьким пріоритетом (nice = 19)
nice -n 19 ./cpu_load.sh &
PID_LOW=$!
echo "Low priority PID: $PID_LOW"

# 3. Запустіть процес з високим пріоритетом (потрібен sudo)
sudo nice -n -10 ./cpu_load.sh &
PID_HIGH=$!
echo "High priority PID: $PID_HIGH"

# 4. Порівняйте в top
top -p $PID_NORMAL,$PID_LOW,$PID_HIGH

# Зверніть увагу на колонку NI та %CPU
# Процес з вищим пріоритетом отримує більше CPU

# 5. Завершіть всі
kill $PID_NORMAL $PID_LOW
sudo kill $PID_HIGH
```

#### 4.3 Зміна пріоритету існуючого процесу

```bash
# 1. Запустіть процес
./cpu_load.sh &
PID=$!

# 2. Подивіться поточний nice
ps -o pid,ni,cmd -p $PID

# 3. Знизьте пріоритет (збільште nice)
renice 10 -p $PID
ps -o pid,ni,cmd -p $PID

# 4. Спробуйте підвищити пріоритет (без sudo - помилка!)
renice 0 -p $PID
# renice: failed to set priority for 1234 (process ID): Permission denied

# 5. Підвищіть з sudo
sudo renice -5 -p $PID
ps -o pid,ni,cmd -p $PID

# 6. Завершіть
kill $PID
```

### Крок 7. Zombie- та orphan-процеси

#### 5.1 Створення zombie-процесу

```bash
# Створіть скрипт, що створює zombie
cat > create_zombie.sh << 'EOF'
#!/bin/bash
# Батьківський процес НЕ викликає wait()

echo "Parent PID: $$"

# Форкаємо дочірній процес
(
    echo "Child PID: $$ - I will become zombie!"
    exit 0  # Дочірній завершується
) &

CHILD_PID=$!
echo "Child PID: $CHILD_PID"

# Батько НЕ викликає wait(), просто спить
echo "Parent sleeping... Child will become zombie"
sleep 60
EOF
chmod +x create_zombie.sh

# Запустіть
./create_zombie.sh &
sleep 2

# Знайдіть zombie процес
ps aux | grep -E 'Z|defunct'

# Запишіть у звіт:
# - Який статус має zombie? (Z)
# - Чи споживає zombie CPU/Memory?
# - Як "вбити" zombie?

# Завершіть батьківський процес - zombie зникне
killall create_zombie.sh
```

#### 5.2 Orphan-процес

```bash
# Створіть скрипт
cat > create_orphan.sh << 'EOF'
#!/bin/bash
echo "Parent PID: $$"

# Створюємо дочірній процес
(
    echo "Child PID: $$ - My parent is $$, PPID: $PPID"
    sleep 2
    echo "Child: Now my PPID should be 1 (init/systemd)"
    echo "Child: Checking... PPID = $(ps -o ppid= -p $$)"
    sleep 30
) &

echo "Parent: I'm exiting immediately!"
exit 0
EOF
chmod +x create_orphan.sh

# Запустіть
./create_orphan.sh

# Через 3 секунди перевірте PPID дочірнього процесу
sleep 3
pgrep -a sleep | grep -v grep

# Знайдіть процес з PPID=1
ps -eo pid,ppid,cmd | grep sleep

# Запишіть у звіт:
# - Хто стає батьком orphan-процесу?
# - Чи це проблема для системи?
```

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Підготувати середовище: встановити утиліти `htop`, `pstree`, `stress-ng` і створити навчальні скрипти згідно з кроками 1–2 прикладу.

3. Отримати перелік процесів трьома способами — `ps`, `ps aux`, `ps -ef` — і пояснити різницю у складі колонок.

4. Побудувати дерево процесів командою `pstree` і визначити, який процес породив ваш термінал.

5. Знайти процес, зазначений у варіанті, визначити його PID, стан, пріоритет та обсяг зайнятої пам'яті.

6. Запустити навчальний скрипт у фоновому режимі, перевести його на передній план і назад, після чого коректно завершити сигналом, зазначеним у варіанті.

7. Порівняти дію сигналів SIGTERM і SIGKILL на тому самому процесі. Зафіксувати, у чому полягає різниця.

8. Запустити процес із пріоритетом свого варіанта командою `nice`, змінити пріоритет уже запущеного процесу командою `renice` і пояснити, чому зменшення значення потребує прав root.

9. Відтворити zombie- та orphan-процес за кроком 7 прикладу. Зафіксувати стан процесу у виводі `ps` і пояснити, який процес стає батьківським для orphan.

10. Виконати індивідуальне завдання свого варіанта.

11. Оформити звіт і зробити висновок.

## Вимоги до звіту

Звіт оформлюється на бланку встановленого зразка і має містити:

- тему, мету та обладнання;
- постановку задачі за індивідуальним варіантом;
- таблицю з переліком досліджених процесів: PID, PPID, стан, пріоритет, пам'ять;
- перелік виконаних команд із поясненням призначення кожного ключа;
- знімки екрана з результатами кожного кроку, зокрема вивід `pstree` і стан zombie-процесу;
- порівняння дії сигналів SIGTERM і SIGKILL;
- текст і результат роботи скрипта індивідуального завдання;
- висновок про те, якими засобами адміністратор діагностує та усуває проблеми з процесами.

| 12 | `yes` | SIGSTOP/SIGCONT | 5 | Показати, як змінюється стан процесу після SIGSTOP |
| 13 | `ping` | SIGKILL | -5 | Знайти orphan-процеси та їхнього нового батька |
| 14 | `sleep` | SIGTERM | 0 | Скрипт, що виводить топ-5 процесів за пам'яттю у файл |
| 15 | `htop` | SIGHUP | 10 | Пояснити, що станеться з дочірніми процесами після SIGHUP |
| 16 | `stress-ng` | SIGTERM | 19 | Порівняти навантаження на CPU за різних nice |
| 17 | `cat` | SIGKILL | 5 | Знайти всі процеси, породжені вашим терміналом |
| 18 | `tail -f` | SIGTERM | -10 | Скрипт перезапуску процесу, якщо він завершився |
| 19 | `find` | SIGSTOP/SIGCONT | 0 | Дослідити, як змінюється стан процесу під час дискових операцій |
| 20 | `bash` | SIGINT | 15 | Скрипт, що будує звіт про процеси у форматі CSV |

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Що таке процес і які ресурси виділяє йому операційна система?
2. Яка різниця між `ps aux` та `ps -ef`? Які колонки відрізняються?
3. Назвіть основні стани процесу в Linux і позначення кожного у виводі `ps`.
4. Поясніть різницю між SIGTERM (15) та SIGKILL (9).
5. Що таке nice value і в яких межах він змінюється?
6. Що таке zombie-процес і як він виникає?
7. Чим foreground-процес відрізняється від background-процесу? Як перемикати режим?
8. Як дізнатися, скільки потоків має процес?

### Достатній рівень (конструктивно-варіативний)

1. Що означає стан «D» (disk sleep) і чому такий процес не завершується командою `kill -9`?
2. Чому для зменшення значення nice потрібні права root, а для збільшення — ні?
3. Як «видалити» zombie-процес, якщо сам він уже не виконується?
4. Що відбувається з дочірніми процесами, коли батьківський процес завершується раніше за них?
5. Запишіть команду, яка покаже п'ять процесів з найбільшим споживанням пам'яті.
6. Чим `kill`, `pkill` і `killall` відрізняються за способом вибору процесу?
7. Як подивитися дерево процесів і визначити, який процес породив заданий?
8. Які відомості про процес дає каталог `/proc/PID` і чим він зручніший за `ps`?

### Високий рівень (творчий)

1. Процес не реагує ні на SIGTERM, ні на SIGKILL. Назвіть можливі причини та порядок дій адміністратора.
2. Сервер періодично «підвисає» під навантаженням. Опишіть, які показники процесів ви перевірите й у якій послідовності.
3. Поясніть, чому кількість zombie-процесів, що зростає, є ознакою помилки в програмі, а не в ядрі.
4. Сформулюйте критерій, за яким адміністратор обирає між зміною пріоритету процесу та його завершенням. Проілюструйте прикладом.

## Додаткові ресурси

### Корисні файли в /proc

```bash
# Інформація про конкретний процес
cat /proc/1234/status    # Детальний статус
cat /proc/1234/cmdline   # Командний рядок
cat /proc/1234/environ   # Змінні середовища
cat /proc/1234/fd        # Відкриті файлові дескриптори
cat /proc/1234/maps      # Карта пам'яті

# Загальна інформація
cat /proc/loadavg        # Load average
cat /proc/stat           # Статистика CPU
cat /proc/meminfo        # Інформація про пам'ять
```

### Додаткові інструменти

```bash
# iotop - моніторинг I/O по процесах
sudo apt install iotop
sudo iotop

# pidstat - статистика процесів
sudo apt install sysstat
pidstat 1 5

# strace - трасування системних викликів
strace -p 1234

# lsof - список відкритих файлів процесу
lsof -p 1234
```

## Дебати Торвальдса і Таненбаума

У 1992 році відбулася знаменита публічна дискусія між Лінусом Торвальдсом (автор Linux) та Ендрю Таненбаумом (автор MINIX, професор):

> **Таненбаум:** "Linux is obsolete. Monolithic kernels are a step back."
> (Linux застарів. Монолітні ядра — це крок назад.)

> **Торвальдс:** "Your langstrumpf is just about langstrumpf, linux is about langstrumpf."
> (Ваш MINIX — це академічна іграшка, Linux — це реальна система.)

30 років потому: Linux працює на 96% серверів, 85% смартфонів та 100% суперкомп'ютерів. MINIX... працює в Intel Management Engine всередині кожного процесора Intel.

**Обидва виявилися праві — для різних випадків.**

## Монолітне ядро (Monolithic Kernel)

**Визначення:** Все ядро — один великий бінарний файл. Всі підсистеми (ФС, мережа, драйвери) працюють у Kernel Mode.

```
┌─────────────────────────────────────────────────────────────────┐
│                    МОНОЛІТНЕ ЯДРО (Linux)                       │
│                                                                 │
│   User Space                                                    │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │    Firefox    │    Terminal    │    VS Code             │  │
│   └───────────────┴────────────────┴────────────────────────┘  │
│                              │                                  │
│   ═══════════════════════════╪══════════════════════════════   │
│                              │ System Calls                     │
│   Kernel Space               ▼                                  │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                                                          │  │
│   │  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │  │
│   │  │ Process  │  │  Memory  │  │   VFS    │  │ Network  │ │  │
│   │  │ Scheduler│  │ Manager  │  │          │  │  Stack   │ │  │
│   │  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │  │
│   │                                                          │  │
│   │  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │  │
│   │  │   ext4   │  │   XFS    │  │   NVMe   │  │  e1000   │ │  │
│   │  │  driver  │  │  driver  │  │  driver  │  │  driver  │ │  │
│   │  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │  │
│   │                                                          │  │
│   │  ВСЕ працює в Ring 0 — повний доступ до заліза          │  │
│   │  Виклик функції = ~10 наносекунд                        │  │
│   │                                                          │  │
│   └─────────────────────────────────────────────────────────┘  │
│                              │                                  │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                      HARDWARE                            │  │
│   └─────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

### Переваги монолітного ядра

| Перевага | Пояснення |
|----------|-----------|
| **Швидкість** | Виклик функції в ядрі ≈ 10 нс (без перемикання контексту) |
| **Простота** | Компоненти напряму викликають один одного |
| **Зрілість** | Десятиліття оптимізацій (Linux, FreeBSD) |

### Недоліки монолітного ядра

| Недолік | Пояснення |
|---------|-----------|
| **Один баг = kernel panic** | Помилка в драйвері "вбиває" всю систему |
| **Складність тестування** | 30+ мільйонів рядків коду (Linux 6.x) |
| **Безпека** | Вразливість у драйвері = доступ до всього |

**Практичний приклад:**

```bash
# Розмір ядра Linux
ls -lh /boot/vmlinuz-$(uname -r)
# ~10-15 МБ (стиснене), ~30 МБ (розпаковане)

# Скільки рядків коду в Linux
# (потрібні вихідники)
# find linux-source -name "*.c" -o -name "*.h" | xargs wc -l
# Результат: ~30 000 000 рядків

# Завантажені модулі (частина монолітного ядра, що завантажується динамічно)
lsmod | head -10

# Інформація про модуль
modinfo ext4 | head -10
```

### Модульність Linux

Linux — **модульне монолітне ядро**. Драйвери можна завантажувати/вивантажувати без перезавантаження.

```
┌─────────────────────────────────────────────────────────────────┐
│                    МОДУЛІ ЯДРА LINUX                            │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                    Базове ядро (vmlinuz)                 │  │
│   │  Scheduler, MM, VFS, базові драйвери                    │  │
│   └───────────────────────────┬─────────────────────────────┘  │
│                               │                                 │
│        ┌──────────────────────┼──────────────────────┐         │
│        │                      │                      │         │
│        ▼                      ▼                      ▼         │
│   ┌─────────┐            ┌─────────┐            ┌─────────┐    │
│   │ nvidia  │            │  ext4   │            │bluetooth│    │
│   │  .ko    │            │  .ko    │            │  .ko    │    │
│   └─────────┘            └─────────┘            └─────────┘    │
│   Завантажується         Завантажується        Завантажується  │
│   при старті X           при mount             при потребі     │
│                                                                 │
│   Все одно Ring 0 — повні привілеї                             │

```

```bash
# Завантажити модуль
sudo modprobe bluetooth

# Вивантажити модуль
sudo modprobe -r bluetooth

# Список модулів
lsmod | grep -E "bluetooth|nvidia|ext4"

# Параметри модуля
cat /sys/module/ext4/parameters/*
```

## Мікроядро (Microkernel)

**Визначення:** Ядро містить лише мінімум функцій. Все інше (драйвери, ФС, мережа) працює в User Space як окремі процеси.

```
┌─────────────────────────────────────────────────────────────────┐
│                    МІКРОЯДРО (QNX, MINIX, L4)                   │
│                                                                 │
│   User Space                                                    │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                                                          │  │
│   │  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │  │
│   │  │  App1  │ │  App2  │ │   FS   │ │Network │ │ Driver │ │  │
│   │  │        │ │        │ │ Server │ │ Server │ │ Server │ │  │
│   │  └───┬────┘ └───┬────┘ └───┬────┘ └───┬────┘ └───┬────┘ │  │
│   │      │          │          │          │          │       │  │
│   │      │          │          │          │          │       │  │
│   │      └──────────┴──────────┴──────────┴──────────┘       │  │
│   │                           │                               │  │
│   │                      IPC (повідомлення)                   │  │
│   │                           │                               │  │
│   └───────────────────────────┼───────────────────────────────┘  │
│                               │                                  │
│   ════════════════════════════╪════════════════════════════════ │
│                               │                                  │
│   Kernel Space (МІНІМАЛЬНЕ)   ▼                                 │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐   │  │
│   │  │     IPC      │  │  Scheduler   │  │  Basic MM    │   │  │
│   │  │ (message     │  │  (перемикання│  │  (сторінки)  │   │  │
│   │  │  passing)    │  │   контексту) │  │              │   │  │
│   │  └──────────────┘  └──────────────┘  └──────────────┘   │  │
│   │                                                          │  │
│   │  ~10 000 рядків коду (vs 30 000 000 у Linux)            │  │
│   └─────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

### Переваги мікроядра

| Перевага | Пояснення |
|----------|-----------|
| **Надійність** | Crash драйвера ≠ crash системи (можна перезапустити) |
| **Безпека** | Мінімальна поверхня атаки в Ring 0 |
| **Модифікованість** | Легко замінити компонент без перекомпіляції ядра |
| **Формальна верифікація** | seL4 — математично доведена коректність |

### Недоліки мікроядра

| Недолік | Пояснення |
|---------|-----------|
| **Overhead IPC** | Кожен виклик = повідомлення через ядро (~1000 нс vs 10 нс) |
| **Складність** | Розподілена система, важче відлагоджувати |
| **Менша екосистема** | Менше драйверів, менше підтримки |

### Де використовуються мікроядра

| Система | Сфера | Чому мікроядро |
|---------|-------|----------------|
| **QNX** | Автомобілі, медицина | Сертифікація безпеки, перезапуск компонентів |
| **seL4** | Оборона, аерокосмос | Математично доведена коректність |
| **MINIX 3** | Intel ME (в кожному CPU) | Мінімальна поверхня атаки |
| **Fuchsia (Zircon)** | Google, IoT | Модульність, безпека |
| **L4 family** | Дослідження, вбудовані | Швидкий IPC |

## Гібридне ядро (Hybrid Kernel)

**Визначення:** Компроміс — частина сервісів у ядрі (для швидкості), частина — в User Space (для надійності).

```
│   │  Applications  │  Subsystems   │  Services               │  │

│                               │                                 │
```

```
│   • Передача повідомлень       • Кому дозволити доступ         │
│                                                                 │
│   Механізми стабільні          Політики змінюються             │
│   (змінюються рідко)           (налаштовуються)                │
│                                                                 │
│   Приклад: Linux scheduler     CFS, FIFO, RR — різні політики  │
│            реалізує механізм   на одному механізмі             │
└─────────────────────────────────────────────────────────────────┘
```

## Практичне завдання

Дослідіть архітектуру вашої системи:

```bash
# 1. Тип ядра
uname -s  # Linux = монолітне модульне

# 2. Кількість модулів ядра
lsmod | wc -l

# 3. Інформація про ядро
cat /proc/version

# 4. Системні виклики (монолітний стиль)
cat /proc/kallsyms | grep sys_ | wc -l

# 5. IPC механізми (є в Linux, але основні сервіси в ядрі)
ipcs -a

# 6. Час syscall (швидкий = монолітний)
time dd if=/dev/zero of=/dev/null bs=1 count=100000

# 7. На macOS: перевірити компоненти XNU
# sysctl kern.ostype kern.osrelease
```

## Підсумок

| Архітектура | Коли використовувати | Приклади |
|-------------|---------------------|----------|
| **Монолітне** | Максимальна продуктивність, загальне призначення | Linux, FreeBSD |
| **Мікроядро** | Критична надійність, сертифікація, безпека | QNX (авто), seL4 (оборона) |
| **Гібридне** | Баланс продуктивності та надійності | Windows, macOS |

**Ключовий висновок:** Немає "найкращої" архітектури — є архітектура, оптимальна для конкретної задачі. Linux домінує на серверах через продуктивність. QNX керує автомобілями через надійність. Windows NT — компроміс для десктопів.

На наступній лекції почнемо детальне вивчення операційної системи Windows.

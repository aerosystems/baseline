## Теоретичні відомості

### 1 Єдине дерево замість літер дисків

У Windows кожен носій отримує власну літеру й власний корінь. У Linux корінь один — `/`, а будь-який додатковий носій приєднується до наявного дерева в довільній точці, яка називається точкою монтування. Через це шлях `/media/student/usb/report.txt` нічого не говорить про фізичний пристрій: те саме дерево може бути зібране з кількох дисків, мережевих ресурсів і віртуальних файлових систем.

Наслідок для адміністратора: питання «на якому диску лежить файл» у Linux завжди вимагає перевірки командою `df` або `findmnt`, а не читання шляху.

### 2 Навігація та перегляд

```bash
pwd                      # поточний каталог
cd /var/log              # абсолютний шлях
cd ../..                 # на два рівні вгору
cd ~                     # домашній каталог
cd -                     # попередній каталог
ls -lha                  # докладно, з прихованими, зручні одиниці
ls -lt                   # сортування за часом зміни
tree -L 2 /etc           # дерево обмеженої глибини
stat report.txt          # повні метадані файлу
file report.txt          # визначити реальний тип вмісту
```

Прихованим у Linux вважається файл, ім'я якого починається з крапки. Це не атрибут, як у Windows, а домовленість про ім'я — саме тому «приховати» файл можна звичайним перейменуванням.

### 3 Файлові операції

Таблиця 1 — Основні команди роботи з файлами й каталогами

| Команда | Дія | Типові ключі |
|---------|-----|--------------|
| `mkdir` | створити каталог | `-p` створити разом із батьківськими |
| `touch` | створити порожній файл або оновити час | — |
| `cp` | копіювати | `-r` рекурсивно, `-i` питати, `-p` зберегти атрибути |
| `mv` | перемістити або перейменувати | `-i` питати, `-n` не перезаписувати |
| `rm` | видалити | `-r` рекурсивно, `-f` без запитів, `-i` питати |
| `rmdir` | видалити порожній каталог | — |
| `cat`, `less` | переглянути вміст | `less` гортає великі файли |
| `head`, `tail` | початок або кінець файлу | `-n 20` кількість рядків, `-f` стежити |

Команда `mv` виконує і переміщення, і перейменування, бо для файлової системи це та сама операція — зміна запису в каталозі.

### 4 Пошук файлів

```bash
find ~/lab7 -name "*.log"              # за іменем
find ~/lab7 -iname "*.LOG"             # без урахування регістру
find /var/log -type f -size +1M        # файли більші за 1 МБ
find ~ -mtime -1                       # змінені за останню добу
find ~/lab7 -type f -exec wc -l {} \;  # виконати команду над кожним
locate passwd                          # швидкий пошук за індексом
grep -rn "PATH" /etc/profile.d/        # пошук усередині файлів
```

Команда `find` обходить дерево в реальному часі й тому бачить щойно створені файли; `locate` шукає в заздалегідь побудованому індексі й працює миттєво, але не знає про зміни, зроблені після останнього оновлення бази.

### 5 Посилання

Таблиця 2 — Жорсткі та символічні посилання

| Характеристика | Жорстке (`ln`) | Символічне (`ln -s`) |
|----------------|----------------|----------------------|
| Що зберігає | той самий inode | шлях до іншого файлу |
| Між файловими системами | неможливе | можливе |
| На каталог | неможливе | можливе |
| Після видалення оригіналу | дані доступні | посилання «висить» |
| Видно в `ls -l` | звичайний файл | стрілка на ціль |

Жорстке посилання — це другий запис у каталозі, що вказує на той самий inode: обидва імені рівноправні, і файл зникає лише тоді, коли видалено останнє з них. Символічне посилання — окремий маленький файл із текстом шляху, тому воно «ламається», якщо ціль перемістити.

### 6 Монтування носіїв

```bash
lsblk                                  # дерево блокових пристроїв
sudo blkid                             # UUID і тип файлової системи
sudo mkdir -p /mnt/lab
sudo mount /dev/sdb1 /mnt/lab          # приєднати розділ
findmnt /mnt/lab                       # перевірити монтування
df -hT /mnt/lab                        # тип ФС і вільне місце
sudo umount /mnt/lab                   # від'єднати
```

Перед вилученням носія його обов'язково відмонтовують: система тримає дані в кеші й записує їх на диск відкладено. Якщо `umount` повідомляє «target is busy», причину знаходять командою `lsof +D /mnt/lab` — це процес, який відкрив файл на цьому носії.

Постійні монтування описують у файлі `/etc/fstab`, де носій зазвичай позначають не іменем пристрою, а UUID: імена `/dev/sdb1` залежать від порядку виявлення й можуть змінитися після перезавантаження.

### 7 Дисковий простір

```bash
df -h                                  # вільне місце за точками монтування
df -i                                  # вільні inode
du -sh ~/lab7                          # обсяг каталогу
du -h --max-depth=1 /var | sort -h     # найбільші підкаталоги
ncdu /var                              # інтерактивний аналіз (за наявності)
```

Можлива ситуація, коли `df -h` показує вільне місце, а система повідомляє «No space left on device»: це означає, що вичерпано не байти, а inode — записи для файлів. Саме тому дисковий простір перевіряють обома командами.

### 8 Архівування та стиснення

```bash
tar -cvf archive.tar dir/              # створити архів
tar -czvf archive.tar.gz dir/          # архів зі стисненням gzip
tar -tzvf archive.tar.gz               # переглянути вміст
tar -xzvf archive.tar.gz -C /tmp/out   # розпакувати в каталог
gzip report.txt                        # стиснути окремий файл
zip -r archive.zip dir/                # сумісний із Windows формат
```

У Linux архівування й стиснення історично розділені: `tar` збирає дерево файлів в один потік, а `gzip` чи `xz` стискає цей потік. Тому подвійне розширення `.tar.gz` описує саме два послідовні перетворення.

### Крок 1. Пісочниця та структура каталогів

```bash
student@lab-vm:~$ mkdir -p ~/lab7/{src,docs,bak,mnt}
student@lab-vm:~$ cd ~/lab7
student@lab-vm:~/lab7$ cp /etc/services /etc/hosts /etc/passwd src/
student@lab-vm:~/lab7$ ls -lh src/
-rw-r--r-- 1 student student  221 вер 18 10:12 hosts

.
├── bak
├── docs
├── mnt
└── src
```

Фігурні дужки розгортаються оболонкою: один рядок `mkdir -p ~/lab7/{src,docs,bak,mnt}` створює одразу чотири каталоги.

### Крок 2. Метадані та типи файлів

```bash
student@lab-vm:~/lab7$ stat src/hosts
  File: src/hosts
  Size: 221        Blocks: 8          IO Block: 4096   regular file
Device: 8,2	Inode: 1443521     Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/student)   Gid: ( 1000/student)
Modify: 2026-09-18 10:12:03.412000000 +0300

student@lab-vm:~/lab7$ file src/*
src/hosts:    ASCII text
src/passwd:   ASCII text
src/services: ASCII text

student@lab-vm:~/lab7$ file /bin/ls
/bin/ls: ELF 64-bit LSB pie executable, x86-64, dynamically linked
```

Команда `file` визначає тип за вмістом, а не за розширенням: у Linux розширення є лише частиною імені й ні на що не впливає.

### Крок 3. Пошук

```bash
student@lab-vm:~/lab7$ find /etc -name "*.conf" -size +10k 2>/dev/null | head -3
/etc/security/limits.conf
/etc/ssh/sshd_config.conf
/etc/sysctl.conf

student@lab-vm:~/lab7$ find ~/lab7 -type f -mmin -10
/home/student/lab7/src/hosts
/home/student/lab7/src/passwd
/home/student/lab7/src/services

student@lab-vm:~/lab7$ find src -type f -exec wc -l {} \;
12 src/hosts
48 src/passwd
11473 src/services

student@lab-vm:~/lab7$ grep -c "" src/services
11473
```

Перенаправлення `2>/dev/null` приховує повідомлення про відмову в доступі до каталогів, куди звичайний користувач зазирнути не може, і залишає у виводі лише корисний результат.

### Крок 4. Посилання

```bash
student@lab-vm:~/lab7$ ln src/hosts docs/hosts-hard
student@lab-vm:~/lab7$ ln -s ../src/hosts docs/hosts-soft
student@lab-vm:~/lab7$ ls -l docs/
-rw-r--r-- 2 student student 221 вер 18 10:12 hosts-hard
lrwxrwxrwx 1 student student  12 вер 18 10:20 hosts-soft -> ../src/hosts

student@lab-vm:~/lab7$ stat -c "%i %n" src/hosts docs/hosts-hard docs/hosts-soft
1443521 src/hosts
1443521 docs/hosts-hard
1443902 docs/hosts-soft

student@lab-vm:~/lab7$ rm src/hosts
student@lab-vm:~/lab7$ cat docs/hosts-hard | head -2
127.0.0.1	localhost
127.0.1.1	lab-vm

student@lab-vm:~/lab7$ cat docs/hosts-soft
cat: docs/hosts-soft: No such file or directory
```

Число `2` у виводі `ls -l` для `hosts-hard` — це кількість імен, що вказують на inode. Після видалення оригіналу жорстке посилання лишається робочим, а символічне «повисає»: воно зберігало лише шлях.

### Крок 5. Монтування носія

```bash
student@lab-vm:~/lab7$ lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   25G  0 disk
├─sda1   8:1    0    1G  0 part /boot/efi
└─sda2   8:2    0   24G  0 part /
sdb      8:16   1  7,5G  0 disk
└─sdb1   8:17   1  7,5G  0 part

student@lab-vm:~/lab7$ sudo blkid /dev/sdb1
/dev/sdb1: UUID="A1B2-C3D4" TYPE="vfat"

student@lab-vm:~/lab7$ sudo mount /dev/sdb1 ~/lab7/mnt
student@lab-vm:~/lab7$ df -hT ~/lab7/mnt
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/sdb1      vfat  7,5G  1,2G  6,3G  16% /home/student/lab7/mnt

student@lab-vm:~/lab7$ sudo umount ~/lab7/mnt
student@lab-vm:~/lab7$ findmnt ~/lab7/mnt
student@lab-vm:~/lab7$ echo $?
1
```

Порожній вивід `findmnt` і код повернення 1 підтверджують, що носій відмонтовано і його можна безпечно вилучити.

```bash
student@lab-vm:~/lab7$ du -h --max-depth=1 ~/lab7 | sort -h

4,0K	/home/student/lab7/mnt
28K	/home/student/lab7/docs
32K	/home/student/lab7/src

student@lab-vm:~/lab7$ tar -czvf bak/lab7-$(date +%F).tar.gz src docs

student@lab-vm:~/lab7$ ls -lh bak/
```

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Створити в домашньому каталозі структуру `~/lab7` з підкаталогами `src`, `docs`, `bak`, `mnt`. Скопіювати в `src` три файли з каталогу, зазначеного у варіанті.

3. Вивести метадані одного з файлів командою `stat` і пояснити призначення полів Inode, Links, Access. Визначити реальний тип трьох файлів командою `file`.

4. Виконати чотири різні пошуки: за іменем, за розміром, за часом зміни та за вмістом. Критерій пошуку за розміром узяти з варіанта. Навести використані команди з ключами.

5. Створити жорстке й символічне посилання на один файл. Порівняти номери inode. Видалити оригінал і показати, що сталося з кожним посиланням. Пояснити результат.

6. Виконати операції копіювання, переміщення та перейменування згідно з варіантом. Показати, чим `cp -p` відрізняється від звичайного `cp`.

7. Змонтувати носій, зазначений викладачем, у каталог `~/lab7/mnt`. Визначити тип файлової системи, UUID і обсяг вільного місця. Скопіювати на носій файл, після чого коректно відмонтувати й підтвердити це командою `findmnt`.

8. Проаналізувати дисковий простір: знайти п'ять найбільших підкаталогів каталогу, зазначеного у варіанті. Пояснити різницю між `df -h` і `df -i`.

9. Створити архів каталогів `src` і `docs` у форматі свого варіанта, переглянути вміст архіву без розпакування та розпакувати його до `/tmp`. Порівняти обсяг архіву й вихідних даних.

10. Виконати додаткове завдання свого варіанта.

11. Оформити звіт і зробити висновок.

| 13 | `/etc/pam.d` | файли з іменем із 4 символів | `tar.xz` | Порівняти час архівування gzip і xz |
| 14 | `/usr/lib/systemd/system` | файли `.service` | `tar.gz` | Знайти службу за словом в описі та пояснити спосіб пошуку |
| 15 | `/etc/udev` | усі каталоги | `zip` | Пояснити, що станеться, якщо відмонтувати зайнятий носій |
| 16 | `/usr/share/man/man1` | файли більші за 2 КБ | `tar.gz` | Пояснити, як влаштована нумерація розділів man |
| 17 | `/etc/logrotate.d` | файли, змінені за місяць | `tar.bz2` | Знайти найбільший файл у домашньому каталозі двома способами |
| 18 | `/boot` | файли більші за 1 МБ | `tar.gz` | Пояснити, чому `/boot` часто виносять в окремий розділ |
| 19 | `/etc/init.d` | виконувані файли | `zip` | Пояснити зв'язок між `/etc/init.d` і systemd |
| 20 | `/usr/games` або `/usr/bin` | файли з правом виконання для всіх | `tar.gz` | Пояснити, чому вичерпання inode блокує запис попри вільне місце |

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Чим організація файлової системи Linux відрізняється від Windows?
2. Що таке точка монтування?
3. Які команди створюють, копіюють, переміщують і видаляють файли?
4. Як у Linux позначається прихований файл?
5. Чим `find` відрізняється від `locate`?
6. Що таке inode?
7. Якою командою створюють символічне посилання?
8. Що робить команда `tar` і що робить `gzip`?

### Достатній рівень (конструктивно-варіативний)

1. Чому `mv` виконує і переміщення, і перейменування? Що відбувається у файловій системі в кожному випадку?
2. Запишіть команду, яка знайде в `/var/log` усі файли більші за 1 МБ, змінені за останню добу.
3. Чим жорстке посилання відрізняється від символічного? Наведіть задачу, де потрібне саме символічне.
4. Чому після видалення оригіналу жорстке посилання працює, а символічне — ні?
5. Чому в `/etc/fstab` носії позначають UUID, а не іменем `/dev/sdb1`?
6. Що робити, якщо `umount` повідомляє «target is busy»?
7. Чому `df -h` може показувати вільне місце, коли система повідомляє про його брак?
8. Поясніть подвійне розширення `.tar.gz` і запишіть команду перегляду вмісту такого архіву.

### Високий рівень (творчий)

1. Поясніть, які переваги для адміністрування дає єдине дерево каталогів із монтуванням, і наведіть сценарій, неможливий у моделі з літерами дисків.
2. Каталог із журналами заповнив увесь розділ. Опишіть послідовність дій із зазначенням команд на кожному кроці й поясніть, чому просте видалення файлу відкритим процесом не звільняє місце.
3. Запропонуйте схему резервного копіювання домашнього каталогу з кількома поколіннями копій. Обґрунтуйте вибір формату архіву та періодичність.
4. Сформулюйте критерії вибору між жорстким посиланням, символічним посиланням і копією файлу. Проілюструйте кожен критерій прикладом із цієї роботи.

## Теоретичні відомості

### 1 Windows як гібридна операційна система

Windows побудована на ядрі NT, яке належить до гібридної архітектури: більшість підсистем виконується в режимі ядра одним великим модулем, як у монолітному ядрі, але при цьому зберігається чіткий поділ на менеджери з визначеними інтерфейсами, характерний для мікроядра.

Основний файл ядра — `ntoskrnl.exe` у каталозі `%SystemRoot%\System32`; нижче нього працює HAL (`hal.dll`), рівень абстракції від апаратури.

**Практичний наслідок такої побудови:** драйвери пристроїв виконуються в режимі ядра й мають ті самі привілеї, що й саме ядро. Саме тому помилка драйвера призводить не до аварійного завершення окремої програми, а до зупинки всієї системи (BSOD).

### 2 Процеси та їх спостереження

Процес — це програма в стані виконання разом із виділеними їй ресурсами: адресним простором, дескрипторами відкритих файлів, потоками виконання. Кожен процес має унікальний числовий ідентифікатор PID.

У Windows перелік процесів доступний трьома способами:

- Через Диспетчер завдань (вкладка «Подробиці»)
- Командою `tasklist` у CMD
- Командлетом `Get-Process` у PowerShell

Процес із PID 4 має ім'я System — це не звичайна програма, а контейнер для потоків самого ядра. Процес Idle з PID 0 показує частку простою процесора.

### 3 Режими роботи процесора у Windows

Код виконується або в режимі користувача (user mode, кільце 3), або в режимі ядра (kernel mode, кільце 0). Прикладні програми не можуть безпосередньо звертатися до апаратури: щоб прочитати файл або відкрити мережеве з'єднання, вони виконують системний виклик, який тимчасово переводить процесор у режим ядра.

Цей поділ можна побачити на власні очі. У Диспетчері завдань на вкладці «Продуктивність» слід вибрати ЦП, клацнути правою кнопкою на графіку і ввімкнути «Показати час ядра» (Show kernel times). На графіку з'явиться друга, темніша лінія: вона показує частку часу, проведену процесором у режимі ядра.

### 4 Командний режим: CMD, PowerShell, Windows Terminal

У Windows співіснують два інтерпретатори команд:

- **CMD** (`cmd.exe`) — спадкоємець командного процесора MS-DOS; працює з текстом, команди короткі, синтаксис ключів через скісну риску
- **PowerShell** — сучасна оболонка, побудована на .NET; її команди (командлети) мають вигляд «Дієслово-Іменник» і передають по конвеєру не текст, а об'єкти

Windows Terminal об'єднує CMD, PowerShell і, за наявності, WSL в одному вікні з вкладками.

**Запуск:** `Win+R` → `cmd` або `powershell`; `Win+X` → Terminal. Комбінація `Ctrl+Shift+Enter` замість Enter запускає оболонку з правами адміністратора.

|-------------|-----|------------|

### 5 Змінні середовища

Змінна середовища — іменоване значення, доступне всім програмам сеансу. Найважливіша з них — `PATH`: це список каталогів, у яких система шукає виконуваний файл.

Змінні поділяються на:

- **Системні:** `COMPUTERNAME`, `OS`, `SystemRoot`, `windir`
- **Користувацькі:** `USERPROFILE`, `APPDATA`, `TEMP`

У CMD значення підставляється відсотками: `echo %TEMP%`; повний перелік дає команда `set`.

У PowerShell використовується префікс `$env:` — наприклад, `$env:TEMP`, а перелік усіх змінних дає `Get-ChildItem env:`.

### 6 Про мову інтерфейсу

Команда `systeminfo` виводить назви полів мовою інтерфейсу системи. На англомовній Windows це рядки `OS Name` і `OS Version`, на україномовній — «Назва ОС» і «Версія ОС».

Тому фільтр виду `systeminfo | findstr /c:"OS Name"` на локалізованій системі нічого не знайде: потрібно підставити назву поля своєю мовою або скористатися командою `systeminfo` без фільтра.

## Приклад виконання

Нижче наведено послідовність дій для довільної системи. Конкретні значення (версія збірки, імена користувача та комп'ютера, перелік процесів) на вашій машині будуть іншими — це нормально, у звіт вносяться саме ваші результати.

### Крок 1. Визначення конфігурації системи

```cmd
C:\Users\Student> ver
Microsoft Windows [Version 10.0.22631.4460]

C:\Users\Student> hostname
LAB-PC-14

C:\Users\Student> whoami
lab-pc-14\student

C:\Users\Student> systeminfo | findstr /c:"OS Name" /c:"OS Version" /c:"System Type"
OS Name:                   Microsoft Windows 11 Pro
OS Version:                10.0.22631 N/A Build 22631
System Type:               x64-based PC
```

У номері `10.0.22631.4460`:

- Перші дві частини — версія ядра NT (вона залишилася 10.0 і у Windows 11)
- `22631` — номер збірки, за яким і визначають реальну версію системи
- `4460` — номер оновлення

### Крок 2. Змінні середовища

```cmd
C:\Users\Student> echo %USERPROFILE%
C:\Users\Student

C:\Users\Student> echo %SystemRoot%
C:\WINDOWS

C:\Users\Student> set | find /c "="
58
```

### Крок 3. Файлові операції

```cmd
C:\Users\Student> cd %USERPROFILE%\Desktop
C:\Users\Student\Desktop> md LAB1\src LAB1\docs LAB1\logs
C:\Users\Student\Desktop> cd LAB1

C:\...\LAB1> echo Lab work 1, OS course > docs\readme.txt
C:\...\LAB1> systeminfo > logs\system.txt
C:\...\LAB1> attrib +h logs\system.txt

C:\...\LAB1> dir
 <DIR>          docs
 <DIR>          logs
 <DIR>          src

C:\...\LAB1> dir /a:h /s system.txt

C:\...\LAB1> tree /f
LAB1
├───docs
│       readme.txt
├───logs
│       system.txt
└───src
```

Каталог `logs` у звичайному виводі `dir` видно, а файл `system.txt` усередині — ні: атрибут `+h` приховав його. Показати такі файли можна ключем `/a:h`.

### Крок 4. Процеси

```cmd
C:\...\LAB1> tasklist | findstr /i "notepad"
notepad.exe                   8124 Console                    1     14 236 KB

C:\...\LAB1> taskkill /pid 8124
SUCCESS: Sent termination signal to the process with PID 8124.
```

```powershell
PS C:\...\LAB1> Get-Process | Sort-Object WorkingSet -Descending |
>> Select-Object -First 5 Name, @{N='MB';E={[math]::Round($_.WorkingSet/1MB)}}

Name                 MB
----                 --
Memory Compression  612
chrome              488
Code                351
explorer            142
SearchHost           98
```

Той самий перелік у CMD довелося б сортувати вручну: `tasklist` віддає текст, тоді як `Get-Process` передає по конвеєру об'єкти, у яких є числова властивість `WorkingSet`. Це і є практична різниця між двома оболонками.

### Крок 5. Спостереження за режимами роботи процесора

1. Відкрити Диспетчер завдань (`Ctrl+Shift+Esc`)
2. Перейти на вкладку «Продуктивність»
3. Вибрати ЦП
4. Клацнути правою кнопкою на графіку та ввімкнути «Показати час ядра»

Далі виконати команду, яка створює інтенсивне навантаження на диск:

```cmd
C:\...\LAB1> dir C:\Windows /s > logs\allfiles.txt
```

Під час виконання темна лінія на графіку піднімається: процесор витрачає помітну частку часу в режимі ядра, обслуговуючи системні виклики читання каталогів. Після завершення команди лінія повертається до попереднього рівня.

**Зафіксувати обидва стани знімками екрана.**

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Визначити конфігурацію робочої станції: версію та збірку Windows, розрядність, ім'я комп'ютера, ім'я користувача та групи, до яких він належить, обсяг оперативної пам'яті. Скористатися командами `ver`, `hostname`, `whoami`, `whoami /groups`, `systeminfo`. Окремо перевірити, якою мовою виводяться назви полів `systeminfo` на вашій машині, і за потреби скоригувати фільтр `findstr`.

3. Знайти й записати значення параметра системи, зазначеного у вашому варіанті. Навести команду, якою його отримано.

4. Вивести значення змінних середовища `USERPROFILE`, `SystemRoot`, `TEMP`, `PATH`. Визначити, скільки каталогів містить `PATH`. Пояснити, для чого система переглядає цей список.

5. Створити на робочому столі структуру каталогів згідно з варіантом. Наповнити її файлами, виконати операції копіювання, перейменування та зміни атрибутів, передбачені варіантом. Зафіксувати результат командою `tree /f`.

6. Отримати перелік процесів двома способами — командою `tasklist` і командлетом `Get-Process`. Знайти процес, зазначений у варіанті, визначити його PID та обсяг зайнятої пам'яті, після чого коректно завершити його.

7. Порівняти вивід `tasklist` і `Get-Process` для одного й того самого процесу. Пояснити, у чому полягає різниця між текстовим і об'єктним конвеєром.

8. Виконати спостереження за часом ядра згідно з кроком 5 прикладу. Зробити два знімки екрана — у стані спокою та під навантаженням — і пояснити спостережувану різницю через поняття системного виклику.

9. Виконати додаткове завдання свого варіанта.

10. Оформити звіт і зробити висновок.

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Що таке операційна система? Назвіть п'ять її основних функцій.
2. Що таке ядро ОС і до якої архітектури належить ядро Windows NT?
3. Що таке процес і чим він відрізняється від програми? Що таке PID?
4. Які процеси мають PID 0 і PID 4?
5. Що таке режим користувача та режим ядра?
6. Що таке системний виклик? Наведіть приклад дії користувача, яка його спричиняє.
7. Що таке змінна середовища? Для чого система використовує змінну PATH?
8. Якими командами визначають версію, ім'я комп'ютера та ім'я користувача?

### Достатній рівень (конструктивно-варіативний)

1. Чим гібридне ядро Windows NT відрізняється від монолітного та від мікроядра?
2. Чому процеси з PID 0 і PID 4 не можна завершити звичайним способом?
3. Чому прикладна програма не може безпосередньо звернутися до диска?
4. Як побачити частку часу, проведену процесором у режимі ядра? За яких дій вона зростає і чому?
5. Чим CMD відрізняється від PowerShell? Що передається по конвеєру в кожному з них?
6. Чим команда set відрізняється від setx?
7. Як вивести приховані файли в CMD? Якою командою встановлюють і знімають атрибут «прихований»?
8. Запишіть команду, яка виведе з systeminfo лише рядки про версію та розрядність системи.

### Високий рівень (творчий)

1. Що показує номер збірки Windows і чим він корисніший за назву версії? Поясніть на прикладі власної системи.
2. Поясніть, чому помилка драйвера призводить до зупинки всієї системи, а помилка прикладної програми — ні.
3. Ви отримали два різні значення кількості процесів від tasklist і Get-Process. Назвіть можливі причини розбіжності та спосіб перевірки кожної.
4. Сформулюйте, чому майже будь-яка дія користувача врешті-решт зводиться до системного виклику. Проілюструйте ланцюжком «дія → підсистема → ядро».

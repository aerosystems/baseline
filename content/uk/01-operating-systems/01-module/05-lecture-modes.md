## Чому програма не може форматувати диск без дозволу?

Уявіть ситуацію: ви завантажили гру з інтернету, запустили її, а вона тихо видалила всі файли на диску. Або вірус отримав доступ до вашої веб-камери без вашого відома. Як операційна система захищає від таких сценаріїв?

Відповідь — **апаратне розділення привілеїв**. Процесор фізично не дозволяє звичайним програмам виконувати небезпечні операції.

## Кільця захисту процесора (Protection Rings)

Сучасні процесори x86/x64 мають 4 рівні привілеїв, але більшість ОС використовують лише два:

```
┌─────────────────────────────────────────────────────────────────┐
│                    КІЛЬЦЯ ЗАХИСТУ x86                           │
│                                                                 │
│                    ┌───────────────────┐                       │
│                    │     Ring 3        │  ← User Mode          │
│                    │   (Найменше      │     Звичайні програми  │
│                    │    привілеїв)    │     Браузер, Word...   │
│                    │  ┌─────────────┐  │                       │
│                    │  │   Ring 2    │  │  ← Не використ.       │
│                    │  │ ┌─────────┐ │  │                       │
│                    │  │ │ Ring 1  │ │  │  ← Не використ.       │
│                    │  │ │ ┌─────┐ │ │  │                       │
│                    │  │ │ │ R 0 │ │ │  │  ← Kernel Mode        │
│                    │  │ │ │     │ │ │  │     Ядро ОС           │
│                    │  │ │ └─────┘ │ │  │     Повний доступ     │
│                    │  │ └─────────┘ │  │                       │
│                    │  └─────────────┘  │                       │
│                    └───────────────────┘                       │
│                                                                 │
│   Ring 0: Kernel Mode — повний доступ до заліза                │
│   Ring 3: User Mode — обмежений доступ                         │
│   Ring 1, 2: Зарезервовані (використ. для віртуалізації)       │
└─────────────────────────────────────────────────────────────────┘
```

## User Mode vs Kernel Mode

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   USER MODE (Ring 3)              KERNEL MODE (Ring 0)         │
│   ══════════════════              ═══════════════════          │
│                                                                 │
│   ✅ Доступ до власної           ✅ Доступ до ВСІЄЇ пам'яті    │
│      пам'яті процесу                                           │
│                                   ✅ Виконання БУДЬ-ЯКИХ       │
│   ❌ Доступ до пам'яті              інструкцій CPU             │
│      інших процесів                                            │
│                                   ✅ Пряма робота з            │
│   ❌ Привілейовані                  пристроями (I/O ports)     │
│      інструкції CPU                                            │
│                                   ✅ Керування перериваннями   │
│   ❌ Прямий доступ до                                          │
│      пристроїв                   ✅ Зміна таблиць сторінок     │
│                                     (віртуальна пам'ять)       │
│   ❌ Зміна системних                                           │
│      структур                                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Що відбувається при порушенні?

```
┌─────────────────────────────────────────────────────────────────┐
│                    ПОРУШЕННЯ ПРИВІЛЕЇВ                          │
│                                                                 │
│   User Mode програма намагається:                               │
│                                                                 │
│   1. Прочитати пам'ять ядра                                    │
│      ──────────────────────────────────────────────────────    │
│      → CPU генерує General Protection Fault (#GP)              │
│      → ОС завершує процес: "Segmentation fault"                │
│                                                                 │
│   2. Виконати привілейовану інструкцію (напр. CLI)            │
│      ──────────────────────────────────────────────────────    │
│      → CPU генерує #GP                                         │
│      → ОС завершує процес                                      │
│                                                                 │
│   3. Звернутися до I/O порту (напр. диск)                     │
│      ──────────────────────────────────────────────────────    │
│      → CPU генерує #GP                                         │
│      → ОС завершує процес                                      │
│                                                                 │
│   Це АПАРАТНИЙ захист — ОС не може його обійти навіть якби     │
│   хотіла. Процесор фізично не виконує заборонені інструкції.   │
└─────────────────────────────────────────────────────────────────┘
```

**Практичний приклад:**

```bash
# Спроба прочитати пам'ять ядра
sudo cat /proc/kcore | head -c 100
# Працює тільки з sudo (root має доступ до kernel space)

# Без sudo:
cat /proc/kcore
# cat: /proc/kcore: Permission denied

# Подивитися, в якому режимі працює процес
cat /proc/self/status | grep -i "seccomp\|cap"
```

## Перехід між режимами

Єдиний легальний спосіб перейти з User Mode в Kernel Mode — через **системний виклик**.

```
┌─────────────────────────────────────────────────────────────────┐
│                    ПЕРЕХІД USER → KERNEL                        │
│                                                                 │
│   User Mode                                                     │
│   ┌────────────────────────────────────┐                       │
│   │  Програма: printf("Hello");        │                       │
│   │            ↓                        │                       │
│   │  libc: write(1, "Hello", 5);       │                       │
│   │            ↓                        │                       │
│   │  Інструкція: SYSCALL (x86-64)      │                       │
│   │              або INT 0x80 (x86)    │                       │
│   └──────────────┬─────────────────────┘                       │
│                  │                                              │
│   ═══════════════╪══════════════════════  ← Межа режимів       │
│                  │                                              │
│   Kernel Mode    ↓                                              │
│   ┌────────────────────────────────────┐                       │
│   │  1. CPU зберігає стан (регістри)   │                       │
│   │  2. Перемикає Ring 3 → Ring 0      │                       │
│   │  3. Переходить до sys_write()      │                       │
│   │  4. Ядро пише в stdout             │                       │
│   │  5. Відновлює стан                 │                       │
│   │  6. SYSRET — назад в Ring 3        │                       │
│   └────────────────────────────────────┘                       │
│                                                                 │
│   Час перемикання: 100-1000 наносекунд                         │
└─────────────────────────────────────────────────────────────────┘
```

**Практичний приклад — відстеження системних викликів:**

```bash
# Подивитися syscalls простої команди
strace -c ls /tmp 2>&1 | tail -20

# Приклад виводу:
# % time     seconds  usecs/call     calls    errors syscall
# ------ ----------- ----------- --------- --------- ----------------
#  25.00    0.000050          12         4           openat
#  20.00    0.000040          10         4           read
#  15.00    0.000030           7         4           close
#  ...

# Кожен виклик — це перехід User→Kernel→User
```

### 1. Планувальник процесів (Process Scheduler)

**Завдання:** Вирішує, який процес виконуватиметься наступним.

```
┌─────────────────────────────────────────────────────────────────┐
│                    ПЛАНУВАЛЬНИК CFS (Linux)                     │
│                                                                 │
│   Completely Fair Scheduler — "повністю справедливий"           │
│                                                                 │
│   Процеси в черзі за часом виконання:                          │
│                                                                 │
│      vruntime (віртуальний час)                                │
│      ┌───┐ ┌───┐ ┌───┐ ┌───┐ ┌───┐                            │
│      │ A │ │ B │ │ C │ │ D │ │ E │                            │
│      │ 5 │ │ 8 │ │12 │ │15 │ │20 │  мс                        │
│      └───┘ └───┘ └───┘ └───┘ └───┘                            │
│        ▲                                                        │
│        │                                                        │
│        └── Наступний для виконання                             │
│            (найменший vruntime)                                │
│                                                                 │
│   Red-Black Tree для O(log n) пошуку                           │
└─────────────────────────────────────────────────────────────────┘
```

**Практичні команди:**

```bash
# Подивитися пріоритети процесів
ps -eo pid,ni,pri,comm | head -20

# Змінити пріоритет (nice value: -20 до +19)
nice -n 10 ./heavy_task    # Знизити пріоритет
sudo nice -n -10 ./important_task  # Підвищити пріоритет

# Real-time політики
chrt -f 50 ./realtime_task  # FIFO з пріоритетом 50
chrt -r 50 ./realtime_task  # Round-robin

# Статистика планувальника
cat /proc/schedstat | head -5
```

### 2. Менеджер пам'яті (Memory Manager)

**Завдання:** Розподіляє RAM між процесами, забезпечує ізоляцію.

```
┌─────────────────────────────────────────────────────────────────┐
│                    ВІРТУАЛЬНА ПАМ'ЯТЬ                           │
│                                                                 │
│   Процес A                        Процес B                      │
│   ┌─────────────────┐             ┌─────────────────┐          │
│   │ Virtual: 0x1000 │             │ Virtual: 0x1000 │          │
│   └────────┬────────┘             └────────┬────────┘          │
│            │                               │                    │
│            │    Page Table A               │    Page Table B    │
│            ▼                               ▼                    │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                    MMU (Memory Management Unit)          │  │
│   │                    Апаратна трансляція адрес             │  │
│   └─────────────────────────────────────────────────────────┘  │
│            │                               │                    │
│            ▼                               ▼                    │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                    ФІЗИЧНА ПАМ'ЯТЬ (RAM)                │  │
│   │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐         │  │
│   │  │ 0x10 │ │ 0x20 │ │ 0x30 │ │ 0x40 │ │ 0x50 │         │  │
│   │  │  A   │ │  B   │ │ kernel│ │  A   │ │  B   │         │  │
│   │  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘         │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│   Однакові віртуальні адреси → різні фізичні адреси            │
│   Процеси не можуть побачити пам'ять один одного               │
└─────────────────────────────────────────────────────────────────┘
```

**Практичні команди:**

```bash
# Карта пам'яті процесу
cat /proc/self/maps

# Використання пам'яті
free -h

# Детальна інформація
cat /proc/meminfo | head -20

# OOM Killer — хто буде "вбитий" при нестачі RAM
cat /proc/*/oom_score | sort -rn | head -5
```

```bash
# формат: allocated  free  max
```

```bash
# Capabilities процесу

capsh --decode=0000000000000000
```

## Порівняння режимів

| Характеристика | User Mode | Kernel Mode |
|----------------|-----------|-------------|
| **Ring** | 3 | 0 |
| **Доступ до пам'яті** | Тільки своя | Вся RAM |
| **I/O операції** | Через syscall | Прямий доступ |
| **Привілейовані інструкції** | Заборонено | Дозволено |
| **Наслідки помилки** | Crash процесу | Kernel panic |
| **Приклади коду** | Браузер, редактор | Драйвери, VFS |

Дослідіть режими роботи на вашій системі:

```bash

# 2. Подивіться час у kernel mode vs user mode

# 3. Перегляньте завантажені модулі ядра
```

## Підсумок

| Компонент | Функція | Приклад |
|-----------|---------|---------|
| **Protection Rings** | Апаратна ізоляція привілеїв | Ring 0 (kernel), Ring 3 (user) |
| **Scheduler** | Розподіл CPU між процесами | CFS, FIFO, Round-Robin |
| **Memory Manager** | Віртуальна пам'ять, ізоляція | Paging, Swapping, OOM |
| **VFS** | Єдиний інтерфейс до ФС | ext4, XFS, NFS через один API |
| **Network Stack** | Мережеві протоколи | TCP/IP, sockets |
| **LSM** | Обов'язковий контроль доступу | SELinux, AppArmor |

**Ключовий висновок:** Розділення на User Mode та Kernel Mode — це не просто програмна концепція, а **апаратний механізм безпеки**. Процесор фізично блокує небезпечні операції, і жодна програма не може це обійти.

На наступній лекції детально розглянемо архітектури ядер ОС: монолітне, мікроядро та гібридне.

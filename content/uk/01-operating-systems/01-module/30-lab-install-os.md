**Мета:** навчитися готувати носій і віртуальну машину до встановлення операційної системи, свідомо обирати схему завантаження та розмітку диска, виконувати інсталяцію й первинне налаштування, а також перевіряти результат засобами самої системи.

**Обладнання:** ПК або віртуальна машина (VirtualBox, Hyper-V, QEMU); інсталяційний образ Ubuntu 22.04+ або Windows 10/11; утиліта запису образу на носій; щонайменше 25 ГБ вільного місця й 4 ГБ оперативної пам'яті для гостьової системи.

**Тривалість:** 4 академічні години (2 заняття).

**УВАГА. Розмітка диска знищує дані. Усі дії цієї роботи виконуються ВИКЛЮЧНО у віртуальній машині з окремим віртуальним диском. Категорично заборонено запускати інсталятор на фізичному комп'ютері аудиторії, змінювати розділи носія, з якого завантажено робочу систему, та виконувати запис образу на диск викладача. Перед початком переконайтеся, що в інсталяторі обрано саме віртуальний диск.**

## Теоретичні відомості

### 1 Дві схеми завантаження

Спосіб, у який мікропрограма материнської плати знаходить і запускає
завантажувач, визначає й допустиму розмітку диска.

Таблиця 1 — Порівняння схем завантаження

| Ознака | BIOS + MBR | UEFI + GPT |
|--------|------------|------------|
| Де лежить завантажувач | у першому секторі диска (446 байтів коду) | у файлі на розділі EFI |
| Максимальний розмір диска | 2 ТБ | 9,4 ЗБ (практично без обмежень) |
| Кількість основних розділів | 4 (більше — через розширений) | 128 і більше |
| Резервна копія таблиці | немає | є, у кінці диска |
| Перевірка підпису завантажувача | немає | Secure Boot |
| Статус | застаріла | стандарт із 2010-х |

Головний практичний висновок: на UEFI-системі потрібен окремий розділ EFI
(ESP) з файловою системою FAT32, і без нього система не завантажиться, навіть
якщо інсталяція формально завершилася.

### 2 Розмітка диска

Розмітка — це поділ фізичного носія на логічні частини з окремими файловими
системами. Мінімальна робоча схема для Linux на UEFI:

Таблиця 2 — Типова схема розмітки диска 25 ГБ

| Розділ | Розмір | Файлова система | Точка монтування | Призначення |
|--------|--------|-----------------|------------------|-------------|
| EFI (ESP) | 512 МБ | FAT32 | `/boot/efi` | завантажувач |
| Кореневий | 15 ГБ | ext4 | `/` | система й програми |
| Домашній | решта | ext4 | `/home` | дані користувача |
| Підкачка | 2 ГБ | swap | — | вивантаження сторінок |

**Навіщо окремий `/home`.** При перевстановленні системи кореневий розділ
форматують, а домашній лишають — дані користувача переживають зміну версії або
навіть дистрибутива. Зворотний бік: розмір розділів фіксується наперед, і
помилка в оцінці виправляється лише зміною розмітки.

### 3 Файлові системи

Таблиця 3 — Поширені файлові системи

| Система | Де застосовують | Особливості |
|---------|-----------------|-------------|
| ext4 | типовий вибір для Linux | журналювання, стабільність, простота |
| Btrfs | Linux, де потрібні знімки | знімки стану, стиснення, перевірка цілісності |
| XFS | великі файли, сервери | добре працює з великими обсягами |
| NTFS | Windows | журналювання, ACL, стиснення |
| FAT32 | розділ EFI, змінні носії | читає будь-яка система, файл до 4 ГБ |

### 4 Етапи інсталяції

```
1. Завантаження з носія    → вибір режиму (UEFI чи Legacy) у меню
2. Мова, розкладка, часовий пояс
3. Тип встановлення         → розмітка: автоматична чи ручна
4. Копіювання файлів        → розпакування образу на розділ
5. Встановлення завантажувача → у ESP (UEFI) або MBR (BIOS)
6. Створення користувача    → ім'я, пароль, назва комп'ютера
7. Перезавантаження         → від'єднати образ, інакше інсталятор
                              запуститься знову
```

### 5 Первинне налаштування

Після першого входу система ще не готова до роботи. Обов'язковий мінімум:

- оновлення переліку пакетів і самих пакетів;
- перевірка мережі й часу;
- встановлення доповнень гостьової ОС (для віртуальної машини);
- перевірка розмітки й вільного місця;
- створення знімка стану (для віртуальної машини) — точка повернення.

## Приклад виконання

### Крок 1. Створення віртуальної машини

Параметри для Ubuntu: 2 ядра, 4096 МБ пам'яті, диск 25 ГБ, тип завантаження
UEFI, мережа NAT.

```bash
# Той самий результат командою (VirtualBox)
VBoxManage createvm --name "lab11-ubuntu" --ostype Ubuntu_64 --register
VBoxManage modifyvm "lab11-ubuntu" --memory 4096 --cpus 2 --firmware efi
VBoxManage createhd --filename "lab11-ubuntu.vdi" --size 25600
VBoxManage storagectl "lab11-ubuntu" --name "SATA" --add sata
VBoxManage storageattach "lab11-ubuntu" --storagectl "SATA" --port 0 \
  --device 0 --type hdd --medium "lab11-ubuntu.vdi"
```

Перевірка створеної машини:

```bash
VBoxManage showvminfo "lab11-ubuntu" | grep -E "Memory size|Firmware|Number of CPUs"
```

Вивід:

```
Memory size:     4096MB
Number of CPUs:  2
Firmware:        EFI
```

### Крок 2. Ручна розмітка диска

В інсталяторі оберіть «Something else» (ручна розмітка) і створіть чотири
розділи за таблицею 2. Після встановлення перевірте результат:

```bash
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT
```

Вивід:

```
NAME   SIZE FSTYPE MOUNTPOINT
sda     25G
├─sda1  512M vfat   /boot/efi
├─sda2   15G ext4   /
├─sda3  7.5G ext4   /home
└─sda4    2G swap   [SWAP]
```

### Крок 3. Перевірка схеми завантаження

```bash
# Якщо каталог існує — система завантажена в режимі UEFI
ls /sys/firmware/efi > /dev/null 2>&1 && echo "UEFI" || echo "Legacy BIOS"

# Таблиця розділів: gpt чи dos
sudo fdisk -l /dev/sda | grep "Disklabel type"
```

Вивід:

```
UEFI
Disklabel type: gpt
```

Розбіжність між цими двома відповідями — типова помилка: система, встановлена
в режимі Legacy на диск GPT, або не завантажиться, або завантажиться лише з
конкретного меню.

### Крок 4. Первинне налаштування

```bash
# Оновлення переліку пакетів і самих пакетів
sudo apt update && sudo apt upgrade -y

# Часовий пояс і синхронізація часу
timedatectl set-timezone Europe/Kyiv
timedatectl status | head -4

# Перевірка мережі
ip -brief address
ping -c 2 8.8.8.8
```

### Крок 5. Підсумкова перевірка системи

```bash
# Версія системи та ядра
cat /etc/os-release | grep PRETTY_NAME
uname -r

# Вільне місце на розділах
df -h --output=source,size,used,avail,pcent,target | grep -E "^/dev"

# Підкачка активна?
swapon --show

# Скільки часу тривало завантаження системи
systemd-analyze
```

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.
2. Створити віртуальну машину з параметрами свого варіанта.
3. Під'єднати інсталяційний образ і завантажитися з нього у вказаному режимі
   (UEFI або Legacy).
4. Виконати **ручну** розмітку диска за схемою свого варіанта.
5. Встановити систему, створити користувача з іменем за варіантом.
6. Від'єднати образ і перезавантажитися в установлену систему.
7. Виконати первинне налаштування: оновлення, часовий пояс, перевірка мережі.
8. Виконати підсумкову перевірку (крок 5) і зберегти знімки екрана.
9. Створити знімок стану віртуальної машини з назвою `after-install`.
10. Оформити звіт і зробити висновок.

## Вимоги до звіту

Звіт оформлюється на бланку встановленого зразка і має містити:

- тему, мету та обладнання;
- параметри віртуальної машини за індивідуальним варіантом;
- таблицю розмітки: розділ, розмір, файлова система, точка монтування;
- знімки екрана: вікно розмітки, завершення інсталяції, вивід команд перевірки;
- перелік виконаних команд первинного налаштування з поясненням кожної;
- відповіді на контрольні запитання свого рівня;
- висновок за результатами роботи.

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Чим схема UEFI + GPT відрізняється від BIOS + MBR?
2. Яка файлова система має бути на розділі EFI і чому саме вона?
3. Скільки основних розділів допускає таблиця MBR?
4. Які чотири розділи входять до типової схеми розмітки Linux?
5. Для чого призначений розділ підкачки?
6. Якою командою перевірити перелік розділів і точки монтування?
7. Як визначити, у якому режимі завантажено систему?
8. Які дії входять до первинного налаштування системи?

### Достатній рівень (конструктивно-варіативний)

1. Навіщо виносити `/home` на окремий розділ і в чому недолік такого рішення?
2. Чому система, установлена в режимі Legacy на диск GPT, може не завантажитися?
3. Що станеться, якщо після інсталяції не від'єднати інсталяційний образ?
4. Чому розділ EFI має бути саме FAT32, а не ext4?
5. Поясніть, чому таблиця GPT зберігає резервну копію в кінці диска.
6. Коли файл підкачки зручніший за окремий розділ підкачки?
7. Чим автоматична розмітка зручна і чим небезпечна?
8. Навіщо створювати знімок стану віртуальної машини одразу після інсталяції?

### Високий рівень (творчий)

1. Спроєктуйте розмітку диска 100 ГБ для навчального комп'ютера, з якого
   щосеместру видаляють дані студентів, але зберігають систему та програми.
   Обґрунтуйте кожен розділ.
2. Поясніть, які саме перевірки виконує Secure Boot і чому наявність цієї
   функції не робить систему захищеною сама собою.
3. Користувач скаржиться: після інсталяції система завантажується лише з меню
   вибору носія. Побудуйте послідовність діагностики й назвіть найімовірнішу
   причину.
4. Порівняйте встановлення системи на фізичний комп'ютер і у віртуальну машину
   за чотирма критеріями: ризик, швидкість, можливість відкату, придатність до
   навчання.

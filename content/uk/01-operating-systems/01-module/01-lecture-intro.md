## Операційні системи навколо нас

Операційні системи оточують нас повсюди:

- **PlayStation 5** працює на модифікованій FreeBSD
- **Tesla Autopilot** керується Linux у реальному часі
- **Android** — це ядро Linux з надбудовою для мобільних пристроїв (3+ млрд пристроїв)
- **macOS та iOS** — нащадки UNIX через NeXTSTEP
- **90% серверів в інтернеті** працюють на Linux
- **100% суперкомп'ютерів** зі списку TOP500 використовують Linux

Навіть смартфон, розумний годинник, роутер, банкомат — усе працює під керуванням операційної системи.

**Запитання до аудиторії**: Скільки пристроїв з ОС ви використали сьогодні до початку лекції?

Знання ОС відкриває двері до:

- **Системного програмування** — драйвери, утиліти, сервери
- **DevOps** — налаштування серверної інфраструктури
- **Кібербезпеки** — розуміння вразливостей на рівні системи
- **Embedded-розробки** — IoT, автомобільні системи

## Що таке операційна система

**Операційна система (ОС)** — це комплекс програм, що керує апаратним забезпеченням комп'ютера та надає сервіси для прикладних програм.

Уявіть ОС як **менеджера готелю**:

- Гості (програми) хочуть користуватися кімнатами (пам'ять), рестораном (процесор), басейном (диск)
- Менеджер (ОС) розподіляє ресурси, щоб усім вистачило
- Гості не знають один про одного і не можуть зайти в чужу кімнату
- Менеджер вирішує конфлікти та забезпечує порядок

ОС виконує дві ключові ролі:

1. **Абстракція** — приховує складність апаратного забезпечення. Замість коду для кожної моделі диска, ви просто відкриваєте файл — ОС подбає про решту.

2. **Арбітраж** — розподіляє обмежені ресурси. Коли 50 програм хочуть процесор одночасно, ОС вирішує, хто отримає час.

## Базові поняття

### Ядро (Kernel)

**Ядро** — серце ОС, програма, яка завжди працює в пам'яті та має повний доступ до апаратного забезпечення.

Коли ви "встановлюєте Linux", ви фактично встановлюєте:

- **Ядро Linux** — один файл (`/boot/vmlinuz`)
- **Системні утиліти GNU** — `ls`, `cp`, `cat`, `grep`, `bash`
- **Графічне середовище** — GNOME, KDE (опціонально)
- **Пакетний менеджер** — apt, dnf, pacman

Технічно "Linux" — це лише ядро. Повна система — GNU/Linux.

### Процес

**Процес** — програма, що виконується. Програма — файл на диску. Процес — активна сутність в пам'яті.

Коли ви запускаєте браузер:

1. ОС створює процес з унікальним PID
2. Виділяє пам'ять для коду та даних
3. Завантажує код з диска
4. Додає в чергу планувальника

```bash
# Подивитися всі процеси
ps aux

# Порахувати кількість процесів
ps aux | wc -l

# Знайти конкретний процес
ps aux | grep firefox
```

Типова система має 200-400 активних процесів одночасно.

### Системний виклик (System Call)

**Системний виклик** — спосіб, яким програма просить ОС виконати привілейовану операцію.

Аналогія: **замовлення в ресторані**. Ви не йдете на кухню самі — робите замовлення через офіціанта, який передає його кухарю.

Приклади системних викликів:

- `open()` — відкрити файл
- `read()` / `write()` — читати / писати дані
- `fork()` — створити новий процес
- `socket()` — працювати з мережею

Linux має понад 400 різних системних викликів.

## Вимоги до сучасних операційних систем

### Надійність

Помилка в одній програмі не повинна "валити" всю систему. Linux-сервери працюють роками без перезавантаження.

### Безпека

Ізоляція процесів, контроль доступу, аутентифікація. Один користувач не може читати файли іншого.

### Ефективність

Мінімальні накладні витрати. Перемикання між процесами — мікросекунди.

### Масштабованість

Linux працює на Raspberry Pi (512 МБ RAM) і на суперкомп'ютері Frontier (9.2 ПБ RAM).

### Портативність

Linux підтримує понад 30 архітектур: x86, ARM, RISC-V та інші.

## П'ять основних функцій ОС

### 1. Керування процесами

ОС відповідає за створення, планування та завершення процесів. **Планувальник** (scheduler) вирішує, який процес виконувати наступним.

```bash
whoami              # Хто я?
ps aux | head -10   # Які процеси працюють?
htop                # Інтерактивний монітор
pstree              # Дерево процесів
```

### 2. Керування пам'яттю

**Віртуальна пам'ять**: кожен процес "думає", що має всю пам'ять. ОС відображає віртуальні адреси на фізичні через MMU.

```bash
free -h                      # Використання пам'яті
cat /proc/meminfo | head -10 # Детальна інформація
ps aux --sort=-%mem | head -5 # Топ споживачів
```

### 3. Керування файловою системою

Популярні файлові системи: ext4 (Linux), NTFS (Windows), APFS (macOS).

```bash
pwd       # Поточний каталог
ls -la    # Вміст каталогу
df -h     # Дисковий простір
```

Концепція UNIX: **"Все є файлом"** — `/dev/sda` (диск), `/dev/null` (чорна діра), `/proc/cpuinfo` (інфо про CPU).

### 4. Керування пристроями

**Драйвери** — модулі ядра для роботи з конкретними пристроями.

```bash
lsblk      # Блочні пристрої
lsusb      # USB-пристрої
lspci      # PCI-пристрої
lsmod      # Завантажені модулі
```

### 5. Забезпечення безпеки

Права доступу для трьох категорій: власник, група, інші. Права: читання (r), запис (w), виконання (x).

```bash
ls -la /etc/passwd  # Права доступу
id                  # Поточний користувач
who                 # Хто в системі
```

Приклад: `-rw-r--r--` означає власник може читати/писати, інші — тільки читати.

## Режими роботи процесора

```
┌───────────────────────────────────────────────────────┐
│                      USER MODE                        │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐   │
│  │ Browser │  │ Editor  │  │  Game   │  │   App   │   │
│  └────┬────┘  └────┬────┘  └────┬────┘  └────┬────┘   │
│       │            │            │            │        │
│       └────────────┴──────┬─────┴────────────┘        │
│                           │ System Calls              │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─│─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─    │
│                           ▼                           │
│                     KERNEL MODE                       │
│  ┌─────────────────────────────────────────────────┐  │
│  │                     KERNEL                      │  │
│  │  • Process Management  • Memory Management      │  │
│  │  • File Systems        • Device Drivers         │  │
│  │  • Network Stack       • Security               │  │
│  └─────────────────────────────────────────────────┘  │
│                           │                           │
│                           ▼                           │
│  ┌─────────────────────────────────────────────────┐  │
│  │            HARDWARE (CPU, RAM, Disk)            │  │
│  └─────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────┘
```

### User Mode (Режим користувача)

Звичайні програми працюють тут. **Не мають** прямого доступу до апаратного забезпечення.

Аналогія: ви — **водій**. Керуєте кермом, але не маєте доступу до двигуна.

### Kernel Mode (Режим ядра)

Ядро має **повний доступ** до всього обладнання.

Аналогія: ви — **механік**. Повний доступ до всіх частин автомобіля.

### Перемикання режимів

1. Програма викликає функцію (`write()`)
2. Виконується інструкція `syscall`
3. Процесор перемикається в Kernel Mode
4. Ядро виконує операцію
5. Процесор повертається в User Mode

Це забезпечує **безпеку** (вірус не пошкодить систему), **стабільність** (помилка програми не "вб'є" ОС) та **ізоляцію** (процеси не втручаються один в одного).

## Архітектура ядра

### Монолітне ядро

Всі компоненти працюють в одному просторі з повними привілеями.

```
┌────────────────────────────────────┐
│           KERNEL MODE              │
│  ┌──────────────────────────────┐  │
│  │ Scheduler │ Memory  │ FS     │  │
│  │ Drivers   │ Network │ IPC    │  │
│  │        (все разом)           │  │
│  └──────────────────────────────┘  │
└────────────────────────────────────┘
```

**Приклади**: Linux, FreeBSD. **Переваги**: висока продуктивність. **Недоліки**: помилка в драйвері може "покласти" систему.

### Мікроядро

Мінімальне ядро, сервіси працюють в User Mode.

```
┌────────────────────────────────────┐
│            USER MODE               │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐      │
│  │ FS │ │Net │ │Drv │ │Drv │      │
│  └──┬─┘ └──┬─┘ └──┬─┘ └──┬─┘      │
│ ────┴──────┴──────┴──────┴─────── │
│           KERNEL MODE              │
│  ┌──────────────────────────────┐  │
│  │ IPC │ Scheduler │ Memory     │  │
│  │      (мінімум функцій)       │  │
│  └──────────────────────────────┘  │
└────────────────────────────────────┘
```

**Приклади**: MINIX, QNX. **Переваги**: надійність. **Недоліки**: нижча продуктивність.

### Гібридне ядро

Компроміс: мікроядро + критичні сервіси в Kernel Mode.

**Приклади**: Windows NT, macOS (XNU).

## Коротка історія

### 1969: UNIX (Bell Labs)

Кен Томпсон і Денніс Рітчі створили систему, що заклала фундамент:

- Ієрархічна файлова система з коренем `/`
- Командний інтерпретатор (shell)
- Принцип "все є файлом"
- Конвеєри для з'єднання програм

> «UNIX is basically a simple operating system, but you have to be a genius to understand the simplicity.»
>
> — Dennis Ritchie

### 1991: Linux (Linus Torvalds)

21-річний студент з Фінляндії опублікував: *"I'm doing a (free) operating system (just a hobby, won't be big and professional like gnu)..."*

Сьогодні Linux — найпоширеніша ОС: сервери, смартфони, суперкомп'ютери, космічні апарати.

## Перше знайомство з CLI

Командний рядок — потужний інструмент. Чому CLI?

- **Швидкість** — досвідчений користувач працює швидше
- **Автоматизація** — команди можна об'єднувати в скрипти
- **Віддалений доступ** — SSH з будь-якої точки світу

```bash
whoami         # Хто я?
pwd            # Де я?
ls -la         # Що тут є?
date           # Дата і час
uptime         # Час роботи системи
ps aux | wc -l # Кількість процесів
uname -a       # Інформація про систему
```

**Демонстрація htop**: `F5` — дерево процесів, `F9` — kill, `q` — вихід.

## Підсумок

| Термін                     | Визначення                                     |
|----------------------------|------------------------------------------------|
| Ядро (Kernel)              | Серце ОС, повний доступ до заліза              |
| Процес (Process)           | Програма, що виконується                       |
| Системний виклик (Syscall) | Запит програми до ядра                         |
| User Mode                  | Режим звичайних програм (обмежений)            |
| Kernel Mode                | Режим ядра (повний доступ)                     |
| Віртуальна пам'ять         | Абстракція для ізоляції процесів               |
| Планувальник (Scheduler)   | Вирішує який процес виконувати                 |

На наступних лекціях — детально про керування процесами та потоками.

## Теоретичні відомості

### 1 Ядро, дистрибутив і система загалом

Linux у вузькому розумінні — це лише ядро: програма, яка керує пам'яттю, процесами, файловими системами й пристроями. Усе інше, що бачить користувач, — оболонка, системні утиліти, менеджер пакетів, графічне середовище — постачається окремо. Саме тому коректна назва системи загалом — GNU/Linux, а конкретний набір «ядро + утиліти + пакети + політика оновлень» називають дистрибутивом.

Із цього поділу випливає практичний наслідок: версія ядра і версія дистрибутива — різні речі, і кожна відповідає на своє питання. Версія ядра говорить про підтримку обладнання й системні можливості, версія дистрибутива — про склад програм і термін підтримки.

```bash
uname -r                 # версія ядра
uname -a                 # ядро, архітектура, дата збірки
cat /etc/os-release      # дистрибутив: назва, версія, кодове ім'я
lsb_release -a           # те саме у стислому вигляді
hostnamectl              # ім'я вузла, ядро, тип віртуалізації
```

### 2 Все є файлом

Ключовий принцип Unix-систем: майже кожен об'єкт — файл. Звичайні документи, каталоги, пристрої, канали між процесами, навіть відомості про ядро подано у вигляді файлів зі звичними операціями читання й запису. Завдяки цьому ті самі команди `cat`, `ls` і `grep` працюють і з текстом, і з пристроєм, і з таблицею процесів.

Таблиця 1 — Призначення основних каталогів кореня

| Каталог | Що містить |
|---------|------------|
| `/bin`, `/usr/bin` | виконувані файли команд, доступних усім користувачам |
| `/sbin`, `/usr/sbin` | системні утиліти, потрібні адміністраторові |
| `/etc` | текстові файли конфігурації системи та служб |
| `/home` | домашні каталоги користувачів |
| `/root` | домашній каталог адміністратора root |
| `/var` | змінні дані: журнали, черги, кеші |
| `/tmp` | тимчасові файли, очищаються під час перезавантаження |
| `/dev` | файли пристроїв |
| `/proc` | віртуальна файлова система: відомості про ядро та процеси |
| `/sys` | віртуальна файлова система: пристрої та драйвери |
| `/mnt`, `/media` | точки монтування змінних і тимчасових носіїв |

Структуру каталогів описує стандарт FHS (Filesystem Hierarchy Standard), тому в різних дистрибутивах вона однакова: навичка орієнтування переноситься з Ubuntu на Fedora без перенавчання.

### 3 Оболонка та структура команди

Оболонка (shell) — програма, що приймає команди користувача й передає їх ядру через системні виклики. Типова оболонка сучасних дистрибутивів — bash. Команда має сталу будову: ім'я, ключі, аргументи.

```bash
ls -l -h /var/log        # ім'я команди, два ключі, аргумент
ls -lh /var/log          # короткі ключі можна об'єднувати
ls --human-readable      # довга форма ключа
```

Оболонка сама по собі не знає більшості команд: `ls`, `cp`, `grep` — окремі програми у `/usr/bin`. Вбудованими є лише ті, що змінюють стан самої оболонки, наприклад `cd`. Перевірити природу команди дозволяє `type`.

### 4 Довідка як частина системи

Linux зберігає документацію локально, тому довідка доступна без мережі. Це принципова навичка: замість пошуку в інтернеті адміністратор дивиться сторінку `man` тієї версії команди, яка справді встановлена.

Таблиця 2 — Джерела довідки

| Команда | Що показує |
|---------|------------|
| `man ls` | повна сторінка посібника з розділами й ключами |
| `ls --help` | стислий перелік ключів самої програми |
| `apropos копіювання` | пошук команд за словом в описі |
| `whatis cp` | однорядковий опис команди |
| `type cd` | чим є команда: вбудованою, програмою чи псевдонімом |
| `which ls` | повний шлях до виконуваного файлу |

### 5 Користувачі, root і sudo

Linux спроєктовано як багатокористувацьку систему: кожен процес виконується від імені певного користувача й отримує лише його права. Адміністратор `root` має необмежені права, тому щоденна робота під ним вважається помилкою. Натомість окремі дії виконують через `sudo`, який підвищує права для однієї команди й записує факт підвищення в журнал.

```bash
whoami                   # поточний користувач
id                       # UID, GID і список груп
groups                   # лише групи
sudo -l                  # які команди дозволені через sudo
sudo systemctl status ssh
```

### 6 Процеси та systemd

Кожна програма, яка виконується, є процесом із власним ідентифікатором PID. Перший процес системи має PID 1: у сучасних дистрибутивах це `systemd` — менеджер служб, який запускає решту й наглядає за їхнім станом. Саме тому перевірка стану будь-якої служби починається з `systemctl`.

```bash
ps aux | head            # перелік процесів
ps -ef --forest | head -20
systemctl status         # загальний стан системи
systemctl list-units --type=service --state=running | head
journalctl -b -p err     # помилки з моменту завантаження
free -h                  # використання пам'яті
uptime                   # час роботи й середнє навантаження
```

## Приклад виконання

Нижче наведено послідовність дій для довільної системи. Конкретні значення на вашій машині будуть іншими — у звіт вносяться саме ваші результати.

### Крок 1. Паспорт системи

```bash
student@lab-vm:~$ uname -r
6.8.0-45-generic

student@lab-vm:~$ cat /etc/os-release | head -3
PRETTY_NAME="Ubuntu 22.04.4 LTS"
NAME="Ubuntu"
VERSION_ID="22.04"

student@lab-vm:~$ hostnamectl
 Static hostname: lab-vm
       Icon name: computer-vm
      Operating System: Ubuntu 22.04.4 LTS
          Kernel: Linux 6.8.0-45-generic
    Architecture: x86-64
```

Версія ядра `6.8.0` і версія дистрибутива `22.04` не збігаються й не мають збігатися: перша належить проєкту Linux, друга — Canonical.

### Крок 2. Орієнтування у файловій системі

```bash
student@lab-vm:~$ pwd
/home/student

student@lab-vm:~$ ls /
bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var

student@lab-vm:~$ ls -lh /etc/os-release
-rw-r--r-- 1 root root 386 Feb 28  2026 /etc/os-release

student@lab-vm:~$ du -sh /var/log
248M	/var/log
```

Запис `-rw-r--r--` показує права: власник може читати й писати, решта — лише читати. Власником конфігураційного файлу є `root`, тому звичайний користувач змінити його не зможе.

### Крок 3. Структура команди та довідка

```bash
student@lab-vm:~$ type cd ls
cd is a shell builtin
ls is aliased to `ls --color=auto'

student@lab-vm:~$ which ls
/usr/bin/ls

student@lab-vm:~$ ls --help | head -5
Usage: ls [OPTION]... [FILE]...
List information about the FILEs (the default is current directory).

student@lab-vm:~$ whatis cp
cp (1)               - copy files and directories
```

Команда `cd` вбудована в оболонку, бо змінює її власний стан — поточний каталог; `ls` є окремою програмою, і в системі є її повний шлях.

### Крок 4. Користувач і права

```bash
student@lab-vm:~$ whoami
student

student@lab-vm:~$ id
uid=1000(student) gid=1000(student) groups=1000(student),27(sudo),44(video)

student@lab-vm:~$ cat /etc/shadow
cat: /etc/shadow: Permission denied

student@lab-vm:~$ sudo head -1 /etc/shadow
[sudo] password for student:
root:$6$rounds=656000$...:19800:0:99999:7:::
```

Та сама команда без `sudo` і з ним дає різний результат: система перевіряє права на кожну операцію читання, а не лише під час входу.

### Крок 5. Процеси та служби

```bash
student@lab-vm:~$ ps -p 1 -o pid,comm
    PID COMMAND
      1 systemd

student@lab-vm:~$ systemctl list-units --type=service --state=running | head -5
  cron.service          loaded active running Regular background program processing daemon
  dbus.service          loaded active running D-Bus System Message Bus
  ssh.service           loaded active running OpenBSD Secure Shell server

student@lab-vm:~$ systemctl status cron | head -4
● cron.service - Regular background program processing daemon
     Loaded: loaded (/lib/systemd/system/cron.service; enabled)
     Active: active (running) since Wed 2026-09-17 08:42:31 EEST; 2h 14min ago

student@lab-vm:~$ free -h | head -2
               total        used        free      shared  buff/cache   available
Mem:           3,8Gi       1,1Gi       1,4Gi        12Mi       1,3Gi       2,4Gi
```

Процес із PID 1 — `systemd`: саме він запустив усі інші процеси, тому в дереві `ps -ef --forest` він стоїть у корені.

### Крок 6. Ядро очима файлової системи

```bash
student@lab-vm:~$ cat /proc/version
Linux version 6.8.0-45-generic (buildd@lcy02) (gcc 11.4.0) #45-Ubuntu SMP

student@lab-vm:~$ cat /proc/cpuinfo | grep "model name" | head -1
model name	: Intel(R) Core(TM) i5-10400 CPU @ 2.90GHz

student@lab-vm:~$ ls /proc/self
cmdline  cwd  environ  exe  fd  maps  status  task

student@lab-vm:~$ cat /proc/loadavg
0.32 0.41 0.38 2/412 3187
```

Каталог `/proc` не займає місця на диску: ядро формує його вміст у пам'яті на момент читання. Це наочна ілюстрація принципу «все є файлом».

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Скласти паспорт системи: версія ядра, назва та версія дистрибутива, архітектура, ім'я вузла, тип віртуалізації, час роботи системи. Скористатися командами `uname`, `/etc/os-release`, `hostnamectl`, `uptime`.

3. Знайти й записати значення параметра системи, зазначеного у вашому варіанті. Навести команду, якою його отримано.

4. Вивести перелік каталогів кореня. Для трьох каталогів, зазначених у варіанті, пояснити призначення за стандартом FHS і навести приклад файлу з кожного.

5. Визначити для команди свого варіанта: чи є вона вбудованою в оболонку, де розташований її виконуваний файл, що показує однорядковий опис `whatis`. Навести три ключі команди з поясненням призначення кожного.

6. Знайти засобами довідки команду, яка виконує задачу, зазначену у варіанті (скористатися `apropos`). Описати, як саме ви її знайшли.

7. Вивести відомості про власний обліковий запис: UID, GID, групи. Пояснити, що дає членство в групі `sudo`. Продемонструвати різницю доступу до файлу `/etc/shadow` з `sudo` і без нього.

8. Отримати перелік процесів і визначити процес із PID 1. Вивести перелік служб у стані running і показати докладний стан служби свого варіанта.

9. Отримати три показники стану системи з віртуальної файлової системи `/proc` і пояснити, чому ці файли не займають місця на диску.

10. Виконати додаткове завдання свого варіанта.

11. Оформити звіт і зробити висновок.

Звіт оформлюється на бланку встановленого зразка і має містити:

- тему, мету та обладнання;
- постановку задачі за індивідуальним варіантом;
- таблицю паспорта системи за результатами пункту 2;
- перелік виконаних команд із поясненням призначення кожного ключа;
- знімки екрана з результатами виконання, зокрема різницю доступу з `sudo` і без нього;
- опис трьох каталогів FHS свого варіанта з прикладами файлів;
- відповідь на запитання додаткового завдання варіанта;
- висновок, у якому пояснено, чим ядро відрізняється від дистрибутива і як принцип «все є файлом» виявляється в роботі з `/proc`.

| 4 | Середнє навантаження системи | `/dev`, `/sys`, `/run` | `find` | `systemd-journald` | Пояснити різницю між `/dev` і `/sys` |

| 8 | Кодове ім'я дистрибутива | `/etc`, `/usr`, `/opt` | `cat` | `dbus` | Знайти файл із переліком репозиторіїв пакетів |
| 9 | Тип віртуалізації | `/sys`, `/dev`, `/boot` | `uname` | `cron` | Пояснити, як система визначає, що працює у ВМ |
| 10 | Обсяг swap-простору | `/var`, `/mnt`, `/srv` | `free` | `ssh` | Пояснити призначення swap і як його переглянути |
| 11 | Ім'я поточної оболонки | `/bin`, `/etc`, `/home` | `echo` | `dbus` | Вивести перелік доступних оболонок системи |
| 12 | Часовий пояс системи | `/etc`, `/usr`, `/var` | `date` | `systemd-timesyncd` | Пояснити, де зберігається налаштування часового поясу |
| 13 | Кількість процесів у системі | `/proc`, `/sys`, `/run` | `top` | `cron` | Порівняти кількість процесів із виводом `/proc/loadavg` |
| 14 | Файлова система кореневого розділу | `/`, `/boot`, `/mnt` | `df` | `ssh` | Пояснити призначення окремого розділу `/boot` |
| 15 | Поточний рівень журналювання ядра | `/proc`, `/var`, `/etc` | `dmesg` | `systemd-journald` | Знайти в журналі повідомлення про завантаження диска |
| 16 | Версія оболонки bash | `/bin`, `/usr`, `/etc` | `bash` | `cron` | Пояснити різницю між `/bin` і `/usr/bin` у сучасних Ubuntu |
| 17 | Максимальна кількість відкритих файлів | `/proc`, `/etc`, `/run` | `ulimit` | `ssh` | Пояснити, навіщо система обмежує кількість дескрипторів |
| 18 | Мережеве ім'я та IP-адреса | `/etc`, `/sys`, `/var` | `ip` | `dbus` | Знайти файл конфігурації мережі свого дистрибутива |
| 19 | Кількість зареєстрованих користувачів | `/home`, `/etc`, `/var` | `who` | `cron` | Пояснити, які записи в `/etc/passwd` не є людьми |
| 20 | Розмір каталогу журналів | `/var`, `/tmp`, `/proc` | `journalctl` | `systemd-journald` | Запропонувати спосіб обмежити розмір журналів |

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Що таке ядро Linux і що таке дистрибутив?
2. Якою командою визначають версію ядра, а якою — версію дистрибутива?
3. Сформулюйте принцип «все є файлом» і наведіть приклад.
4. Що описує стандарт FHS?
5. Що зберігається в каталогах `/etc`, `/var` і `/home`?
6. З яких частин складається команда оболонки? Наведіть приклад із двома ключами.
7. Які команди дають довідку про іншу команду?
8. Який процес має PID 1 у сучасних дистрибутивах?

### Достатній рівень (конструктивно-варіативний)

1. Чому версія ядра й версія дистрибутива не збігаються? Що показує кожна з них?
2. Чому `cd` є вбудованою командою оболонки, а `ls` — окремою програмою?
3. Чим `man` відрізняється від `--help` і коли зручніший кожен із них?
4. Чому каталоги `/proc` і `/sys` не займають місця на диску?
5. Чому повсякденна робота від імені root вважається помилкою? Що дає `sudo` натомість?
6. Запишіть команду, яка покаже п'ять найбільших каталогів у `/var`.
7. Що показує `systemctl status` для служби і які поля в ньому найважливіші?
8. Як за допомогою `apropos` знайти команду, призначення якої відоме, а ім'я — ні?

### Високий рівень (творчий)

1. Поясніть, як принцип «все є файлом» спрощує написання системних утиліт. Проілюструйте на прикладі читання відомостей про процесор.
2. Два комп'ютери мають однакову версію дистрибутива, але різні версії ядра. Назвіть щонайменше три наслідки цієї різниці для адміністратора.
3. Сформулюйте критерії вибору дистрибутива для навчального класу й обґрунтуйте кожен із них.
4. Система завантажилася, але одна зі служб не працює. Опишіть послідовність дій із використанням `systemctl` і `journalctl` та поясніть, що саме ви шукаєте на кожному кроці.

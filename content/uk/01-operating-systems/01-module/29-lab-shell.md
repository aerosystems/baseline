## Теоретичні відомості

### 1 Скрипт як програма оболонки

Скрипт bash — текстовий файл із командами, які оболонка виконує послідовно. На відміну від Windows, розширення не має значення: систему цікавить перший рядок файлу й біт виконання.

```bash
#!/bin/bash
# backup.sh — резервне копіювання документів
echo "Скрипт: $0"
```

Перший рядок `#!/bin/bash` називається shebang: ядро читає ці два символи й запускає вказаний інтерпретатор, передаючи йому файл. Без shebang скрипт виконається поточною оболонкою, і команди, специфічні для bash, можуть не спрацювати в системі, де за замовчуванням стоїть dash.

```bash
chmod +x backup.sh     # надати право виконання
./backup.sh            # запустити як програму
bash backup.sh         # запустити явним інтерпретатором
source backup.sh       # виконати в поточній оболонці
```

Різниця принципова: `./backup.sh` створює дочірній процес, тому змінні, встановлені в скрипті, зникають після завершення; `source` виконує команди в поточній оболонці й змінює її стан.

### 2 Змінні та підстановки

```bash
name="LAB10"                     # без пробілів навколо =
dir="$HOME/lab10"                # підстановка іншої змінної
count=$(ls "$dir" | wc -l)       # підстановка результату команди
today=$(date +%F)                # 2026-09-18
echo "У каталозі $dir файлів: $count"
```

Змінну завжди беруть у подвійні лапки: без них значення з пробілами розпадеться на кілька аргументів, а порожня змінна зникне зовсім. Це найчастіша причина помилок у скриптах, які «працювали, доки в імені файлу не з'явився пробіл».

Таблиця 1 — Спеціальні змінні bash

| Змінна | Значення |
|--------|----------|
| `$0` | ім'я самого скрипта |
| `$1`…`$9` | позиційні параметри |
| `$#` | кількість переданих параметрів |
| `$@` | усі параметри як окремі слова |
| `$*` | усі параметри одним рядком |
| `$?` | код повернення попередньої команди |
| `$$` | PID поточного процесу |
| `$USER`, `$HOME`, `$PATH` | змінні середовища |

### 3 Умовні конструкції

```bash
if [[ $# -eq 0 ]]; then
    echo "Використання: $0 <каталог>" >&2
    exit 1
fi

if [[ -d "$1" ]]; then
    echo "Це каталог"
elif [[ -f "$1" ]]; then
    echo "Це файл"
else
    echo "Об'єкт не знайдено" >&2
    exit 2
fi
```

Таблиця 2 — Основні перевірки в умовах

| Перевірка | Істинна, якщо |
|-----------|---------------|
| `-f файл` | існує звичайний файл |
| `-d файл` | існує каталог |
| `-e файл` | об'єкт існує (будь-який тип) |
| `-r`, `-w`, `-x` | є право читання, запису, виконання |
| `-s файл` | файл не порожній |
| `-z "$var"` | рядок порожній |
| `-n "$var"` | рядок не порожній |
| `"$a" == "$b"` | рядки рівні |
| `$a -eq $b` | числа рівні (`-ne`, `-lt`, `-le`, `-gt`, `-ge`) |

Подвійні дужки `[[ ]]` — вбудована конструкція bash: вона безпечніша за класичні одинарні `[ ]`, бо не потребує лапок навколо змінних і підтримує шаблони.

### 4 Цикли

```bash
for file in "$dir"/*.log; do
    echo "Обробляю $file"
done

for i in {1..5}; do
    echo "Ітерація $i"
done

while read -r line; do
    echo "Рядок: $line"
done < users.txt

until ping -c1 -W1 "$host" &>/dev/null; do
    echo "Чекаю на $host"
    sleep 2
done
```

Цикл `while read -r line` — стандартний спосіб обробки файлу рядок за рядком. Ключ `-r` вимикає інтерпретацію зворотних скісних рисок, тому шляхи Windows і спецсимволи читаються без спотворень.

### 5 Функції та коди повернення

```bash
log() {
    echo "[$(date '+%F %T')] $*" >> "$LOG"
}

check_dir() {
    local dir="$1"
    if [[ ! -d "$dir" ]]; then
        log "ПОМИЛКА: каталогу $dir немає"
        return 1
    fi
    return 0
}

check_dir "$1" || exit 2
log "Каталог перевірено"
```

Ключове слово `local` робить змінну видимою лише всередині функції — без нього змінна стає глобальною і може непомітно зіпсувати стан скрипта. Функція повертає не значення, а код завершення: результат передають через `echo` та підстановку `$(...)`.

Коди повернення з'єднують скрипт із рештою системи: `0` означає успіх, будь-яке інше число — конкретну помилку. Оператори `&&` і `||` виконують наступну команду залежно від коду попередньої.

### 6 Надійність скрипта

```bash
set -euo pipefail
```

Три параметри перетворюють «мовчазний» скрипт на передбачуваний: `-e` зупиняє виконання після першої помилки, `-u` робить помилкою звертання до неоголошеної змінної, `-o pipefail` змушує конвеєр повертати код невдалої команди, а не останньої. Для адміністративних скриптів цей рядок вважається стандартом.

```bash
trap 'rm -f "$tmp"' EXIT          # прибрати тимчасовий файл за будь-якого виходу
tmp=$(mktemp)                     # безпечне створення тимчасового файлу
```

### 7 Запуск за розкладом

```bash
crontab -e                        # редагувати розклад користувача
crontab -l                        # переглянути
# ┌ хвилина ┌ година ┌ день ┌ місяць ┌ день тижня
  0          3        *      *       *   /home/student/lab10/backup.sh >> /home/student/lab10/cron.log 2>&1
```

Скрипт, запущений cron, отримує мінімальне оточення: змінна `PATH` коротша, робочий каталог — домашній, графічних діалогів немає. Саме тому в скриптах для розкладу використовують абсолютні шляхи й перенаправляють вивід у журнал.

### Крок 2. Параметри та перевірки

```bash
#!/bin/bash
# info.sh — відомості про об'єкт файлової системи
set -euo pipefail

if [[ $# -eq 0 ]]; then
    echo "Використання: $0 <шлях>" >&2
    exit 1
fi

target="$1"

if [[ ! -e "$target" ]]; then
    echo "Об'єкт '$target' не існує" >&2
    exit 2
fi

if [[ -d "$target" ]]; then
    echo "Тип:     каталог"
    echo "Файлів:  $(find "$target" -maxdepth 1 -type f | wc -l)"
else
    echo "Тип:     файл"
    echo "Розмір:  $(stat -c%s "$target") байт"
    echo "Рядків:  $(wc -l < "$target")"
fi
echo "Власник: $(stat -c%U "$target")"
echo "Права:   $(stat -c%A "$target")"
```

```bash
student@lab-vm:~/lab10$ ./info.sh
Використання: ./info.sh <шлях>
student@lab-vm:~/lab10$ echo $?
1

student@lab-vm:~/lab10$ ./info.sh src/hosts
Тип:     файл
Розмір:  221 байт
Рядків:  12
Власник: student
Права:   -rw-r--r--

student@lab-vm:~/lab10$ ./info.sh /nonexistent
Об'єкт '/nonexistent' не існує
student@lab-vm:~/lab10$ echo $?
2
```

Різні причини відмови дають різні коди повернення — саме так скрипт вбудовують у ланцюжок автоматизації.

### Крок 3. Цикл і лічильники

```bash
#!/bin/bash
# count.sh — статистика каталогу
set -euo pipefail
dir="${1:-$PWD}"
count=0
bytes=0

for file in "$dir"/*; do
    [[ -f "$file" ]] || continue
    size=$(stat -c%s "$file")
    count=$((count + 1))
    bytes=$((bytes + size))
    printf "%2d) %-20s %8d байт\n" "$count" "$(basename "$file")" "$size"
done

echo "Разом: $count файлів, $bytes байт"
[[ $count -gt 0 ]] && echo "Середній розмір: $((bytes / count)) байт"
```

```bash
student@lab-vm:~/lab10$ ./count.sh src
 1) hosts                     221 байт
 2) passwd                   3020 байт
 3) services                19183 байт
Разом: 3 файлів, 22424 байт
Середній розмір: 7474 байт
```

Конструкція `${1:-$PWD}` задає значення за замовчуванням: якщо параметр не переданий, скрипт працює з поточним каталогом.

### Крок 4. Функції та журнал

```bash
#!/bin/bash
# backup.sh — резервне копіювання з журналом
set -euo pipefail

readonly SRC="${1:-$HOME/lab10/src}"
readonly DST="$HOME/lab10/bak/$(date +%F)"
readonly LOG="$HOME/lab10/logs/backup.log"

log() {
    echo "[$(date '+%F %T')] $*" | tee -a "$LOG"
}

die() {
    log "ПОМИЛКА: $*"
    exit 1
}

[[ -d "$SRC" ]] || die "каталог $SRC не існує"
mkdir -p "$DST" "$(dirname "$LOG")"

log "Початок копіювання $SRC → $DST"
if cp -a "$SRC"/. "$DST"/; then
    files=$(find "$DST" -type f | wc -l)
    log "Скопійовано файлів: $files"
else
    die "копіювання не вдалося (код $?)"
fi

archive="$HOME/lab10/bak/backup-$(date +%F).tar.gz"
tar -czf "$archive" -C "$DST" . || die "архівування не вдалося"
log "Архів: $archive ($(stat -c%s "$archive") байт)"
```

```bash
student@lab-vm:~/lab10$ ./backup.sh
[2026-09-18 12:05:11] Початок копіювання /home/student/lab10/src → /home/student/lab10/bak/2026-09-18
[2026-09-18 12:05:11] Скопійовано файлів: 3
[2026-09-18 12:05:11] Архів: /home/student/lab10/bak/backup-2026-09-18.tar.gz (6482 байт)

student@lab-vm:~/lab10$ ./backup.sh /nonexistent
[2026-09-18 12:06:02] ПОМИЛКА: каталог /nonexistent не існує
student@lab-vm:~/lab10$ echo $?
1
```

Команда `tee -a` одночасно виводить повідомлення на екран і дописує його в журнал — зручно, коли скрипт запускають і вручну, і за розкладом.

### Крок 5. Обробка файлу рядок за рядком

```bash
#!/bin/bash
# users.sh — розбір текстового файлу з роздільниками
set -euo pipefail
input="${1:?Вкажіть файл}"

while IFS=';' read -r name dept quota; do
    [[ "$name" == \#* || -z "$name" ]] && continue
    printf "%-12s %-12s %s МБ\n" "$name" "$dept" "$quota"
    total=$((${total:-0} + quota))
done < "$input"

echo "Загальна квота: ${total:-0} МБ"
```

```bash
student@lab-vm:~/lab10$ cat users.csv
# name;department;quota
ivanov;IT;500
petrenko;Accounting;200
kovalenko;IT;800

student@lab-vm:~/lab10$ ./users.sh users.csv
ivanov       IT           500 МБ
petrenko     Accounting   200 МБ
kovalenko    IT           800 МБ
Загальна квота: 1500 МБ
```

Конструкція `${1:?Вкажіть файл}` завершує скрипт із повідомленням, якщо параметр не переданий, — компактна заміна окремій перевірці.

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Створити структуру `~/lab10` з підкаталогами `src`, `bak`, `logs`. Наповнити `src` щонайменше п'ятьма файлами, зокрема одним текстовим файлом із даними, розділеними символом `;`.

3. Написати скрипт `hello.sh`, який виводить своє ім'я, кількість переданих параметрів, ім'я користувача, поточний каталог і PID. Показати, що без права виконання скрипт не запускається, і надати це право.

4. Пояснити у звіті різницю між запусками `./script.sh`, `bash script.sh` і `source script.sh`. Підтвердити висновок експериментом зі змінною.

5. Написати скрипт `info.sh`, який приймає шлях параметром, перевіряє його існування й тип та виводить відомості згідно з варіантом. Передбачити різні коди повернення для різних причин відмови й показати значення `$?` у кожному випадку.

6. Написати скрипт із циклом, який обробляє всі файли каталогу `src`: рахує їх кількість, сумарний і середній обсяг. Використати підстановку команд і арифметику.

7. Реалізувати основне завдання свого варіанта. Скрипт має містити: перевірку вхідних даних, цикл, щонайменше одну функцію та запис у журнал.

8. Додати до скрипта рядок `set -euo pipefail` і пояснити, як змінилася поведінка в разі помилки. Навести приклад до і після.

9. Написати скрипт, який читає текстовий файл рядок за рядком, розбирає поля за роздільником і виводить підсумок за числовим полем.

10. Налаштувати запуск основного скрипта за розкладом через `cron` з періодичністю свого варіанта. Підтвердити спрацювання записом у журналі. Після перевірки прибрати завдання з розкладу.

11. Виконати додаткове завдання свого варіанта.

12. Оформити звіт і зробити висновок.

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Що таке скрипт bash і чим він відрізняється від звичайної програми?
2. Що таке shebang і навіщо він потрібен?
3. Як надати скрипту право виконання?
4. Як звернутися до першого параметра скрипта й до їхньої кількості?
5. Що зберігає змінна `$?`?
6. Запишіть перевірку існування каталогу.
7. Які види циклів є в bash?
8. Якою командою скрипт завершується з кодом помилки?

### Достатній рівень (конструктивно-варіативний)

1. Чим `./script.sh` відрізняється від `source script.sh`? Наведіть задачу для кожного способу.
2. Чому змінні беруть у подвійні лапки? Наведіть приклад помилки без них.
3. Що робить кожен із параметрів у рядку `set -euo pipefail`?
4. Чим `[[ ]]` відрізняється від `[ ]`?
5. Запишіть цикл, який обробить усі файли `.log` у каталозі, переданому параметром.
6. Навіщо у функції оголошують змінні через `local`?
7. Як функція повертає результат обчислення, якщо `return` приймає лише код завершення?
8. Чому скрипт, який працює вручну, може не спрацювати з cron? Назвіть дві причини.

### Високий рівень (творчий)

1. Опишіть структуру скрипта резервного копіювання, що зберігає сім останніх копій і видаляє старіші. Які перевірки, цикли й коди повернення потрібні?
2. Поясніть, чому конструкція `rm -rf "$dir"/*` небезпечна, і запропонуйте три різні способи захисту від помилки в змінній.
3. Порівняйте bash і PowerShell як засоби автоматизації за трьома критеріями. У яких задачах ви оберете кожен?
4. Сформулюйте критерії, за якими адміністративну задачу варто автоматизувати скриптом, а коли доцільніше застосувати готовий інструмент. Проілюструйте прикладом із цієї роботи.

**Мета:** навчитися працювати з дисковими пристроями: переглядати структуру носіїв, створювати таблицю розділів і розділи, форматувати їх у різні файлові системи, монтувати вручну та автоматично, а також діагностувати стан носія й файлової системи.

**Обладнання:** віртуальна машина з Ubuntu 22.04+ і **додатковим** віртуальним диском на 2-5 ГБ; право виконувати `sudo`; за потреби — Windows із оснасткою «Керування дисками».

**Тривалість:** 4 академічні години (2 заняття).

**УВАГА. Усі операції розмітки й форматування знищують дані на носії. Працювати дозволено ВИКЛЮЧНО з додатковим віртуальним диском (зазвичай `/dev/sdb`), який не містить системи. Перед кожною командою `fdisk`, `mkfs` чи `dd` перевіряйте ім'я пристрою командою `lsblk`. Помилка в одній літері імені диска знищує систему.**

## Теоретичні відомості

### 1 Як система бачить накопичувачі

Блоковий пристрій у Linux — це файл у каталозі `/dev`, що надає доступ до носія
блоками сталого розміру.

```bash
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINT
```

Вивід:

```
NAME   TYPE  SIZE FSTYPE MOUNTPOINT
sda    disk   25G
├─sda1 part  512M vfat   /boot/efi
├─sda2 part   15G ext4   /
└─sda3 part  9.5G ext4   /home
sdb    disk    3G
```

Диск `sdb` порожній: у нього немає ні таблиці розділів, ні файлової системи.
Саме з ним ми й працюватимемо.

Таблиця 1 — Імена блокових пристроїв

| Ім'я | Що означає |
|------|------------|
| `/dev/sda` | перший диск із інтерфейсом SATA або SCSI |
| `/dev/sdb1` | перший розділ другого такого диска |
| `/dev/nvme0n1` | перший простір імен першого накопичувача NVMe |
| `/dev/nvme0n1p2` | другий розділ цього накопичувача |
| `/dev/sr0` | оптичний привід |

### 2 Таблиця розділів

Таблиця розділів описує, з якого сектора починається кожен розділ і якого він
розміру. Два формати — MBR і GPT — розглянуто в лабораторній роботі з
інсталяції; тут ми створюємо GPT як сучасний стандарт.

### 3 Файлова система

Розділ сам по собі — лише проміжок секторів. Щоб у ньому можна було зберігати
файли, потрібна файлова система: структури, які описують каталоги, права,
розташування даних.

Таблиця 2 — Утиліти створення файлових систем

| Команда | Файлова система | Типове застосування |
|---------|-----------------|---------------------|
| `mkfs.ext4` | ext4 | основний вибір для Linux |
| `mkfs.xfs` | XFS | великі файли, сервери |
| `mkfs.btrfs` | Btrfs | знімки стану, стиснення |
| `mkfs.vfat` | FAT32 | змінні носії, розділ EFI |
| `mkfs.ntfs` | NTFS | обмін із Windows |
| `mkswap` | підкачка | розділ підкачки |

### 4 Монтування

Монтування приєднує файлову систему розділу до каталогу наявного дерева.
Точка монтування — звичайний каталог; після монтування його попередній вміст
стає недоступним, доки розділ не відмонтують.

```
до монтування                  після монтування /dev/sdb1 у /mnt/data

/mnt/data (порожній)           /mnt/data → вміст файлової системи sdb1
```

### 5 Автоматичне монтування

Щоб розділ монтувався під час завантаження, його описують у `/etc/fstab`.
Пристрій указують не іменем `/dev/sdb1`, а **UUID**: імена залежать від порядку
виявлення дисків і можуть змінитися після додавання нового носія.

```
UUID=1f2e3d4c-...  /mnt/data  ext4  defaults,nofail  0  2
   пристрій        точка      тип   параметри       dump fsck
```

Параметр `nofail` критично важливий у навчальних роботах: без нього система з
помилковим записом у `/etc/fstab` не завантажиться.

## Приклад виконання

### Крок 1. Огляд наявних пристроїв

```bash
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINT
sudo fdisk -l /dev/sdb
```

Вивід для порожнього диска:

```
Disk /dev/sdb: 3 GiB, 3221225472 bytes, 6291456 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
```

Рядка `Disklabel type` немає — таблиці розділів ще не існує.

### Крок 2. Створення таблиці розділів і двох розділів

```bash
# Неінтерактивно: GPT, розділ 1 на 1 ГБ, розділ 2 на решту
sudo sgdisk --zap-all /dev/sdb
sudo sgdisk --new=1:0:+1G --typecode=1:8300 --change-name=1:data1 /dev/sdb
sudo sgdisk --new=2:0:0   --typecode=2:8300 --change-name=2:data2 /dev/sdb
sudo partprobe /dev/sdb
lsblk /dev/sdb
```

Вивід:

```
NAME   MAJ:MIN RM SIZE RO TYPE MOUNTPOINT
sdb      8:16   0   3G  0 disk
├─sdb1   8:17   0   1G  0 part
└─sdb2   8:18   0   2G  0 part
```

### Крок 3. Створення файлових систем

```bash
sudo mkfs.ext4 -L LABDATA1 /dev/sdb1
sudo mkfs.vfat -n LABDATA2 /dev/sdb2
lsblk -o NAME,SIZE,FSTYPE,LABEL /dev/sdb
```

Вивід:

```
NAME   SIZE FSTYPE LABEL
sdb      3G
├─sdb1   1G ext4   LABDATA1
└─sdb2   2G vfat   LABDATA2
```

### Крок 4. Монтування вручну

```bash
sudo mkdir -p /mnt/data1 /mnt/data2
sudo mount /dev/sdb1 /mnt/data1
sudo mount /dev/sdb2 /mnt/data2

# Перевірка
df -h --output=source,fstype,size,used,avail,target | grep sdb
```

Вивід:

```
/dev/sdb1      ext4  974M   24K  907M /mnt/data1
/dev/sdb2      vfat  2.0G  4.0K  2.0G /mnt/data2
```

Зверніть увагу: на розділі ext4 із 974 МБ одразу зайнято місце під службові
структури, а доступно 907 МБ. Різниця — плата за журнал і резерв
суперкористувача.

### Крок 5. Перевірка прав і поведінки файлових систем

```bash
# ext4 зберігає права UNIX
sudo touch /mnt/data1/file.txt
sudo chmod 640 /mnt/data1/file.txt
ls -l /mnt/data1/file.txt

# FAT32 прав не має: вони задаються параметрами монтування
sudo touch /mnt/data2/file.txt
sudo chmod 640 /mnt/data2/file.txt
ls -l /mnt/data2/file.txt
```

Вивід:

```
-rw-r----- 1 root root 0 ... /mnt/data1/file.txt
-rwxr-xr-x 1 root root 0 ... /mnt/data2/file.txt
```

Права на FAT32 не змінилися: ця файлова система їх просто не зберігає. Це
наочна демонстрація того, що можливості визначаються не командою, а форматом.

### Крок 6. Автоматичне монтування через /etc/fstab

```bash
# Дізнатися UUID розділу
sudo blkid /dev/sdb1

# Додати запис (зверніть увагу на nofail)
echo "UUID=$(sudo blkid -s UUID -o value /dev/sdb1) /mnt/data1 ext4 defaults,nofail 0 2" \
  | sudo tee -a /etc/fstab

# Перевірити запис БЕЗ перезавантаження
sudo umount /mnt/data1
sudo mount -a
df -h | grep data1
```

Команда `mount -a` — обов'язкова перевірка: якщо в записі є помилка, вона
виявиться зараз, а не при наступному завантаженні.

### Крок 7. Діагностика

```bash
# Перевірка файлової системи (лише на відмонтованому розділі)
sudo umount /mnt/data2
sudo fsck.vfat -v /dev/sdb2 | tail -5

# Використання простору за каталогами
sudo du -sh /mnt/data1/* 2>/dev/null | sort -h | tail -5

# Скільки вільних inode лишилося
df -i | grep -E "Filesystem|sdb"
```

Показник inode важливий окремо: розділ може мати вільні гігабайти й водночас не
приймати нових файлів, якщо вичерпано записи inode.

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.
2. Переконатися, що додатковий диск підключено, і визначити його ім'я.
3. Створити таблицю розділів і розділи за схемою свого варіанта.
4. Створити файлові системи вказаних у варіанті типів.
5. Змонтувати розділи вручну та перевірити доступний обсяг.
6. Виконати перевірку поведінки прав доступу на різних файлових системах.
7. Налаштувати автоматичне монтування одного з розділів через `/etc/fstab` з
   параметром `nofail` і перевірити запис командою `mount -a`.
8. Виконати діагностику: перевірку файлової системи та облік inode.
9. Виконати додаткове завдання свого варіанта.
10. Відмонтувати розділи, прибрати запис з `/etc/fstab`, оформити звіт.

## Вимоги до звіту

Звіт оформлюється на бланку встановленого зразка і має містити:

- тему, мету та обладнання;
- схему розмітки за індивідуальним варіантом;
- перелік виконаних команд із поясненням призначення кожної;
- знімки екрана з результатами `lsblk`, `df -h`, `blkid`;
- запис, доданий до `/etc/fstab`, із поясненням кожного поля;
- результати діагностики файлової системи;
- відповіді на контрольні запитання свого рівня;
- висновок за результатами роботи.

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Що показує команда `lsblk`?
2. Чим розділ відрізняється від файлової системи?
3. Якою командою створюють файлову систему ext4?
4. Що таке точка монтування?
5. Для чого призначений файл `/etc/fstab`?
6. Що таке UUID розділу й де його дізнатися?
7. Якою командою перевіряють файлову систему на помилки?
8. Що показує ключ `-i` команди `df`?

### Достатній рівень (конструктивно-варіативний)

1. Чому в `/etc/fstab` записують UUID, а не ім'я `/dev/sdb1`?
2. Навіщо потрібен параметр `nofail` і що станеться без нього?
3. Чому перевірку файлової системи виконують лише на відмонтованому розділі?
4. Чому доступний обсяг на щойно створеному розділі ext4 менший за його розмір?
5. Чому команда `chmod` не змінює права на розділі FAT32?
6. Що станеться з попереднім вмістом каталогу, який став точкою монтування?
7. Навіщо потрібна команда `mount -a` після редагування `/etc/fstab`?
8. Чому розділ може не приймати нових файлів за наявності вільних гігабайтів?

### Високий рівень (творчий)

1. Спроєктуйте схему розділів для файлового сервера, де користувачі
   вивантажують багато дрібних файлів. Обґрунтуйте вибір файлової системи та
   параметрів створення.
2. Поясніть, чому перенесення даних між Linux і Windows через FAT32 зручне для
   обміну й неприйнятне для резервного копіювання.
3. Запропонуйте порядок дій, який мінімізує ризик знищити систему під час
   роботи з розміткою. Опишіть щонайменше чотири перевірки.
4. Користувач повідомляє, що після перезавантаження система не завантажується,
   а на екрані пропонується аварійна консоль. Напередодні він редагував
   `/etc/fstab`. Побудуйте послідовність діагностики та відновлення.

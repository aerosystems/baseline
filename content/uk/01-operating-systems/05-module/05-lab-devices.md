## Теоретичні відомості

### 1 Пристрій як файл

Підсистема введення-виведення приховує від програм відмінності конкретних контролерів і надає єдиний інтерфейс: файл пристрою в каталозі `/dev`. Прикладна програма відкриває такий файл звичайним `open`, читає його `read` і пише `write` — решту робить драйвер.

Файл пристрою не містить даних: це лише посилання на драйвер у ядрі. Зв'язок задають два числа — major визначає драйвер, minor — конкретний пристрій, який цей драйвер обслуговує.

```bash
ls -l /dev/sda /dev/sda1 /dev/null /dev/tty0
# brw-rw----  1 root disk    8,  0 вер 18 09:12 /dev/sda
# brw-rw----  1 root disk    8,  1 вер 18 09:12 /dev/sda1
# crw-rw-rw-  1 root root    1,  3 вер 18 09:12 /dev/null
# crw--w----  1 root tty     4,  0 вер 18 09:12 /dev/tty0
```

Перший символ виводу `ls -l` показує тип: `b` — блоковий пристрій, `c` — символьний. Замість розміру файлу система виводить пару чисел major, minor.

### 2 Блокові та символьні пристрої

Таблиця 1 — Два класи пристроїв

| Характеристика | Блокові (`b`) | Символьні (`c`) |
|----------------|---------------|-----------------|
| Одиниця обміну | блок фіксованого розміру | окремий байт (потік) |
| Довільний доступ | так, за номером блока | ні, послідовно |
| Буферизація ядром | так, через кеш сторінок | зазвичай без кешу |
| Приклади | диски, розділи, SSD, RAID | термінали, порти, `/dev/null`, `/dev/random` |

Поділ визначає спосіб роботи драйвера: блокові пристрої ядро обслуговує через планувальник введення-виведення й кеш, символьні — передає дані безпосередньо.

Таблиця 2 — Псевдопристрої, які існують лише в ядрі

| Пристрій | Призначення |
|----------|-------------|
| `/dev/null` | «чорна діра»: усе записане зникає, читання дає кінець файлу |
| `/dev/zero` | нескінченний потік нульових байтів |
| `/dev/random`, `/dev/urandom` | джерела випадкових чисел |
| `/dev/full` | завжди повертає помилку «немає місця» |
| `/dev/loop0` | файл, підключений як блоковий пристрій |

### 3 Підсистема udev

Каталог `/dev` не зберігається на диску: його наповнює служба `udev` у момент завантаження й під час кожного підключення пристрою. Ядро надсилає подію (uevent), `udev` знаходить відповідне правило й створює файл пристрою з потрібними іменем, власником і правами.

```bash
udevadm monitor --udev            # спостерігати за подіями в реальному часі
udevadm info /dev/sda1            # усі атрибути пристрою
udevadm info -a /dev/sda1 | head  # ланцюжок батьківських пристроїв
ls -l /dev/disk/by-uuid/          # сталі імена, створені udev
```

Саме `udev` створює каталоги сталих імен `/dev/disk/by-uuid`, `/dev/disk/by-id` і `/dev/disk/by-path`. Ці імена не залежать від порядку виявлення пристроїв, тому в `/etc/fstab` використовують саме їх, а не `/dev/sdb1`.

### 4 Драйвери як модулі ядра

Драйвер у Linux може бути вбудований у ядро або завантажений як модуль під час роботи. Модульність дозволяє підтримувати тисячі пристроїв, не роздуваючи ядро.

```bash
lsmod | head                      # завантажені модулі
modinfo usb_storage               # відомості про модуль
sudo modprobe vfat                # завантажити модуль
sudo modprobe -r vfat             # вивантажити
dmesg | tail -20                  # повідомлення ядра, зокрема про пристрої
```

Стовпець `Used by` у виводі `lsmod` показує залежності: модуль, від якого залежать інші, вивантажити неможливо, доки не звільнено залежні.

### 5 Дерево пристроїв у /sys

Віртуальна файлова система `/sys` подає внутрішню модель пристроїв ядра: шини, драйвери, класи, параметри живлення. На відміну від `/dev`, який дає доступ до даних пристрою, `/sys` дає доступ до його характеристик.

```bash
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT,MODEL   # блокові пристрої
lsusb                                       # пристрої USB
lspci                                       # пристрої PCI
cat /sys/block/sda/size                     # розмір у секторах по 512 байт
cat /sys/block/sda/queue/rotational         # 1 — HDD, 0 — SSD
cat /sys/block/sda/queue/scheduler          # планувальник введення-виведення
cat /proc/devices                           # зареєстровані major-номери
```

### 6 Буферизація введення-виведення

Ядро не записує дані на диск одразу: воно накопичує їх у кеші сторінок і виконує запис відкладено, об'єднуючи звертання. Це різко підвищує швидкодію, але створює ризик втрати даних у разі раптового вимкнення живлення — саме тому носій перед вилученням відмонтовують.

```bash
free -h                            # стовпець buff/cache
sync                               # примусово записати кеш на диск
echo 3 | sudo tee /proc/sys/vm/drop_caches   # очистити кеш (лише для експерименту)
dd if=/dev/zero of=test.img bs=1M count=200 # запис із буферизацією
dd if=/dev/zero of=test.img bs=1M count=200 oflag=direct  # запис повз кеш
```

Різниця у швидкості між звичайним записом і записом із `oflag=direct` — це і є наочний вимір впливу буферизації.

### Крок 2. Типи пристроїв і номери

```bash
student@lab-vm:~$ ls -l /dev/sda /dev/sda1 /dev/null /dev/urandom
brw-rw---- 1 root disk 8, 0 вер 18 09:12 /dev/sda
brw-rw---- 1 root disk 8, 1 вер 18 09:12 /dev/sda1
crw-rw-rw- 1 root root 1, 3 вер 18 09:12 /dev/null
crw-rw-rw- 1 root root 1, 9 вер 18 09:12 /dev/urandom

student@lab-vm:~$ grep -E "^ *8 |^ *1 " /proc/devices
  1 mem
  8 sd

student@lab-vm:~$ stat -c "%n: %F, major=%t minor=%T" /dev/sda1 /dev/null
/dev/sda1: block special file, major=8 minor=1
/dev/null: character special file, major=1 minor=3

student@lab-vm:~$ ls -l /dev/sda1 /dev/null
brw-rw---- 1 root disk    8, 1 Sep 17 08:42 /dev/sda1
crw-rw-rw- 1 root root    1, 3 Sep 17 08:42 /dev/null
```

Обидва диски `/dev/sda` і `/dev/sda1` мають major 8 — їх обслуговує той самий драйвер `sd`; розрізняє їх minor.

Зверніть увагу: `%t` і `%T` виводять номери **шістнадцятково**. Тут це непомітно,
бо числа малі, але для `/dev/sda16` (minor 16) `stat` покаже `10`. Десяткові
значення дає `ls -l`, і саме їх зручніше звіряти з `/proc/devices`.

### Крок 3. Псевдопристрої

```bash
student@lab-vm:~$ echo "цей текст зникне" > /dev/null
student@lab-vm:~$ cat /dev/null | wc -c
0

student@lab-vm:~$ head -c 16 /dev/urandom | xxd
00000000: 8f3a 20d1 47b9 0c6e a154 fb92 3d08 e7c1  .: .G..n.T..=...

student@lab-vm:~$ dd if=/dev/zero of=zeros.bin bs=1K count=4 2>/dev/null
student@lab-vm:~$ xxd zeros.bin | head -2
00000000: 0000 0000 0000 0000 0000 0000 0000 0000  ................

student@lab-vm:~$ echo test > /dev/full

```

Псевдопристрої не мають фізичного носія: їхню поведінку повністю реалізує драйвер у ядрі.

### Крок 4. Події udev під час підключення носія

student@lab-vm:~$ # підключаємо USB-носій

student@lab-vm:~$ udevadm info /dev/sdb1 | grep -E "ID_FS_TYPE|ID_FS_UUID|ID_MODEL"

student@lab-vm:~$ modinfo vfat | head -5

student@lab-vm:~$ dmesg | tail -5

[  412.489] usb-storage 1-1:1.0: USB Mass Storage device detected

Журнал ядра показує повний ланцюжок: виявлення USB-пристрою → визначення класу Mass Storage → створення блокового пристрою `sdb` → виявлення розділу `sdb1`.

### Крок 6. Параметри блокового пристрою й буферизація

```bash
student@lab-vm:~$ cat /sys/block/sda/size
50331648
student@lab-vm:~$ echo $((50331648 * 512 / 1024 / 1024 / 1024)) 
24

student@lab-vm:~$ cat /sys/block/sda/queue/rotational
1
student@lab-vm:~$ cat /sys/block/sda/queue/scheduler
[mq-deadline] none

student@lab-vm:~$ dd if=/dev/zero of=~/test.img bs=1M count=200 2>&1 | tail -1
209715200 bytes (210 MB, 200 MiB) copied, 0,187 s, 1,1 GB/s

student@lab-vm:~$ dd if=/dev/zero of=~/test2.img bs=1M count=200 oflag=direct 2>&1 | tail -1
209715200 bytes (210 MB, 200 MiB) copied, 1,94 s, 108 MB/s

student@lab-vm:~$ sync && rm ~/test.img ~/test2.img
```

Перший запис «зі швидкістю 1,1 ГБ/с» насправді потрапив лише в кеш пам'яті; другий, із `oflag=direct`, показує реальну швидкість носія. Різниця в десять разів — це і є вплив буферизації.

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Скласти перелік пристроїв системи: блокові пристрої (`lsblk`), пристрої USB (`lsusb`), пристрої PCI (`lspci`). Зафіксувати результат у звіті таблицею.

3. Для трьох файлів пристроїв зі свого варіанта визначити тип (блоковий чи символьний), номери major і minor, власника та права. Пояснити, що означає кожне з цих значень.

4. Знайти у файлі `/proc/devices` драйвер, який відповідає major-номеру пристрою свого варіанта.

5. Продемонструвати роботу псевдопристрою зі свого варіанта: виконати з ним операцію читання або запису й пояснити результат.

6. Запустити спостереження за подіями udev, підключити змінний носій і зафіксувати послідовність подій. Вивести атрибути створеного пристрою (`udevadm info`): тип файлової системи, UUID, модель.

7. Знайти сталі імена підключеного носія в каталогах `/dev/disk/by-uuid` і `/dev/disk/by-id`. Пояснити, чому саме їх використовують у `/etc/fstab`.

8. Переглянути перелік завантажених модулів ядра. Для модуля свого варіанта вивести відомості командою `modinfo` і пояснити поля `description` та `depends`.

9. Дослідити параметри блокового пристрою у `/sys/block`: розмір у секторах і в гігабайтах, тип носія (`rotational`), планувальник введення-виведення.

10. Виміряти вплив буферизації: виконати запис файлу розміром 200 МБ звичайним способом і з ключем `oflag=direct`. Порівняти швидкість і пояснити різницю.

11. Знайти в журналі ядра (`dmesg`) повідомлення про підключення носія й описати послідовність подій.

12. Виконати додаткове завдання свого варіанта.

13. Оформити звіт і зробити висновок.

| 16 | `/dev/sda1`, `/dev/full`, `/dev/tty` | `/dev/zero` | `ext4` | Порівняти вивід `df` і `/sys/block/sda/size` |
| 17 | `/dev/sdb`, `/dev/urandom`, `/dev/console` | `/dev/urandom` | `scsi_mod` | Пояснити, чому імена `/dev/sdX` можуть змінюватися |

## Контрольні запитання

Запитання згруповано за рівнями навчальних досягнень. Для позитивної оцінки студент має відповісти на запитання середнього рівня, оцінка «добре» потребує відповідей достатнього рівня, оцінка «відмінно» — високого.

### Середній рівень (репродуктивний)

1. Що таке файл пристрою і в якому каталозі він розташований?
2. Чим блоковий пристрій відрізняється від символьного?
3. Що означають числа major і minor?
4. Назвіть чотири псевдопристрої та їхнє призначення.
5. Що робить служба udev?
6. Якою командою переглядають перелік блокових пристроїв?
7. Що таке модуль ядра і як переглянути перелік завантажених модулів?
8. Для чого призначена команда `dmesg`?

### Достатній рівень (конструктивно-варіативний)

1. Чому файл пристрою не займає місця на диску й що він насправді містить?
2. Як система визначає, який драйвер обслуговує пристрій? Де це видно?
3. Чому каталог `/dev` формується під час завантаження, а не зберігається на диску?
4. Чому в `/etc/fstab` використовують `/dev/disk/by-uuid`, а не `/dev/sdb1`?
5. Чим `/sys` відрізняється від `/dev` за призначенням?
6. Що показує стовпець `Used by` у виводі `lsmod` і чому модуль із залежностями не вивантажується?
7. Поясніть, чому `dd` без `oflag=direct` показує швидкість, вищу за фізичні можливості диска.
8. Навіщо перед вилученням носія виконують `umount` або `sync`?

### Високий рівень (творчий)

1. Поясніть, як абстракція «пристрій — це файл» спрощує написання прикладних програм, і назвіть випадки, коли цієї абстракції недостатньо.
2. Після перезавантаження системи носій отримав інше ім'я, і служба перестала працювати. Опишіть причину й запропонуйте два способи усунення проблеми.
3. Порівняйте модель управління пристроями в Linux і у Windows за трьома критеріями: подання пристрою, спосіб завантаження драйверів, доступ прикладної програми.
4. Сформулюйте, які ризики створює відкладений запис і якими засобами система та адміністратор ці ризики зменшують.

## Мета самостійної роботи

Вивчити алгоритм IDEA як альтернативу DES. Зрозуміти проблему розподілу ключів та ідею асиметричної криптографії.

## Теоретичний матеріал

### Алгоритм IDEA

**IDEA** (International Data Encryption Algorithm) — симетричний блочний шифр, розроблений Xuejia Lai та James Massey у 1991 році.

```
┌────────────────────────────────────────────────────────────────┐
│                    ПАРАМЕТРИ IDEA                              │
├────────────────────────────┬───────────────────────────────────┤
│ Розмір блоку               │ 64 біти                           │
├────────────────────────────┼───────────────────────────────────┤
│ Розмір ключа               │ 128 біт                           │
├────────────────────────────┼───────────────────────────────────┤
│ Кількість раундів          │ 8.5 (8 повних + 1 вихідний)       │
├────────────────────────────┼───────────────────────────────────┤
│ Кількість підключів        │ 52 (по 16 біт кожен)              │
└────────────────────────────┴───────────────────────────────────┘
```

### Математичні операції IDEA

IDEA використовує три операції над 16-бітними блоками:

```
┌───────────────────────────────────────────────────────────────────┐
│                    ОПЕРАЦІЇ IDEA                                   │
├────────────────────┬──────────────────────────────────────────────┤
│ ⊕ (XOR)            │ Побітове виключне АБО                        │
├────────────────────┼──────────────────────────────────────────────┤
│ ⊞ (Addition)       │ Додавання за модулем 2¹⁶ = 65536             │
├────────────────────┼──────────────────────────────────────────────┤
│ ⊙ (Multiplication) │ Множення за модулем 2¹⁶ + 1 = 65537          │
│                    │ (0 інтерпретується як 2¹⁶)                   │
└────────────────────┴──────────────────────────────────────────────┘
```

**Чому 2¹⁶ + 1 = 65537?**
- 65537 — просте число (число Ферма)
- Це забезпечує існування оберненого елемента для будь-якого ненульового числа
- Операції з різних алгебраїчних груп не "спрощуються" одна з одною

### Структура раунду IDEA

```
    X₁ (16)   X₂ (16)   X₃ (16)   X₄ (16)
      │         │         │         │
      ⊙ K₁     ⊞ K₂      ⊞ K₃     ⊙ K₄
      │         │         │         │
      ├─────────⊕─────────┤         │
      │         │         │         │
      │    ┌────┴────┐    │         │
      │    │   MA    │◄───┼─────────┤
      │    │ структ. │    │         │
      │    └────┬────┘    │         │
      │         │         │         │
      ⊕─────────┼─────────⊕         │
      │         │         │         │
      │         ⊕─────────┼─────────⊕
      │         │         │         │
      ▼         ▼         ▼         ▼
    Y₁         Y₂        Y₃        Y₄
```

### MA-структура (Multiplication-Addition)

```
        A                 B
        │                 │
        ├────────⊕────────┤
        │        │        │
        │        ⊙ K₅     │
        │        │        │
        │   ┌────⊞────┐   │
        │   │    │    │   │
        │   │    ⊙ K₆ │   │
        │   │    │    │   │
        │   └────┼────┘   │
        │        │        │
        ⊕────────┤        │
        │        │        │
        │        ⊕────────┤
        │        │        │
        ▼        ▼        │
       Out1     Out2      │
```

### Генерація підключів

1. 128-бітний ключ ділиться на 8 частин по 16 біт → K₁...K₈
2. Ключ циклічно зсувається на 25 біт вліво
3. Знову ділиться на 8 частин → K₉...K₁₆
4. Повторюємо до отримання 52 підключів

### Переваги IDEA над DES

| Характеристика | DES | IDEA |
|----------------|-----|------|
| Довжина ключа | 56 біт | 128 біт |
| Стійкість до brute force | ~2⁵⁶ | ~2¹²⁸ |
| Відомі практичні атаки | Так | Ні |
| Використання в PGP | Ні | Так (до AES) |

## Проблема розподілу ключів

### Суть проблеми

У симетричній криптографії обидві сторони мають знати один і той самий секретний ключ.

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ПРОБЛЕМА РОЗПОДІЛУ КЛЮЧІВ                        │
│                                                                     │
│   Аліса                                                       Боб  │
│     │                                                           │   │
│     │   Хочу надіслати секретне повідомлення!                  │   │
│     │                                                           │   │
│     │   Але спочатку треба передати ключ...                    │   │
│     │                                                           │   │
│     │   ┌─────────────────────────────────────────────────┐    │   │
│     │   │  Якщо передаю ключ відкритим каналом —          │    │   │
│     │   │  Єва його перехопить!                           │    │   │
│     │   │                                                 │    │   │
│     │   │  Якщо є захищений канал для ключа —            │    │   │
│     │   │  навіщо тоді шифрування?                       │    │   │
│     │   └─────────────────────────────────────────────────┘    │   │
│     │                                                           │   │
└─────────────────────────────────────────────────────────────────────┘
```

### Масштабування проблеми

Для n користувачів потрібно n(n-1)/2 унікальних ключів:

| Користувачі | Ключі |
|-------------|-------|
| 10 | 45 |
| 100 | 4,950 |
| 1,000 | 499,500 |
| 1,000,000 | ~500 млрд |

## Ідея асиметричної криптографії

### Аналогія з поштовою скринькою

```
┌─────────────────────────────────────────────────────────────────────┐
│                    АНАЛОГІЯ: ПОШТОВА СКРИНЬКА                       │
│                                                                     │
│   ┌──────────────┐                                                  │
│   │  ┌────────┐  │                                                  │
│   │  │ Щілина │  │ ← Будь-хто може кинути листа                     │
│   │  │  для   │  │                                                  │
│   │  │ листів │  │                                                  │
│   │  └────────┘  │                                                  │
│   │              │                                                  │
│   │   🔒 Замок   │ ← Тільки власник може відкрити                   │
│   │              │                                                  │
│   └──────────────┘                                                  │
│                                                                     │
│   Публічний ключ = щілина (відома всім)                            │
│   Приватний ключ = ключ від замка (тільки у власника)              │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### Принцип асиметричного шифрування

```
┌─────────────────────────────────────────────────────────────────────┐
│                    АСИМЕТРИЧНА КРИПТОГРАФІЯ                         │
│                                                                     │
│   1. Боб генерує пару ключів:                                       │
│      • Публічний ключ (Pub) — публікує                             │
│      • Приватний ключ (Priv) — зберігає в секреті                  │
│                                                                     │
│   2. Аліса шифрує повідомлення публічним ключем Боба:              │
│      C = E(M, Pub_Bob)                                              │
│                                                                     │
│   3. Тільки Боб може розшифрувати:                                 │
│      M = D(C, Priv_Bob)                                             │
│                                                                     │
│   ┌──────────┐                              ┌──────────┐            │
│   │  Аліса   │        Шифротекст C          │   Боб    │            │
│   │          │ ─────────────────────────────►│          │            │
│   │  M ─►[E] │◄─── Pub_Bob (відкритий)      │ [D]─► M  │            │
│   │          │                               │          │            │
│   └──────────┘                              └──────────┘            │
│                                                    ▲                │
│                                                    │                │
│                                              Priv_Bob               │
│                                              (секретний)            │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### Односторонні функції з секретом

Асиметрична криптографія базується на **односторонніх функціях** (one-way functions):

```
Легко обчислити:     f(x) → y
Важко обчислити:     f⁻¹(y) → x

Але з "секретом":    f⁻¹(y, secret) → x  — легко!
```

**Приклади математичних проблем:**

| Проблема | Легко | Важко |
|----------|-------|-------|
| Факторизація | n = p × q | Знайти p, q за n |
| Дискретний логарифм | y = gˣ mod p | Знайти x за y, g, p |
| Еліптичні криві | Q = k × P | Знайти k за Q, P |

### Порівняння симетричної та асиметричної криптографії

```
┌────────────────────────────────────────────────────────────────────┐
│                        ПОРІВНЯННЯ                                   │
├────────────────────┬─────────────────────┬─────────────────────────┤
│                    │    СИМЕТРИЧНА       │     АСИМЕТРИЧНА         │
├────────────────────┼─────────────────────┼─────────────────────────┤
│ Кількість ключів   │ 1 (спільний)        │ 2 (пара)                │
├────────────────────┼─────────────────────┼─────────────────────────┤
│ Швидкість          │ Дуже швидка         │ Повільна (100-1000×)    │
├────────────────────┼─────────────────────┼─────────────────────────┤
│ Довжина ключа      │ 128-256 біт         │ 2048-4096 біт           │
│ (еквівалентна)     │                     │                         │
├────────────────────┼─────────────────────┼─────────────────────────┤
│ Розподіл ключів    │ Проблема!           │ Вирішено                │
├────────────────────┼─────────────────────┼─────────────────────────┤
│ Цифровий підпис    │ Складно             │ Природно                │
├────────────────────┼─────────────────────┼─────────────────────────┤
│ Приклади           │ AES, DES, ChaCha20  │ RSA, ECC, ElGamal       │
└────────────────────┴─────────────────────┴─────────────────────────┘
```

### Гібридні криптосистеми

На практиці використовують **комбінацію** обох підходів:

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ГІБРИДНА СИСТЕМА (TLS/HTTPS)                     │
│                                                                     │
│   1. Аліса генерує випадковий сесійний ключ K (256 біт)            │
│                                                                     │
│   2. Аліса шифрує K публічним ключем Боба (RSA):                   │
│      K_encrypted = RSA_Encrypt(K, Pub_Bob)                         │
│                                                                     │
│   3. Аліса надсилає K_encrypted Бобу                               │
│                                                                     │
│   4. Боб розшифровує K:                                            │
│      K = RSA_Decrypt(K_encrypted, Priv_Bob)                        │
│                                                                     │
│   5. Обидва використовують K для симетричного шифрування (AES):    │
│      • Швидко шифрують великі обсяги даних                         │
│      • Сесійний ключ змінюється для кожної сесії                   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### Протокол Діффі-Геллмана (1976)

Перший протокол обміну ключами через відкритий канал:

```
Публічні параметри: p (просте), g (генератор)

   Аліса                                          Боб
     │                                              │
     │  Обирає секретне a                          │  Обирає секретне b
     │  A = gᵃ mod p                               │  B = gᵇ mod p
     │                                              │
     │                    A                         │
     │ ─────────────────────────────────────────────►
     │                                              │
     │                    B                         │
     │ ◄─────────────────────────────────────────────
     │                                              │
     │  K = Bᵃ mod p                               │  K = Aᵇ mod p
     │    = (gᵇ)ᵃ mod p                            │    = (gᵃ)ᵇ mod p
     │    = gᵃᵇ mod p                              │    = gᵃᵇ mod p
     │                                              │
     └──────────────── K = K ──────────────────────┘
```

Єва бачить A та B, але не може обчислити K без знання a або b (проблема дискретного логарифма).

## Теоретичні відомості

### 1 Концепція електронного цифрового підпису

Електронний цифровий підпис (ЕЦП) — це математичний механізм, що забезпечує:

- **Автентичність**: підтвердження особи автора документа
- **Цілісність**: виявлення будь-яких змін у документі
- **Неспростовність**: автор не може відмовитися від свого підпису

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ЕЛЕКТРОННИЙ ЦИФРОВИЙ ПІДПИС                        │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│  ФОРМУВАННЯ ПІДПИСУ (автор):                                          │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │ Документ M ──► [HASH] ──► H(M) ──► [SIGN з d] ──► Підпис S     │  │
│  │                                    (закритий ключ)              │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                       │
│  ПЕРЕВІРКА ПІДПИСУ (верифікатор):                                     │
│  ┌─────────────────────────────────────────────────────────────────┐  │
│  │ Документ M ──► [HASH] ──► H(M) ─┐                               │  │
│  │                                  ├──► [COMPARE] ──► Valid/Invalid│ │
│  │ Підпис S ──► [VERIFY з e] ──► H' ┘                              │  │
│  │              (відкритий ключ)                                   │  │
│  └─────────────────────────────────────────────────────────────────┘  │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```
### 2 Схема підпису RSA

Схема RSA використовує ті самі ключі, що й для шифрування, але в іншому порядку:

**Ключі:**

- Відкритий ключ: (e, n) — для перевірки підпису
- Закритий ключ: (d, n) — для формування підпису

**Формування підпису:**

```
S = H(M)^d mod n
```
де:

- M — повідомлення
- H(M) — хеш повідомлення
- d — закрита експонента
- n — модуль RSA
- S — цифровий підпис

**Перевірка підпису:**

```
H'(M) = S^e mod n
Підпис дійсний, якщо H'(M) == H(M)
```
### 3 Роль хеш-функції

Безпосереднє підписування повідомлення M має проблеми:

1. **Повільно**: RSA працює з числами, меншими за n; великі документи потребують багато операцій
2. **Небезпечно**: атака множення — можна створити підпис для добутку двох підписаних повідомлень

Хеш-функція вирішує обидві проблеми:

- Фіксований розмір виходу (256 біт для SHA-256)
- Лавинний ефект унеможливлює підробку

```
Без хешу:    Sign(M1) * Sign(M2) = Sign(M1 * M2)  ← АТАКА!
З хешем:     Sign(H(M1)) * Sign(H(M2)) ≠ Sign(H(M1 * M2))  ← OK
```
### 4 Стандарт PKCS#1

PKCS#1 (Public-Key Cryptography Standards) визначає формат підпису:

```
┌───────────────────────────────────────────────────────────────────────┐
│                    ФОРМАТ PKCS#1 v1.5                                 │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│  EM = 0x00 || 0x01 || PS || 0x00 || T                                 │
│                                                                       │
│  0x00 0x01  — заголовок (вказує на підпис)                            │
│  PS         — padding з байтів 0xFF (мінімум 8 байт)                  │
│  0x00       — розділювач                                              │
│  T          — DigestInfo (OID алгоритму хешу + хеш)                   │
│                                                                       │
│  Приклад DigestInfo для SHA-256:                                      │
│  30 31 30 0D 06 09 60 86 48 01 65 03 04 02 01    -- OID SHA-256       │
│  05 00                                           -- NULL              │
│  04 20 [32 байти хешу]                           -- OCTET STRING      │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```
Для навчальних цілей використовуємо спрощену схему без PKCS#1.

### 5 Властивості цифрового підпису

Таблиця 1 — Властивості цифрового підпису

| Властивість | Опис | Як досягається |
|----|----|----|
| **Автентичність** | Підпис може створити тільки власник закритого ключа | Операція S = H(M)^d mod n |
| **Цілісність** | Будь-яка зміна документа змінює хеш | Лавинний ефект хеш-функції |
| **Неспростовність** | Автор не може відмовитися від підпису | Закритий ключ відомий тільки автору |

## Приклад виконання

### Крок 1. Структура програми (Python)

```python
import hashlib
from typing import Tuple

class RSAKeyPair:
    """Ключова пара RSA для цифрового підпису."""

    def __init__(self, p: int, q: int, e: int = 65537):
        self.n = p * q
        phi = (p - 1) * (q - 1)

        # Перевірка: gcd(e, phi) = 1
        if self._gcd(e, phi) != 1:
            raise ValueError("e та phi(n) не взаємно прості")

        self.e = e  # Відкрита експонента
        self.d = self._mod_inverse(e, phi)  # Закрита експонента

    @staticmethod
    def _gcd(a: int, b: int) -> int:
        while b:
            a, b = b, a % b
        return a

    @staticmethod
    def _mod_inverse(a: int, m: int) -> int:
        """Обчислення оберненого елемента за модулем (розширений Евклід)."""
        if RSAKeyPair._gcd(a, m) != 1:
            raise ValueError("Обернений не існує")

        # Розширений алгоритм Евкліда
        old_r, r = a, m
        old_s, s = 1, 0

        while r != 0:
            q = old_r // r
            old_r, r = r, old_r - q * r
            old_s, s = s, old_s - q * s

        return old_s % m

    def get_public_key(self) -> Tuple[int, int]:
        """Повертає відкритий ключ (e, n)."""
        return (self.e, self.n)

    def get_private_key(self) -> Tuple[int, int]:
        """Повертає закритий ключ (d, n)."""
        return (self.d, self.n)
```
### Крок 2. Хешування повідомлення

```python
def hash_message(message: str) -> int:
    """
    Хешує повідомлення за допомогою SHA-256
    і повертає хеш як ціле число.
    """
    # Обчислюємо SHA-256
    hash_bytes = hashlib.sha256(message.encode('utf-8')).digest()

    # Перетворюємо байти на число
    hash_int = int.from_bytes(hash_bytes, byteorder='big')

    return hash_int

def truncate_hash(hash_int: int, n: int) -> int:
    """
    Обрізає хеш, щоб він був меншим за n.
    У реальних системах використовується PKCS#1.
    """
    # Визначаємо кількість біт у n
    n_bits = n.bit_length()

    # Обрізаємо хеш до потрібної довжини
    mask = (1 << (n_bits - 1)) - 1
    return hash_int & mask
```
### Крок 3. Формування та перевірка підпису

```python
def sign(message: str, private_key: Tuple[int, int]) -> int:
    """
    Формує цифровий підпис повідомлення.

    Args:
        message: Повідомлення для підпису
        private_key: Закритий ключ (d, n)

    Returns:
        Цифровий підпис S
    """
    d, n = private_key

    # 1. Хешуємо повідомлення
    hash_int = hash_message(message)

    # 2. Обрізаємо хеш (для навчальних цілей)
    h = truncate_hash(hash_int, n)

    # 3. Формуємо підпис: S = H(M)^d mod n
    signature = pow(h, d, n)

    return signature

def verify(message: str, signature: int, public_key: Tuple[int, int]) -> bool:
    """
    Перевіряє цифровий підпис.

    Args:
        message: Підписане повідомлення
        signature: Цифровий підпис
        public_key: Відкритий ключ (e, n)

    Returns:
        True якщо підпис дійсний, False інакше
    """
    e, n = public_key

    # 1. Хешуємо повідомлення
    hash_int = hash_message(message)
    h = truncate_hash(hash_int, n)

    # 2. "Розшифровуємо" підпис: H' = S^e mod n
    recovered_hash = pow(signature, e, n)

    # 3. Порівнюємо хеші
    return h == recovered_hash
```
### Крок 4. Демонстрація роботи

```python
def demo():
    print("=" * 60)
    print("ДЕМОНСТРАЦІЯ ЦИФРОВОГО ПІДПИСУ RSA")
    print("=" * 60)

    # Генерація ключів (малі прості для демонстрації)
    # У реальних системах використовують числа 2048+ біт
    p = 61
    q = 53
    keys = RSAKeyPair(p, q, e=17)

    public_key = keys.get_public_key()
    private_key = keys.get_private_key()

    print(f"\nПараметри RSA:")
    print(f"  p = {p}, q = {q}")
    print(f"  n = {keys.n}")
    print(f"  e = {public_key[0]} (відкрита експонента)")
    print(f"  d = {private_key[0]} (закрита експонента)")

    # Документ для підпису
    document = "Договір купівлі-продажу №123"

    print(f"\n{'─' * 60}")
    print("ФОРМУВАННЯ ПІДПИСУ")
    print(f"{'─' * 60}")
    print(f"Документ: \"{document}\"")

    # Підписуємо документ
    signature = sign(document, private_key)
    print(f"Підпис S = {signature}")

    # Верифікація підпису
    print(f"\n{'─' * 60}")
    print("ПЕРЕВІРКА ПІДПИСУ")
    print(f"{'─' * 60}")

    is_valid = verify(document, signature, public_key)
    print(f"Результат: {'✓ ПІДПИС ДІЙСНИЙ' if is_valid else '✗ ПІДПИС НЕДІЙСНИЙ'}")

    # Спроба модифікації документа
    print(f"\n{'─' * 60}")
    print("ВИЯВЛЕННЯ МОДИФІКАЦІЇ")
    print(f"{'─' * 60}")

    modified_document = "Договір купівлі-продажу №124"  # Змінено номер
    print(f"Модифікований документ: \"{modified_document}\"")

    is_valid_modified = verify(modified_document, signature, public_key)
    print(f"Результат: {'✓ ПІДПИС ДІЙСНИЙ' if is_valid_modified else '✗ ПІДПИС НЕДІЙСНИЙ'}")

    # Спроба підробки підпису
    print(f"\n{'─' * 60}")
    print("СПРОБА ПІДРОБКИ ПІДПИСУ")
    print(f"{'─' * 60}")

    fake_signature = signature + 1
    print(f"Підроблений підпис: {fake_signature}")

    is_valid_fake = verify(document, fake_signature, public_key)
    print(f"Результат: {'✓ ПІДПИС ДІЙСНИЙ' if is_valid_fake else '✗ ПІДПИС НЕДІЙСНИЙ'}")

if __name__ == "__main__":
    demo()
```

## Порядок виконання роботи

1. Отримати в викладача номер індивідуального варіанта.

2. Реалізувати генерацію ключової пари RSA. Використати прості числа з варіанта.

3. Реалізувати функцію хешування повідомлення. Можна використати бібліотечну SHA-256 або власну реалізацію з попередньої роботи.

4. Реалізувати функцію формування підпису: S = H(M)^d mod n.

5. Реалізувати функцію перевірки підпису: порівняння H(M) та S^e mod n.

6. Продемонструвати коректну верифікацію підписаного документа.

7. Продемонструвати виявлення модифікації — змінити документ і показати, що підпис став недійсним.

8. Продемонструвати захист від підробки — змінити підпис і показати, що верифікація не проходить.

9. Виконати індивідуальне завдання згідно з варіантом.

10. Оформити звіт та зробити висновок.

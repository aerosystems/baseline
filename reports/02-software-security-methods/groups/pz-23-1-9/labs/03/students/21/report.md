## Хід роботи

1 Отримано індивідуальне завдання — варіант 1: ключове слово CIPHER, текст
"THE QUICK BROWN FOX". Реалізацію виконано мовою Go; вихідні файли лежать
у каталозі `src/`, запуск — `go run .`, тести — `go test ./...`.

2 Підготовка тексту. Перед записом у таблицю з тексту прибирають усе, крім
латинських літер: збережені пробіли видали б у шифротексті межі слів.
Після нормалізації лишається 16 літер — THEQUICKBROWNFOX.

Далі текст доповнюють літерою X до повного прямокутника. Це не косметика:
доповнення вирівнює довжину всіх стовпців, і саме завдяки йому розшифрування
зводиться до оберненої перестановки. Без нього той, хто розшифровує, мусив би
ще й вгадувати, які стовпці на одну літеру коротші.

```go
// pad доповнює текст до size літер.
func pad(text []rune, size int) []rune {
	for len(text) < size {
		text = append(text, padding)
	}
	return text
}
```

3 Проста шифруюча таблиця. Текст записують по рядках, а читають по стовпцях
зліва направо. Ширину обрано 4: на 16 літер це рівно 4x4, тож перший приклад
показує шифр у чистому вигляді, без жодної літери доповнення.

```
 ┌──┬──┬──┬──┐
 │T │H │E │Q │
 │U │I │C │K │
 │B │R │O │W │
 │N │F │O │X │
 └──┴──┴──┴──┘

Шифротекст:   TUBNHIRFECOOQKWX
Розшифровано: THEQUICKBROWNFOX
```

Ключа тут немає взагалі — таємницею є сама ширина таблиці. Це й робить шифр
беззахисним: ширину можна просто перебрати, бо вона мусить бути дільником
довжини шифротексту.

4 Порядок стовпців за ключовим словом. Стовпці нумерують за алфавітним
порядком літер ключа, і в цьому порядку їх потім читають. Сортування стійке,
тому однакові літери ключа читаються зліва направо: у CIPHER повторів немає,
але в списку завдань є ключі DEFEND і GUARD, де без стійкого сортування
порядок стовпців залежав би від реалізації.

```go
// keyOrder повертає індекси стовпців у порядку читання: першим іде стовпець
// під найранішою за алфавітом літерою ключа.
func keyOrder(key string) []int {
	letters := normalize(key)

	order := make([]int, len(letters))
	for i := range order {
		order[i] = i
	}
	sort.SliceStable(order, func(a, b int) bool {
		return letters[order[a]] < letters[order[b]]
	})
	return order
}
```

Для ключа CIPHER виходить C=1, E=2, H=3, I=4, P=5, R=6, тобто стовпці читають
у порядку C, E, H, I, P, R.

5 Шифрування та дешифрування з ключовим словом. Ширина таблиці тепер дорівнює
довжині ключа — шість стовпців на 16 літер дають три рядки, останні дві комірки
заповнює X.

```
  C  I  P  H  E  R
  1  4  5  3  2  6
 ┌──┬──┬──┬──┬──┬──┐
 │T │H │E │Q │U │I │
 │C │K │B │R │O │W │
 │N │F │O │X │X │X │
 └──┴──┴──┴──┴──┴──┘

Шифротекст:   TCNUOXQRXHKFEBOIWX
Розшифровано: THEQUICKBROWNFOXXX
```

Дешифрування — та сама таблиця, заповнена у зворотному напрямку: шифротекст
розкладають по стовпцях у порядку ключа й читають по рядках.

```go
// keywordEncrypt: та сама таблиця, але стовпці читають не зліва направо,
// а в алфавітному порядку літер ключа.
func keywordEncrypt(text, key string) string {
	order := keyOrder(key)
	table := layout(text, len(order))

	var out strings.Builder
	for _, col := range order {
		for row := range table {
			out.WriteRune(table[row][col])
		}
	}
	return out.String()
}
```

6 Подвійна перестановка. Тут переставляють і рядки, і стовпці, а результат
читають по рядках.

Завдання дає один ключ, а подвійна перестановка потребує двох. Другий ключ узято
з тексту того самого варіанта — THE. Вибір не довільний: літери T, H, E стоять
у зворотному алфавітному порядку, тому рядки справді міняються місцями. Слово
FOX із того ж тексту для цього не годиться — воно вже впорядковане за алфавітом,
і перестановка рядків вийшла б тотожною, а «подвійний» шифр звівся б до
звичайного стовпцевого.

```go
// doubleEncrypt переставляє спершу рядки за ключем рядків, потім стовпці
// за ключем стовпців, і читає результат по рядках.
func doubleEncrypt(text, rowKey, colKey string) string {
	rowOrder, colOrder := keyOrder(rowKey), keyOrder(colKey)
	letters := pad(normalize(text), len(rowOrder)*len(colOrder))

	return rows(permute(layout(string(letters), len(colOrder)), rowOrder, colOrder))
}
```

Обидва кроки видно окремо. Спершу рядки стають у порядку ключа THE (E, H, T —
тобто третій, другий, перший):

```
 ┌──┬──┬──┬──┬──┬──┐        ┌──┬──┬──┬──┬──┬──┐
 │T │H │E │Q │U │I │        │N │F │O │X │X │X │
 │C │K │B │R │O │W │   ->   │C │K │B │R │O │W │
 │N │F │O │X │X │X │        │T │H │E │Q │U │I │
 └──┴──┴──┴──┴──┴──┘        └──┴──┴──┴──┴──┴──┘
```

Потім стовпці стають у порядку ключа CIPHER:

```
 ┌──┬──┬──┬──┬──┬──┐
 │N │X │X │F │O │X │
 │C │O │R │K │B │W │
 │T │U │Q │H │E │I │
 └──┴──┴──┴──┴──┴──┘

Шифротекст:   NXXFOXCORKBWTUQHEI
Розшифровано: THEQUICKBROWNFOXXX
```

## Відповіді на контрольні питання

### Середній рівень

1 Чим шифри перестановки відрізняються від шифрів заміни?

Шифр заміни міняє самі літери, лишаючи їх на місці; шифр перестановки міняє
місця, лишаючи літери. Тому заміна змінює частотний портрет тексту, а
перестановка зберігає його незмінним.

2 Як виконується шифрування простою шифруючою таблицею?

Текст записують у таблицю заданої ширини по рядках, доповнюють до повного
прямокутника й читають по стовпцях зліва направо.

3 Як визначається порядок стовпців за ключовим словом?

Літери ключа нумерують за алфавітом: найраніша літера дає стовпець номер один.
Стовпці потім читають у порядку цих номерів.

4 Як доповнюється текст, якщо його довжина не кратна довжині ключа?

У кінець дописують службову літеру — у цій роботі X — доти, доки таблиця не
стане повним прямокутником.

5 Що таке подвійна перестановка?

Послідовне застосування двох перестановок до однієї таблиці: спершу за одним
ключем міняють місцями рядки, потім за другим — стовпці.

6 Скільки можливих перестановок існує для таблиці 5x5?

Для перестановки лише стовпців — 5! = 120 варіантів. Для подвійної перестановки,
де переставляють і рядки, і стовпці, — 5! x 5! = 14 400.

7 Чи змінює шифр перестановки склад літер тексту?

Ні. Шифротекст містить рівно ті самі літери в тій самій кількості, змінено лише
їхній порядок; додаються хіба що літери доповнення.

8 Які дані потрібні для розшифрування тексту, зашифрованого шифруючою таблицею?

Ширина таблиці, а для варіанта з ключем — саме ключове слово, з якого ширина
й порядок стовпців випливають однозначно.

### Достатній рівень

1 Чому шифри перестановки не піддаються класичному частотному аналізу окремих
літер?

Бо частоти літер у шифротексті й у відкритому тексті однакові. Частотний аналіз
покаже, що текст англійською, але жодної літери не розкриє: він відповідає на
питання «яка це літера», а перестановка ховає не літеру, а її місце.

2 Що дає подвійна перестановка для стійкості порівняно з одинарною?

Після одинарної стовпцевої перестановки літери кожного стовпця лишаються
сусідами й у тому ж порядку — криптоаналітику досить правильно скласти цілі
стовпці. Друга перестановка руйнує й ці блоки, тож відновлювати доводиться не
порядок стовпців, а розташування окремих літер.

3 Як символи-заповнювачі можуть видати довжину ключа криптоаналітику?

Заповнювачі стоять у кінці останнього рядка таблиці, тому після читання по
стовпцях вони опиняються в кінцях стовпців — тобто на регулярній відстані один
від одного. У шифротексті цієї роботи TCNUOXQRXHKFEBOIWX літери X стоять на
позиціях 6, 9 і 18; крок 3 одразу дає число рядків, а 18 : 3 — шість стовпців,
тобто довжину ключа.

4 Запишіть алгоритм розшифрування тексту, зашифрованого таблицею з ключовим
словом.

Обчислити порядок стовпців за ключем; поділити довжину шифротексту на довжину
ключа й дістати число рядків; розрізати шифротекст на відрізки завдовжки в число
рядків; розкласти ці відрізки по стовпцях у порядку ключа; прочитати таблицю по
рядках.

5 Як однакові літери в ключовому слові впливають на порядок стовпців і як цю
неоднозначність усувають?

Однакові літери самі по собі не кажуть, який зі стовпців читати першим. Усувають
це домовленістю: рівні літери впорядковують за позицією в ключі, зліва направо.
У програмі це забезпечує стійке сортування, а окремий тест перевіряє ключ DEFEND.

6 Чому аналіз частот біграм ефективніший проти шифрів перестановки, ніж аналіз
частот літер?

Частоти літер перестановка не змінює, тому вони не несуть інформації про ключ.
А от сусідство літер вона руйнує, і його можна відновлювати: перебираючи
розташування стовпців, аналітик обирає той варіант, де пари сусідніх літер
найбільше схожі на звичайні для мови — TH, HE, IN.

7 Як визначити ймовірну довжину ключа, маючи лише шифротекст?

Довжина шифротексту кратна довжині ключа, тому кандидатами є дільники цієї
довжини. Кожен кандидат перевіряють: складають таблицю відповідної ширини
й дивляться, чи вдається знайти порядок стовпців із правдоподібною статистикою
біграм. Додаткову підказку дають заповнювачі з питання 3.

8 Чим магічний квадрат як спосіб перестановки відрізняється від шифруючої
таблиці з ключем?

У магічному квадраті порядок задають числа самого квадрата, а не окреме слово:
ключем є квадрат. Це незручніше на практиці й слабше як ключ — магічних квадратів
кожного розміру скінченна й невелика кількість, тоді як ключових слів стільки,
скільки слів у мові.

### Високий рівень

1 Запропонуйте алгоритм автоматичного зламу шифру простої перестановки за
наявності достатнього обсягу шифротексту.

Перебрати дільники довжини шифротексту як можливу кількість стовпців. Для
кожного скласти таблицю й шукати порядок стовпців, що дає найбільшу оцінку
правдоподібності тексту за логарифмами частот біграм. Повний перебір придатний
до восьми стовпців; далі — жадібний пошук: почати з довільного порядку й міняти
місцями пари стовпців, поки оцінка зростає, з кількох випадкових стартів, щоб не
застрягти в локальному максимумі. Відповіддю є варіант із найкращою оцінкою.

2 Поясніть, чому комбінація заміни й перестановки стійкіша за кожен із цих
методів окремо, і наведіть приклад такої комбінації в сучасних шифрах.

Заміна приховує, яка це літера, але лишає структуру тексту; перестановка
приховує структуру, але лишає літери. Кожен метод окремо має слабке місце, і
воно різне, тому їх чергування закриває обидва: після заміни частотний аналіз
не працює, після перестановки не працює аналіз сусідства. Шеннон назвав ці дві
властивості плутаниною і розсіюванням. У DES це S-блоки разом із P-блоком
у кожному раунді, в AES — SubBytes разом із ShiftRows і MixColumns; сучасна
стійкість береться з багаторазового повторення цієї пари, а не з одного проходу.

3 Оцініть реальну стійкість подвійної перестановки з ключами довжиною 8 і 10
символів: скільки варіантів має перебрати криптоаналітик?

Формально 8! x 10! = 40 320 x 3 628 800, тобто близько 1,46 x 10^11 варіантів —
приблизно 2^37. Звичайний комп'ютер перебирає це за години, тому за сучасними
мірками, де порогом вважають 2^128, шифр нестійкий. Насправді ж стійкість іще
нижча: ключами є слова, тож перебирати треба не всі перестановки, а пари слів зі
словника — а це вже мільйони варіантів, не мільярди.

4 Сформулюйте, які властивості тексту зберігає шифр перестановки, і поясніть,
як саме ці властивості використовує криптоаналітик.

Перестановка зберігає склад літер, їхні частоти й довжину тексту. З частот
аналітик визначає мову й одразу відкидає гіпотезу заміни — надто вже розподіл
схожий на природний. З довжини дістає кандидатів на довжину ключа: вона має бути
дільником. А далі відновлює саме те єдине, що шифр приховав, — порядок, —
спираючись на статистику біграм, якої в шифротексті вже немає, але яка має
з'явитися в правильному варіанті розшифрування.

## Висновок

Виконано програмну реалізацію трьох шифрів перестановки — простої шифруючої
таблиці, таблиці з ключовим словом і подвійної перестановки — з дешифруванням
для кожного. Правильність підтверджено тестами, які відтворюють контрольні
приклади з методичних вказівок.

Головне, що показала робота: шифр перестановки приховує лише порядок літер
і не чіпає їхнього складу. Через це він не піддається частотному аналізу окремих
літер, але й стійкості не дає — уся інформація про текст лишається в шифротексті,
змінено тільки її розташування. Довжина шифротексту видає кандидатів на довжину
ключа, заповнювачі підказують розмір таблиці, а статистика біграм дозволяє
відновити порядок стовпців перебором. Навіть подвійна перестановка з ключами
у вісім і десять символів дає близько 2^37 варіантів — величину, яку сучасна
